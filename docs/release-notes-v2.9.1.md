# 视频工具箱 v2.9.1

> 补丁版，只修一个用户可感知的问题：**启动后程序自己去建还没打开的页面**，
> 导致 `.bat` 打开后主线程被持续独占 30–50 秒才恢复可交互。
> 本版把这类构建全部改成「打开那一页才做」，并把工作台构建拆成三段回事件循环。
> **本版只固化源码，未重新打包，线上安装包仍为 v2.9.0。**

## 修复

### 1. 启动期不再自动构建用户未打开的页面

| 原行为 | 现行为 |
|---|---|
| 启动 800ms 自动 `prewarm_kick`，预热完回主线程整页构建字幕引擎工作台（冷态 20–44s） | 删除自动注册。只在用户进入「字幕处理」页，或拖入文件触发分派、预构建尚未完成时才建 |
| 启动 20s 自动构造「自动化」页（冷态实测 **52.6s**） | 改为惰性外壳：导航项立即出现，**点开才建真身** |
| 启动 4000ms 自动构造「AI 托管」页（0.34–1.31s） | 同惰性外壳，按需构建 |
| 启动 1500ms 自动 `library_page.auto_load()`（建视频库页 + 扫盘） | `library_page.defer(...)`：首次打开视频库、真身建好后才扫 |
| 启动 3500ms 起校准/声纹后台同步 | 顺延到 25s（9s 起时实测 T+13/T+14 各有 600–720ms GIL 争用） |
| 启动期后台 import 预热建界面 | 延后到 30s，且只 import 不建界面；已因进页起过线程时不重复 |

### 2. 按需构建也不再一口气做完

`_build_now` 拆成三段 `QTimer.singleShot(0, ...)` 串联：
`_build_stage_engine`（构造 HomeInterface）→ `_build_stage_mount`（并入宿主布局）→
`_build_stage_adopt`（任务创建移交 / 运行期配置 / 收状态行 / 导航收敛）。
构建前先把「正在准备…」文案 `processEvents()` 推上屏，避免看起来像死程序。
提前拖入文件的 `_pending_dispatch` 改到第 3 段之后续跑，语义不变。

### 3. 调度器可观测性

- 工作台构建逐段计时；
- 单任务超预算时写日志：`sched[xxx] 超预算 …ms（budget=…ms，任务体内不可切分）`
  —— 下次不必再猜「点不动那一下」到底多长。

## 实测（本机，`VT_SCHED_TRACE=1`）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 窗口首帧可见 | 2.4s | **1.88s** |
| 首页任务创建可交互 | 3.7s | **2.93s** |
| 启动后 0–25s 主线程阻塞 | 连续 33s，随后又 52s | **0 次 >150ms** |
| 自动化页 | 启动 20s 自建，冷态 52.6s | 启动期不构建，点开才建 |
| 点进「字幕处理」按需构建 | — | 三段 0.91s / 0.22s / 0.03s，总 1.16s |

## 已知限制

1. 冷缓存下 `HomeInterface` 构造本身仍有秒级（qtawesome 字体与首次 QSS polish），
   已用三段 + 占位文案兜住，尚未拆到子界面级。
2. `prewarm_import`（30s）与 `startup_sync`（25s）仍各会引发一次百毫秒–1.2s 的 GIL 争用，
   发生在启动 25s 之后，不影响首屏。
3. **本版未重出安装包**：`installer\` 与 `installer_online\` 仍是 v2.9.0 产物；
   源码运行（`src\视频工具箱.bat`）已生效。
