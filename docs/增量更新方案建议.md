# 视频工具箱 · 不全量更新的版本迭代方案

> ⚠️ **v1.14.1 安全整改注记**：本文写作时的 COMPONENTS 含 `github_proxy.yaml` 与
> `tools\mihomo\`，二者**含代理节点凭据，严禁进入任何发布物**，现已从在线安装器
> 移除（见程序说明书 4.3 / 6.6）。文中涉及它们的拆包示例均需以此为前提调整。

> 基于 v1.14.1 现状实测数据编写。结论先行：**当前结构在技术上无法做到有效增量，
> 瓶颈不在 Inno/IFW 脚本，而在 PyInstaller 的 onefile 打包模式。**
> 安装包侧的改造必须和打包侧配套，单改任何一侧收益都很有限。

## 一、现状诊断（实测数据）

`installer_repository/` 当前 104.1 MB，全部归属于**一个**组件 `com.videotoolbox.base`：

| 归档 | 压缩后 | 内容 | 变更频率 |
|---|---|---|---|
| `1.14.1content.7z` | **89.1 MB** | `dist\视频工具箱.exe`（89.3 MB，onefile+UPX） | 每次迭代必变 |
| `1.14.1tools.7z` | **14.5 MB** | `tools\mihomo`（未压缩 56 MB） | 几乎不变 |
| `1.14.1src.7z` | 0.3 MB | `src\`（未压缩 2.3 MB） | 每次迭代必变 |
| `1.14.1docs.7z` | 0.1 MB | `docs\`（未压缩 0.4 MB） | 偶尔变 |
| `2026-09-18-1100_meta.7z` | <0.1 MB | 组件元数据 | 每次必变 |

两个结构性问题：

### 问题 1：单组件 = 全有或全无

IFW 的更新粒度是**组件**。`com.videotoolbox.base` 的 `<Version>` 一升，
客户端就要重下该组件的**全部四个归档**（104 MB），哪怕你只改了 `ui_theme.py` 的一行。

`Updates.xml` 里的 `<DownloadableArchives>docs.7z,src.7z,tools.7z,content.7z</DownloadableArchives>`
是 IFW 按 `data/` 一级子目录自动拆的，**只用于断点续传，不构成增量下载单元**——
更新组件时这四个包会全下。

### 问题 2：onefile + UPX 让 exe 无法二进制 diff（关键）

这是最容易踩空的一点。直觉上「改几行代码，用 bsdiff/xdelta 打个补丁」应该可行，
但在当前 `视频工具箱.spec` 下**几乎无效**：

```python
exe = EXE(
    pyz, a.scripts, a.binaries, a.datas, [],   # ← binaries/datas 直接进 EXE = onefile
    name='视频工具箱',
    upx=True,                                   # ← UPX 把熵拉满
    runtime_tmpdir=None,
    ...
)
```

三重致命因素：

1. **UPX 压缩**：`upx=True` 后 exe 内部是高熵压缩数据。改一个字节 → 压缩流雪崩 →
   整个文件字节面目全非。任何 diff 算法都退化到接近全量。
2. **PyInstaller archive 偏移表**：onefile 把整个目录树打成一个 CArchive，
   末尾有 TOC 记录每个条目的**绝对偏移**。PYZ 段体积一变，后面所有 DLL/pyd 的偏移全部位移 →
   即使内容一字节没改，在 diff 眼里也全变了。
3. **自研代码混在 PYZ 里**：`a.pure` 包含你的 `src\*.py` **和** `videocaptioner` 全部子模块
   （`collect_submodules('videocaptioner')`）。改一行自研代码 → 整个 PYZ 重打 → 十几 MB 变动。

**结论：只要还是 onefile + UPX，"增量更新"就只能停留在组件拆分层面，
天花板是省掉那 14.5 MB 的 mihomo（约 14%）。要拿到数量级的收益，必须先改打包模式。**

## 二、方案总览

按投入产出排序，三层可独立实施、逐层叠加：

| 层级 | 改造内容 | 迭代时下载量 | 工作量 | 是否必需 |
|---|---|---|---|---|
| **现状** | — | 104 MB | — | — |
| **L1** | IFW 组件拆分 + `--sha-update` + `--update` | ~89 MB | 半天 | 建议做（零风险） |
| **L2** | onedir 化 + 引导层/依赖层/代码层三分离 | **~0.5 MB** | 1-2 天 | ★核心 |
| **L3** | 文件级 manifest 自更新器 + xdelta 补丁 | ~0.1-0.5 MB，可静默 | 2-3 天 | 可选（要无感升级才做） |

**L2 是分水岭**：它把「每次都变的代码」和「几乎不变的依赖」在物理上分开，
增量才真正成立。L1 单独做只有 14% 收益，L3 单独做在 onefile 上无效。

## 三、L2 核心：三层分离（先讲这个，因为它决定其余设计）

### 3.1 目标形态

```
{app}\
├─ 视频工具箱.exe          ← 引导壳，几百 KB，含 bootstrap + PYZ(仅第三方纯模块)
├─ _internal\              ← 依赖层：python312.dll / PyQt5 / *.pyd / videocaptioner 资源
│                             ★ 稳定，只在升级 Python 或第三方依赖时才变
├─ src\                    ← 代码层：你的全部自研 .py（明文）
│                             ★ 热更层，每次迭代就改这里，~0.5 MB
├─ subtitle_calib_merged.py
├─ tools\mihomo\           ← 运行时层，几乎不变
└─ docs\
```

关键洞察：**exe 只当「装依赖的壳」，业务代码全部走明文 `.py` 放在 `{app}\src\`，
运行时 `sys.path` 优先加载。** 于是「改代码」和「重打 exe」彻底解耦。

项目其实已经具备全部前提：`src\` 本来就随包分发、`subtitle_calib_merged.py` 本来就是
明文外部脚本、已有 `src\视频工具箱.bat` 走源码运行的模式、且因 VideoCaptioner 是
GPL-3.0 本就有开源义务——明文 `.py` 不构成新的泄露面。

### 3.2 spec 改造

新增 `src\bootstrap.py`（**唯一进 exe 的代码，写完基本永不再改**）：

```python
# -*- coding: utf-8 -*-
"""引导层：唯一被冻结进 exe 的代码。
职责仅三件——定位程序目录、把 {app}\src 插到 sys.path 最前、转交真正的入口。
本文件必须保持极简且不随业务演进，它是"exe 不需要重打"的前提。
"""
import os
import sys


def _app_dir() -> str:
    """程序根目录。onedir 下 sys.executable 就是 {app}\视频工具箱.exe，取其父目录。
    冻结态与源码态分别处理，保证开发期直接 python bootstrap.py 也能跑。"""
    if getattr(sys, "frozen", False):
        return os.path.dirname(os.path.abspath(sys.executable))
    return os.path.dirname(os.path.dirname(os.path.abspath(__file__)))


def main() -> None:
    app = _app_dir()
    src = os.path.join(app, "src")

    # 明文代码层优先于 exe 内冻结的任何同名模块 —— 这是热更新能生效的机制本身
    if os.path.isdir(src) and src not in sys.path:
        sys.path.insert(0, src)

    # 兼容旧布局：代码层缺失时退回 exe 内冻结副本，绝不让程序起不来
    import runpy
    runpy.run_module("video_toolbox_qt", run_name="__main__", alter_sys=True)


if __name__ == "__main__":
    main()
```

### 3.4 两个必须验证的点

改造后务必实测，否则会在用户机上暴雷：

1. **`_MEI` 临时目录问题不再存在**：v1.12.1 那个「退出后无限重启」的严重 bug
   根因是 onefile 的 `sys.executable` 指向自身。onedir 下 `sys.executable` 仍是主 exe，
   但**不再有 `_MEI` 解压目录**，所以那类抢占/删除临时目录的故障模式整体消失。
   不过 `system_python()` / `_is_self_exe()` 那套兜底逻辑要重新验证——
   onedir 下 `{app}\tools\python` 可能不存在（IFW 在线版不含内嵌 Python），
   确认退出同步会正确跳过而不是回退到 exe 自身。
2. **`_internal` 路径锚定**：原代码里所有「exe 同级 tools」的路径推导
   （`APP_DIR` 相关）要复查。onedir 下 `sys.executable` 的父目录就是 `{app}`，
   语义与 onefile 一致，`tools\`、`data\`、`src\` 的相对定位应当不变，但要跑一遍
   `_selftest_pack.py` 和 `_selftest_e2e.py` 确认。

## 四、L1：IFW 组件拆分

### 4.1 组件划分

改 `installer_src/build_online_installer.py` 的 `COMPONENTS`：

```python
# 组件 -> 文件来源映射：(源路径, data 内相对位置)
#
# 拆分原则：**按变更频率分层，而不是按目录分类**。
# 同一层内的文件必须"同生共死"（一起变、一起更新），
# 否则会把不变的文件拖进变更层，白白多下。
#
# ⚠️ 各组件的 data 展开后不得有文件重叠：IFW 按文件记录归属，
#    重叠会导致更新一个组件时覆盖/删除另一个组件的文件。
COMPONENTS = {
    # ── 引导层：exe 壳 + _internal 依赖 ─────────────────────────────
    # onedir 后这层很稳定，只在升级 Python / 第三方依赖时才动。
    # 版本号独立于应用版本演进（见 4.3）。
    "com.videotoolbox.core": [
        ("dist/视频工具箱/视频工具箱.exe", "视频工具箱.exe"),
        ("dist/视频工具箱/_internal",      "_internal"),
    ],

    # ── 代码层：自研业务代码，热更主力，每次迭代都变 ──────────────────
    # 这是唯一需要频繁发版的组件，压完约 0.5MB。
    "com.videotoolbox.code": [
        ("src",                          "src"),
        ("subtitle_calib_merged.py",     "subtitle_calib_merged.py"),
    ],

    # ── 运行时层：内嵌代理，56MB→14.5MB，几乎从不变化 ────────────────
    "com.videotoolbox.runtime": [
        ("tools/mihomo", "tools/mihomo"),
    ],

    # ── 工具脚本层：极小，偶尔变 ────────────────────────────────────
    "com.videotoolbox.tools": [
        ("tools/ai_client.py",                  "tools/ai_client.py"),
        ("tools/download_open_source_deps.py",  "tools/download_open_source_deps.py"),
        ("github_proxy.yaml",                   "github_proxy.yaml"),
    ],

    # ── 文档层：含 GPL-3.0 合规声明，必须始终分发 ────────────────────
    "com.videotoolbox.docs": [
        ("docs", "docs"),
    ],
}

# 每个组件的独立版本号：与 APP_VERSION 解耦。
# 规则：内容不变就不动，内容变了才递增。这是"客户端不重下"的唯一可靠开关。
COMPONENT_VERSIONS = {
    "com.videotoolbox.core":    "1.15.0",   # onedir 首次改造，必变
    "com.videotoolbox.code":    "1.15.0",   # 每次迭代递增
    "com.videotoolbox.runtime": "1.0.0",    # mihomo 未升级则长期不动
    "com.videotoolbox.tools":   "1.0.0",
    "com.videotoolbox.docs":    "1.14.1",
}
```

`runtime` / `tools` / `docs` 三个稳定组件：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Package>
    <DisplayName>视频工具箱 网络代理运行时</DisplayName>
    <Description>内置 mihomo 代理核心，用于下载开源依赖。内容极少变动。</Description>
    <Version>1.0.0</Version>
    <ReleaseDate>2026-09-18</ReleaseDate>
    <ForcedInstallation>true</ForcedInstallation>
    <SortingPriority>100</SortingPriority>
</Package>
```

> **关键点**：稳定组件的 `<Version>` 绝对不要跟着应用版本一起升。
> IFW 客户端是**按 Version 字符串比较**决定要不要重下的——版本号一涨，
> 内容再一样也会全量重下 14.5 MB。`COMPONENT_VERSIONS` 字典就是为了把这件事固化下来。

### 4.3 repogen 参数改造

当前脚本用的是 `-r`（强制删库重建），这本身就排除了增量。改为：

```python
    # 3. repogen 生成/更新在线仓库
    if args.skip_repo:
        print("== 跳过 repogen ==")
    else:
        REPO.mkdir(exist_ok=True)

        # --update：只重新打包 Version 有变化的组件，未变组件的归档原样保留。
        #   这是增量的第一道闸——避免每次发版把 14.5MB 的 mihomo 重新压一遍。
        #   注意 --update 与 -r 互斥：-r 会先删掉整个仓库目录。
        # --sha-update：对列出的组件用"内容 sha1"而非版本号判断是否需要重打。
        #   适合 runtime/docs 这类内容稳定但你可能忘了改版本号的组件，双保险。
        # --unite-metadata：所有组件 meta 合成一个 7z，加快客户端元数据阶段。
        #   代价是任一组件 meta 变化都会让整包重下，但 meta 只有几十 KB，可接受。
        stable = ",".join(["com.videotoolbox.runtime",
                           "com.videotoolbox.docs",
                           "com.videotoolbox.tools"])
        cmd = [str(IFW_BIN / "repogen.exe"),
               "--update",
               "--sha-update", stable,
               "--unite-metadata",
               "--ac", str(args.compression),
               "--af", "7z",
               "-p", str(STAGE), str(REPO)]
        # 首次建库时 --update 无意义（没有旧仓库），退化为全量生成
        if not (REPO / "Updates.xml").exists():
            cmd = [c for c in cmd if c != "--update"]

        print("== repogen 生成组件仓库 ==")
        print("   " + " ".join(cmd))
        r = subprocess.run(cmd, capture_output=True, text=True,
                           encoding="utf-8", errors="replace")
        print((r.stdout or "")[-3000:], (r.stderr or "")[-2000:] if r.returncode else "")
        if r.returncode:
            sys.exit("repogen 失败")
        if not (REPO / "Updates.xml").exists():
            sys.exit("Updates.xml 未生成")
```

同时把 `COMPONENT_VERSIONS` 写进各组件的 `package.xml`（在暂存阶段动态改写，

### 5.1 构建侧：生成清单

`installer_src/gen_manifest.py`：

```python
# -*- coding: utf-8 -*-
"""生成文件级增量更新清单。

对 dist\视频工具箱\（onedir 产物）+ src\ + docs\ + tools\ 做全量 sha256 指纹，
输出 manifest.<version>.json。客户端比对本地指纹，只下载 sha 不同的文件。

设计要点：
- 用 sha256 而非 mtime/size：mtime 会因构建机时间而漂移，size 相同内容可能不同。
- 清单文件名带版本号，入口 latest.json 只含指针。这样规避 GitHub Pages
  约 10 分钟的 CDN 缓存（Pages 忽略 query string，?v= 无效，只能靠文件名）。
- 对上一版本的大文件额外产 xdelta3 补丁，客户端有旧文件时走补丁，否则回退全量。
"""
import argparse
import hashlib
import json
import subprocess
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent

# 参与清单的路径 -> 安装后相对 {app} 的位置
SOURCES = [
    (ROOT / "dist/视频工具箱",           ""),          # exe + _internal
    (ROOT / "src",                       "src"),
    (ROOT / "docs",                      "docs"),
    (ROOT / "tools/mihomo",              "tools/mihomo"),
    (ROOT / "tools/ai_client.py",        "tools/ai_client.py"),
    (ROOT / "tools/download_open_source_deps.py", "tools/download_open_source_deps.py"),
    (ROOT / "subtitle_calib_merged.py",  "subtitle_calib_merged.py"),
    (ROOT / "github_proxy.yaml",         "github_proxy.yaml"),
]

EXCLUDE_DIRS = {"__pycache__", ".git"}
EXCLUDE_SUFFIX = {".pyc", ".pyo"}

# 超过此体积的文件才考虑做二进制补丁（小文件直接下全量更简单可靠）
PATCH_MIN_SIZE = 4 * 1024 * 1024


def sha256_file(p: Path, chunk: int = 1 << 20) -> str:
    h = hashlib.sha256()
    with p.open("rb") as f:
        while True:
            b = f.read(chunk)
            if not b:
                break
            h.update(b)
    return h.hexdigest()


def collect() -> dict:
    """遍历 SOURCES，返回 {相对路径: {"sha256":..., "size":...}}。"""
    out = {}
    for base, rel_prefix in SOURCES:
        base = Path(base)
        if base.is_file():
            rel = f"{rel_prefix}" if rel_prefix else base.name
            out[rel.replace("\\", "/")] = {
                "sha256": sha256_file(base), "size": base.stat().st_size}
            continue
        if not base.is_dir():
            print(f"  [warn] 跳过不存在的路径: {base}")
            continue
        for p in sorted(base.rglob("*")):
            if not p.is_file():
                continue
            if p.suffix in EXCLUDE_SUFFIX:
                continue
            if any(part in EXCLUDE_DIRS for part in p.relative_to(base).parts):
                continue
            rel = (Path(rel_prefix) / p.relative_to(base)).as_posix() if rel_prefix \
                  else p.relative_to(base).as_posix()
            out[rel] = {"sha256": sha256_file(p), "size": p.stat().st_size}
    return out


def make_patch(old_root: Path, new_root: Path, rel: str, out_dir: Path) -> dict | None:
    """对单个文件生成 xdelta3 补丁。返回补丁描述，失败返回 None（客户端回退全量）。"""
    o, n = old_root / rel, new_root / rel
    if not o.is_file() or not n.is_file():
        return None
    if n.stat().st_size < PATCH_MIN_SIZE:
        return None
    out_dir.mkdir(parents=True, exist_ok=True)
    patch = out_dir / (rel.replace("/", "__") + ".xd3")
    # xdelta3 -e -s 旧文件 新文件 补丁
    r = subprocess.run(["xdelta3", "-e", "-9", "-s", str(o), str(n), str(patch)],
                       capture_output=True, text=True)
    if r.returncode != 0 or not patch.is_file():
        print(f"  [patch-fail] {rel}: {r.stderr[:120]}")
        return None
    ratio = patch.stat().st_size / max(n.stat().st_size, 1)
    print(f"  [patch] {rel}: {n.stat().st_size/1048576:.1f}MB -> "
          f"{patch.stat().st_size/1048576:.2f}MB ({ratio:.1%})")
    return {
        "from_sha256": sha256_file(o),
        "url": f"patches/{out_dir.name}/{patch.name}",
        "sha256": sha256_file(patch),
        "size": patch.stat().st_size,
        "result_size": n.stat().st_size,
    }


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("version", help="新版本号，如 1.15.0")
    ap.add_argument("--prev-dir", help="上一版 onedir 产物目录，提供则生成二进制补丁")
    ap.add_argument("--out", default=str(ROOT / "installer_repository/files"))
    ap.add_argument("--base-url",
                    default="https://09th90.github.io/VideoToolbox/files/")
    args = ap.parse_args()

    files = collect()
    total = sum(v["size"] for v in files.values())
    print(f"清单: {len(files)} 个文件, {total/1048576:.1f}MB")

    if args.prev_dir:
        prev_root = Path(args.prev_dir)
        tag = f"{args.version}"
        n_patch = 0
        for rel, meta in files.items():
            if meta["size"] < PATCH_MIN_SIZE:
                continue
            pd = make_patch(prev_root, ROOT / "dist/视频工具箱", rel,
                            Path(args.out) / "patches" / tag)
            if pd:
                meta["patch"] = pd
                n_patch += 1
        print(f"生成补丁: {n_patch} 个")

    manifest = {
        "app": "视频工具箱",
        "version": args.version,
        "base_url": args.base_url if args.base_url.endswith("/") else args.base_url + "/",
        "generated": __import__("time").strftime("%Y-%m-%dT%H:%M:%S%z"),
        # 低于此版本的客户端不允许走增量（差异过大，直接引导全量重装更安全）
        "min_incremental_from": "1.15.0",
        "files": files,
    }

    out = Path(args.out)
    out.mkdir(parents=True, exist_ok=True)
    # 带版本号的文件名：绕开 GitHub Pages CDN 缓存
    mf = out / f"manifest.{args.version}.json"
    mf.write_text(json.dumps(manifest, ensure_ascii=False, indent=1),
                  encoding="utf-8")
    # 入口指针：体积极小，即使被缓存 10 分钟影响也可控
    (out / "latest.json").write_text(
        json.dumps({"version": args.version,
                    "manifest": f"manifest.{args.version}.json"},
                   ensure_ascii=False),
        encoding="utf-8")
    print(f"写出: {mf}")
    print(f"      {out / 'latest.json'}")


if __name__ == "__main__":
    main()
```

### 5.2 客户端：检查与下载

`src/self_updater.py`（属于代码层，可热更）：

```python
# -*- coding: utf-8 -*-
"""文件级增量自更新。

流程：拉清单 → 比对本地指纹 → 只下变化的文件到暂存区 → 逐个校验 sha256
      → 全部通过后交给 updater.exe 做原子替换 → 重启。

可靠性底线（任何一条不满足就放弃增量、回退到"提示用户跑维护工具全量更新"）：
  ① 清单能拉到且 JSON 合法、version 字段存在；
  ② 本地版本 >= min_incremental_from；
  ③ 所有待更新文件下载后 sha256 全部匹配；
  ④ 补丁应用后结果 sha256 匹配（不匹配则改下该文件全量）；
  ⑤ 暂存区完整后才动 {app} 里的任何文件 —— 绝不做"边下边换"。
"""
from __future__ import annotations

import hashlib
import json
import os
import shutil
import subprocess
import sys
import urllib.request
from pathlib import Path

LATEST = "latest.json"
LOCAL_MANIFEST_NAME = "_installed_manifest.json"


def app_dir() -> Path:
    if getattr(sys, "frozen", False):
        return Path(sys.executable).resolve().parent
    return Path(__file__).resolve().parent.parent


def _sha256(p: Path) -> str:
    h = hashlib.sha256()
    with p.open("rb") as f:
        for b in iter(lambda: f.read(1 << 20), b""):
            h.update(b)
    return h.hexdigest()


def _get_json(url: str, timeout: int = 30):
    req = urllib.request.Request(url, headers={"User-Agent": "VideoToolbox-Updater"})
    with urllib.request.urlopen(req, timeout=timeout) as r:
        return json.loads(r.read().decode("utf-8"))


class UpdateResult:
    """更新检查结果。ok=False 时 reason 说明为什么必须走全量。"""
    def __init__(self, ok: bool, reason: str = "", pending=None, version: str = ""):
        self.ok = ok
        self.reason = reason
        self.pending = pending or []      # [(rel_path, meta), ...]
        self.version = version

    @property
    def total_bytes(self) -> int:
        return sum(m.get("size", 0) for _, m in self.pending)


def check_update(repo_url: str, local_manifest_path: Path | None = None) -> UpdateResult:
    """比对远端清单与本地已安装清单，返回待更新文件列表。"""
    ad = app_dir()
    local_manifest_path = local_manifest_path or (ad / "data" / LOCAL_MANIFEST_NAME)

    try:
        latest = _get_json(repo_url.rstrip("/") + "/" + LATEST)
        remote = _get_json(repo_url.rstrip("/") + "/" + latest["manifest"])
    except Exception as e:                       # 网络/解析失败：静默放弃
        return UpdateResult(False, f"清单获取失败: {e}")

    new_ver = remote.get("version", "")
    if not new_ver or not remote.get("files"):
        return UpdateResult(False, "远端清单格式异常")

    if not local_manifest_path.is_file():
        return UpdateResult(False, "本地无安装清单，需走全量安装", version=new_ver)

    try:
        local = json.loads(local_manifest_path.read_text(encoding="utf-8"))
    except Exception as e:
        return UpdateResult(False, f"本地清单损坏: {e}", version=new_ver)

    cur_ver = local.get("version", "0.0.0")
    if cur_ver == new_ver:
        return UpdateResult(False, "已是最新版本", version=new_ver)

    # 跨版本过大时不做增量：中间状态难以保证一致，全量重装更稳
    min_from = remote.get("min_incremental_from")
    if min_from and _ver_tuple(cur_ver) < _ver_tuple(min_from):
        return UpdateResult(False, f"当前 {cur_ver} 过旧，请全量重装", version=new_ver)

    lf = local.get("files", {})
    rf = remote["files"]
    pending = []
    for rel, meta in rf.items():
        old = lf.get(rel)
        if old is None or old.get("sha256") != meta.get("sha256"):
            # 只把清单里记的 sha 带上；实际落地前还会再验一次本地文件
            pending.append((rel, meta))

    # 远端已删除的文件：交给 updater 处理，这里只记录
    removed = [rel for rel in lf if rel not in rf]

    if not pending and not removed:
        return UpdateResult(False, "版本号不同但文件无差异", version=new_ver)

    return UpdateResult(True, "", pending, new_ver), removed


def _ver_tuple(v: str):
    try:
        return tuple(int(x) for x in v.split(".")[:3])
    except Exception:
        return (0, 0, 0)


def download_pending(res: UpdateResult, removed: list[str]) -> Path | None:
    """把待更新文件下到 {app}\data\_pending\，全部校验通过才返回暂存目录。
    任何一个文件校验失败就整体放弃 —— 不允许出现"装了一半"的状态。"""
    ad = app_dir()
    try:
        remote = _get_json(res_repo_url() + "/" + LATEST)
        manifest = _get_json(res_repo_url() + "/" + remote["manifest"])
    except Exception:
        return None
    base = manifest["base_url"].rstrip("/")

    stage = ad / "data" / "_pending"
    if stage.exists():
        shutil.rmtree(stage, ignore_errors=True)
    stage.mkdir(parents=True, exist_ok=True)

    for rel, meta in res.pending:
        dst = stage / rel
        dst.parent.mkdir(parents=True, exist_ok=True)
        want = meta["sha256"]

        # 优先走补丁：本地旧文件 sha 与补丁的 from_sha256 匹配时才用
        got = False
        patch = meta.get("patch")
        if patch:
            cur = ad / rel
            if cur.is_file() and _sha256(cur) == patch["from_sha256"]:
                got = _apply_patch(cur, base + "/" + patch["url"],
                                   patch["sha256"], dst, want)

        if not got:
            got = _download_full(base + "/" + rel, dst, want)

        if not got:
            shutil.rmtree(stage, ignore_errors=True)   # 整体回滚
            return None

    # 记录待删除文件，由 updater 执行
    (stage / "_removed.json").write_text(
        json.dumps({"version": res.version, "removed": removed}, ensure_ascii=False),
        encoding="utf-8")
    return stage


def _download_full(url: str, dst: Path, want_sha: str) -> bool:
    try:
        tmp = dst.with_suffix(dst.suffix + ".part")
        req = urllib.request.Request(url, headers={"User-Agent": "VideoToolbox-Updater"})
        with urllib.request.urlopen(req, timeout=300) as r, tmp.open("wb") as f:
            shutil.copyfileobj(r, f, 1 << 20)
        if _sha256(tmp) != want_sha:
            tmp.unlink(missing_ok=True)
            return False
        tmp.replace(dst)
        return True
    except Exception:
        return False


def _apply_patch(src: Path, patch_url: str, patch_sha: str,
                 dst: Path, want_sha: str) -> bool:
    """xdelta3 解码。需要 {app}\tools\xdelta3.exe 随包分发（约 200KB）。"""
    xdelta = app_dir() / "tools" / "xdelta3.exe"
    if not xdelta.is_file():
        return False
    try:
        pf = dst.with_suffix(".xd3")
        if not _download_full(patch_url, pf, patch_sha):
            return False
        # xdelta3 -d -s 旧文件 补丁 输出
        r = subprocess.run([str(xdelta), "-d", "-s", str(src), str(pf), str(dst)],
                           capture_output=True, timeout=600)
        pf.unlink(missing_ok=True)
        if r.returncode != 0 or not dst.is_file():
            return False
        return _sha256(dst) == want_sha       # 补丁结果必须等于全量 sha
    except Exception:
        return False


def res_repo_url() -> str:
    """更新源地址。默认官方源，可被 data\update_source.txt 覆盖（内网/镜像）。"""
    f = app_dir() / "data" / "update_source.txt"
    if f.is_file():
        u = f.read_text(encoding="utf-8").strip()
        if u:
            return u.rstrip("/")
    return "https://09th90.github.io/VideoToolbox/files"
```

### 5.3 替换器：解决「运行中的 exe 无法覆盖」

Windows 下运行中的 exe **不能删除、不能覆盖，但可以重命名**。利用这一点：

`installer_src/updater.py`（单独打成一个几十 KB 的 `updater.exe`，随 `core` 组件分发）：

```python
# -*- coding: utf-8 -*-
"""独立替换器。由主程序在退出前拉起，负责把暂存区的文件落到 {app}。

为什么要独立进程：主程序自己无法替换正在运行的自己。
为什么不直接用 .bat：会闪控制台窗口，且中文路径下的 quoting 极易出错。

核心技巧：正在运行的 exe 不能被覆盖，但**能被重命名**。
所以流程是 旧exe → .old，新exe → 就位，重启，下次启动时清理 .old。
这样连"等主进程退出"都可以省掉，替换是准原子的。

用法：updater.exe <app_dir> <stage_dir>
返回码：0 成功 / 非 0 失败（失败时 {app} 保持原状，不会半新半旧）
"""
import json
import os
import shutil
import subprocess
import sys
import time
from pathlib import Path


def main() -> int:
    if len(sys.argv) < 3:
        print(__doc__)
        return 2

    app = Path(sys.argv[1]).resolve()
    stage = Path(sys.argv[2]).resolve()

    if not app.is_dir() or not stage.is_dir():
        print(f"路径无效: app={app} stage={stage}")
        return 2

    # 安全检查：暂存区必须位于 app 之下，避免被指向任意目录后覆盖系统文件
    try:
        stage.relative_to(app)
    except ValueError:
        print("暂存区不在程序目录内，拒绝执行")
        return 2

    meta_f = stage / "_removed.json"
    meta = json.loads(meta_f.read_text(encoding="utf-8")) if meta_f.is_file() else {}
    new_version = meta.get("version", "")
    removed = meta.get("removed", [])

    # ---- 1. 预检：暂存区里每个文件都必须存在且可读，任一缺失就整体放弃 ----
    payload = [p for p in stage.rglob("*") if p.is_file() and p.name != "_removed.json"]
    if not payload:
        print("暂存区为空，无事可做")
        return 0
    for p in payload:
        if not os.access(p, os.R_OK):
            print(f"预检失败，无法读取: {p}")
            return 1

    # ---- 2. 备份：把即将被覆盖的文件先移到 .bak 树，失败可整体回滚 ----
    bak = app / "data" / "_rollback"
    if bak.exists():
        shutil.rmtree(bak, ignore_errors=True)
    bak.mkdir(parents=True, exist_ok=True)

    renamed = []          # [(原路径, 备份路径)]
    exe_target = app / "视频工具箱.exe"
    new_exe = stage / "视频工具箱.exe"

    try:
        for p in payload:
            rel = p.relative_to(stage)
            target = app / rel
            if target.exists():
                b = bak / rel
                b.parent.mkdir(parents=True, exist_ok=True)
                # 运行中的 exe 走"重命名"而不是移动出目录（Windows 允许重命名）
                if target == exe_target and new_exe.is_file():
                    old = target.with_suffix(".exe.old")
                    if old.exists():
                        old.unlink()
                    os.rename(target, old)
                    renamed.append((target, old))
                else:
                    shutil.move(str(target), str(b))
                    renamed.append((target, b))

        # ---- 3. 落地：暂存区 -> 程序目录 ----
        for p in payload:
            rel = p.relative_to(stage)
            target = app / rel
            target.parent.mkdir(parents=True, exist_ok=True)
            shutil.move(str(p), str(target))

        # ---- 4. 删除远端已移除的文件 ----
        for rel in removed:
            t = app / rel
            try:
                if t.is_file():
                    t.unlink()
                elif t.is_dir():
                    shutil.rmtree(t, ignore_errors=True)
            except Exception as e:
                print(f"  [warn] 清理 {rel} 失败: {e}")   # 非致命，继续

        # ---- 5. 写新的本地清单（下次 check_update 的比对基准）----
        if new_version:
            mf = app / "data" / "_installed_manifest.json"
            mf.parent.mkdir(parents=True, exist_ok=True)
            files = {}
            for p in (app / rel for rel in
                      [q.relative_to(stage).as_posix() for q in payload]):
                pass  # 清单由主程序下次启动时按远端 manifest 重写，见下
            # 直接把远端清单副本落下更可靠：
            remote_mf = stage / "_manifest.json"
            if remote_mf.is_file():
                shutil.copy2(remote_mf, mf)

        shutil.rmtree(stage, ignore_errors=True)
        shutil.rmtree(bak, ignore_errors=True)
        print(f"更新完成: {new_version}，{len(payload)} 个文件")

    except Exception as e:
        # ---- 回滚：把备份移回去，保证 {app} 停在旧版本的完整状态 ----
        print(f"更新失败，回滚: {e}")
        for target, b in reversed(renamed):
            try:
                if target.exists():
                    target.unlink() if target.is_file() else shutil.rmtree(
                        target, ignore_errors=True)
                if b.exists():
                    shutil.move(str(b), str(target))
            except Exception as e2:
                print(f"  [rollback-warn] {target}: {e2}")
        return 1

    # ---- 6. 重启主程序 ----
    if exe_target.is_file():
        subprocess.Popen([str(exe_target)], cwd=str(app),
                         creationflags=getattr(subprocess, "DETACHED_PROCESS", 0))
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

主程序侧的调用（在 `video_toolbox_qt.py` 的退出流程里，
**注意 v1.12.1 那个「退出后无限重启」的教训——务必确认拿到的是 `updater.exe`
而不是主 exe 自身**）：

```python
def apply_update_and_restart(stage: Path) -> bool:
    """拉起 updater.exe 后退出主程序。

    严格复用 v1.12.1 建立的 _is_self_exe() 兜底原则：
    解析不到 updater.exe 就**放弃更新**，绝不回退到用 sys.executable 拉自己
    （那会造成新旧实例互相抢占，就是当年那个无限重启 bug）。
    """
    updater = app_dir() / "updater.exe"
    if not updater.is_file():
        log("updater.exe 不存在，跳过本次更新")
        return False
    if _is_self_exe(updater):          # 理论上不可能，但按既有原则守住
        log("updater 路径解析到自身，跳过")
        return False
    try:
        subprocess.Popen(
            [str(updater), str(app_dir()), str(stage)],
            cwd=str(app_dir()),
            creationflags=subprocess.DETACHED_PROCESS | subprocess.CREATE_NEW_PROCESS_GROUP,
            close_fds=True,
        )
    except Exception as e:
        log(f"拉起 updater 失败: {e}")
        return False
    # 交棒成功，主程序立即退出（不要 wait，否则 updater 等不到文件解锁）
    os._exit(0)
```

### 5.4 发布侧：增量上传 blob

`deploy_installer_ghpages.py` 当前**每次发版把 104 MB 全量重传一遍**
（逐个 POST blob）。GitHub 的 blob 是内容寻址的，可以本地算出 sha 后跳过未变文件：

```python
import hashlib

def git_blob_sha(data: bytes) -> str:
    """本地计算 git blob 的 sha1，与 GitHub tree 里的 sha 完全一致。
    git 的对象哈希就是 sha1("blob <长度>\\0" + 内容)，无需调用 git 命令。"""
    h = hashlib.sha1()
    h.update(b"blob %d\0" % len(data))
    h.update(data)
    return h.hexdigest()


def remote_tree_map() -> dict:
    """取 gh-pages 当前的 {path: blob_sha}。分支不存在时返回空表。"""
    try:
        t = api("GET", f"git/trees/{BRANCH}?recursive=1")
    except SystemExit:
        return {}
    return {e["path"]: e["sha"] for e in t.get("tree", []) if e["type"] == "blob"}


def upload_changed(files, remote: dict):
    """只上传内容变化的文件。返回 tree 条目列表（含未变文件的既有 sha）。"""
    tree, skipped, uploaded = [], 0, 0
    for i, f in enumerate(files, 1):
        rel = f.relative_to(REPO_DIR).as_posix()
        data = f.read_bytes()
        sha = git_blob_sha(data)

        if remote.get(rel) == sha:
            # 内容未变：直接复用远端已有的 blob sha，一个字节都不用传
            tree.append({"path": rel, "mode": "100644", "type": "blob", "sha": sha})
            skipped += 1
            continue

        blob = api("POST", "git/blobs", {
            "content": base64.b64encode(data).decode("ascii"),
            "encoding": "base64",
        })
        tree.append({"path": rel, "mode": "100644", "type": "blob", "sha": blob["sha"]})
        uploaded += 1
        print(f"  [{i}/{len(files)}] ↑ {rel} ({len(data)/1048576:.1f} MB)")

    print(f"上传 {uploaded} 个，跳过 {skipped} 个（内容未变）")
    return tree
```

`main()` 里把原来的全量循环换成：

```python
    remote = remote_tree_map()
    print(f"远端已有 {len(remote)} 个 blob")
    tree = upload_changed(files, remote)
```

**收益**：L1+L2 做完后，日常迭代只有 `code` 组件的 0.5 MB 归档 + `Updates.xml` +
meta 包变化，上传量从 104 MB 降到 ~1 MB，发版耗时从几十分钟降到几十秒。

> 另外提醒一个 GitHub Pages 的坑：**Pages 忽略 query string，CDN 缓存约 10 分钟**。
> 所以 `Updates.xml` 更新后，客户端可能拿到旧副本。缓解办法是发版后不立刻通知用户，
> 或把关键指针放在带版本号的文件名里（L3 的 `manifest.<version>.json` 就是这么设计的）。
> IFW 侧无法改文件名，只能接受这个延迟。

## 六、实施顺序与验收

### 推荐顺序

1. **先做 L2 的 spec 改造并验证程序能正常跑**（onedir + bootstrap）。
   这是风险最高的一步——路径锚定、`_MEI` 相关兜底、退出同步逻辑都要重新验证。
   验收：`_selftest_pack.py`、`_selftest_e2e.py` 全过；
   实测启动、字幕处理、字幕校准、AI 校准、退出同步各走一遍。
   **这一步没过就不要往下走**，L1/L3 都建立在它之上。

2. **再做 L1 的组件拆分**。验收：
   - 全新安装：装完目录结构与旧版一致，程序正常启动；
   - 覆盖升级：从 1.14.1 装到 1.15.0，`data\`、`logs\` 内容一字未动，
     旧版残留目录（`tools\videocaptioner` 等）被清掉；
   - **关键验收**：只改一个 `.py` 后重新发版，客户端「维护工具 → 更新」
     只显示 `com.videotoolbox.code` 需要更新，下载量 ~0.5 MB，
     `runtime` 的 14.5 MB 不重下。

3. **发布脚本增量上传**（5.4）。验收：第二次发版时日志显示大量 `跳过（内容未变）`。

4. **L3 视需求再上**。只有确实需要「程序内静默升级、用户零操作」时才做。
   如果用户能接受双击「维护工具」点一下更新，L1+L2 已经解决了 99% 的痛点，
   L3 带来的复杂度（回滚、锁文件、杀软拦截、清单一致性）不一定划算。

### 必须保留的全量兜底

无论做到哪一层，这几条不能省：

- **在线安装器 exe 继续发布**，作为新用户首装和增量失败后的救援路径；
- L3 的任何一步失败（清单拉不到、sha 不匹配、补丁应用失败、updater 返回非 0）
  都要**静默放弃并保持旧版可用**，然后提示用户走维护工具全量更新，绝不弹错误栈；
- `data\`、`logs\`、VideoCaptioner 用户配置在任何更新路径下都不碰——
  这一点现有 `[Files]` 白名单和 `RemoveTargetDir=false` 已经做对了，保持。

## 七、几个容易踩的坑

1. **`upx=True` 必须关掉**。留着它，onedir 的 DLL 每次构建字节都会变，
   整个 L2 白做。代价是体积涨一些（UPX 大约能省 30-50%），
   但换来的是增量能力，值。如果体积是硬约束（GitHub 单文件 100 MB 限制），
   考虑对 `_internal` 打 7z 分发、安装时解压，而不是 UPX。

2. **稳定组件的 `<Version>` 不要跟应用版本一起涨**。这是 L1 唯一容易失效的地方。
   版本号一涨，IFW 就重下，`--sha-update` 也救不回下载量（它只影响 repogen 是否重打归档）。

3. **组件间文件不能重叠**。IFW 按文件记录组件归属，重叠会导致更新 A 组件时
   动到 B 组件的文件。上面的划分已经保证互斥，后续加文件时注意别破坏。

4. **明文 `.py` 的启动性能**。`{app}\src` 走文件系统导入会比 PYZ 慢一点
   （首次导入要编译 `.pyc`）。项目里 `__pycache__` 是被排除的，
   建议改为**允许运行时生成** `__pycache__`（安装包里仍然不带，
   首次启动时由用户机上的 Python 自己生成），第二次启动就恢复速度。
   注意 `stage_one` 和 `collect` 里的 `EXCLUDE_SUFFIX` 只影响打包，不影响运行期。

5. **`min_incremental_from` 要认真维护**。跨太多版本的增量容易出一致性问题
   （中途某个版本删过文件、改过目录结构）。设一个滚动窗口（比如只支持最近 3 个版本增量），
   更早的版本直接引导全量重装，比debug 一致性 bug 便宜得多。

6. **杀软误报**。updater.exe 要重命名主 exe、删文件、写用户目录，
   是典型的「可疑行为」画像。无代码签名的话误报率不低。
   如果有条件，买个代码签名证书（对 IFW 安装器和 updater 都签）能省掉大量支持成本。
