### 1.2 关于 UI 层的更正

原判断「UI 视图层仅参考外观、实际代码自研」**与事实不符**：

- `src/video_toolbox_qt.py:2925` 的 `_build_engine()` 直接 `from videocaptioner.ui.view.home_interface import HomeInterface` 并实例化内嵌；
- `TranscriptionInterface`、`SettingInterface`、`TranscriptionSettingCard`、`TaskFactory`、`MyVideoWidget`、`TranscriptionSettingDialog` 均为引擎类；
- 36 处 monkey-patch 是对上述类的**运行期改写**（`_setup_command_bar`、`_on_transcript_finished`、`__init__`、`dropEvent` 等）；
- `engine_ui_brand_patch()` 承担「用户可见文案中性化」（隐藏品牌水印与捐助入口）。

**结论：UI 是引擎的 UI，自研的是补丁层。** 这使 UI 层替换成为工作量最大的单项，而非已完成项。

判定依据（三条事实，均可复验）
1. **它是广泛使用的开源项目，不是个人项目**——TeamNewPipe 维护、GitHub 公开、发行多年。按第三节判定口径（个人主导的 GPL 项目 → 必须剔除；广泛使用的开源组件 → 保留并登记），它属后者。

3. **交互方式是子进程调用**——`npe_backend.py` 以 `java -jar` 调用，不静态链接进 exe，不构成衍生作品关系。

**义务履行情况（`scripts/dev/_selftest_npe_compliance.py`，21 项正向 + 2 项负向，PASS）**
| GPL-3.0 义务 | 落实方式 |
|---|---|
| 提供许可全文 | `docs\开源许可_GPL-3.0.txt`（标准原文），由 iss 的 `Source:` 行随包分发 |
| 提供对应源码 | 声明给出上游仓库地址与源码压缩包地址；Java 侧封装与构建脚本随仓库分发 |

**P1 已确立的方法论**（后续接缝沿用）：

1. **兼容面 = 取值 + 成员名 + 反构造**，三者缺一不可。`TranslatorServiceEnum.OPENAI` 的教训：按值语义命名会让按名访问的调用方 `AttributeError`，且异常在 `try` 里被静默吞掉。
2. **契约值的唯一事实来源**是「运行期可观察接口 + settings.json 实存数据」。枚举成员**不能**直接由 `LANGUAGES` 键生成——后者含中英双语重复键（112 项），枚举是唯一标签（102 项）。
3. **自检脚本必须带负向验证**（污染取值后确认检查会失败），否则「全绿」可能只是检查形同虚设。
4. **改自检脚本的 import 前先分流**：测「我们自己的契约」才切自研模块；测「引擎行为 / 引擎存在性」的必须保留引擎 import（P1~P4 引擎仍是运行时）。
5. **多会话并行施工的实测风险**：同一仓库被多个模型同时编辑时，自检结果会**间歇性 PASS/FAIL**（`engine_paths` 自检首次 FAIL、复跑 PASS；`engine_asr_data` 自检退出码 1 后复跑 PASS）。判定回归前必须**复跑至少两次**，并对比文件 mtime 确认没有正在进行的编辑。交叉验证发现的问题要区分「真缺陷」与「读到编辑中间态」。
6. **零三方依赖优先，组件只做可选增强**。`engine_asr_data.from_srt` 的双语检测优先用 langdetect（MIT 组件，运行期已装），try-import 失败即退化到自研 Unicode 脚本估计——自研模块不得把「引擎恰好装了某组件」当前提，否则裁剪环境直接不可用（引擎自身在缺 langdetect 时反而 `import videocaptioner.core.asr.asr_data` 直接失败，自研模块可用性更宽）。
7. **组件的运行期非确定性是兼容面边界，不是自研偏差**。langdetect 的 `detect()` 依赖进程内 `DetectorFactory` 单例的 random 状态，同一短文本跨进程可能判出不同语言（引擎自身同样不稳定，实测 "Hello world" 跨进程 en/nl 都有）。自检对这类路径只用**跨进程稳定**的输入做逐字节断言（纯中文、中韩语言对），其余场景明确标注为非确定性，不追平。
8. **读文件的换行口径要对齐**：引擎 `Path.read_text()` 带 universal newlines（CRLF→LF），自研走 `decode_any(read_bytes())` 时必须显式规范化，否则 Windows 上 CRLF 字幕的 `split("\n\n")` 切不开块、整份解析为 0 条。
9. **负向注入点要落在「语义生效」的位置**：污染代码让用例崩溃（AttributeError 等）与让用例行为变体是两回事——`engine_cache` 负向②曾把 `self._ensure()` 插在 `self._factory` 赋值之前，构造即崩而非构造即建库，检出的不是目标行为。锚点必须紧跟依赖项初始化之后。
10. **负向判据必须检「目标行为」，不能检「与参照物的差异」**（P2 实测两次踩坑）。`engine_asr` 负向①原判据是「污染后的合并结果是否仍与引擎一致」——但滑动窗口会重新定位切点，两边**仍然一致**，负向验证假绿。改为直接检「重叠窗提取是否误纳窗外段」才检出。判据要指向**被破坏的那个不变量**，不是整体输出的差异。
11. **负向退出码的方向要写对**：`sys.exit(3 if 条件 else 0)` 里「条件」必须是「**正向检查失效了**」而非「行为正确」。写成 `sys.exit(3 if key.startswith(crc) else 0)` 会在污染生效时返回 0，判成「检查通过」。
12. **`env` 必须合并进 `os.environ`**，不能拿字面 dict 当整个子进程环境——只传 `{"PYTHONPATH": ...}` 会丢掉 `SystemRoot`/`COMSPEC` 等 Windows 必需变量，子进程可能在启动阶段就挂掉，表现为「污染后仍判通过」。所有 `_selftest_engine_*.py` 的 `negative()` 都用 `env = dict(os.environ)` + 覆盖单个键。
13. **别给单个布尔表达式套 `all()`**：`all(x <= y <= z)` 里若比较对象本身是 bool 以外的类型会报 `TypeError: 'bool' object is not iterable`。进度单调性这类断言直接写表达式。
14. **HTTP 传输层要能脱离网络测**：`engine_asr_http` 单列出来后，用 `http.server` 起本地假服务即可覆盖 multipart 字段、Authorization 头、空语言不传、401/HTML/纯文本/空输入六类错误路径——不需要真实 ASR 服务，也不会产生费用。
15. **负向子进程的环境变量有两处陷阱**（P1/P2 各踩一次，六个自检脚本现已统一修好）：
    - **别拿字面 dict 当整个子进程环境**。`env = {"PYTHONPATH": ...}` 会丢掉 `SystemRoot`/`COMSPEC` 等 Windows 必需变量，子进程可能在启动阶段就挂掉，表现为「污染后仍判通过」——**假绿**。正确写法 `env = dict(os.environ)` 后只覆盖目标键。
    - **覆盖 `PYTHONPATH` 时要保留原值**。`tmp + os.pathsep + SRC` 会丢掉外部注入的路径（本机就有 WorkBuddy 的 cli shim），换个环境自检就莫名失败。正确写法 `os.pathsep.join([tmp, SRC] + ([os.environ["PYTHONPATH"]] if ... else []))`。  
      这两条的共同症状都是**静默假绿**，排查时先看子进程 stderr 有没有异常，别急着怀疑被测代码。
16. **跨进程/跨实现的「行为细节」要逐条对着参照物验**。例：引擎 `_make_segments` **句级 `text.strip()`、词级不 strip**（词是 token，不该动空白）。这类差异不验就不知道，跟着直觉写必然错一边。

2. **每个自检脚本都有独立的「负向」段**。只跑正向会得到假绿——负向段的价值恰恰在于证明正向检查**不是形同虚设**。改动任何接缝后，请连负向段一起跑。

4. **新接缝必须显式登记 `packaging/视频工具箱.spec` 的 `hiddenimports`**。这些模块都从函数体内延迟 import（`vc_*` 补丁函数），静态分析跟踪不到；漏登记不会报错，只在打包后运行期 `ModuleNotFoundError`，而调用点通常套了 `try/except` 只记日志 ⇒ 静默失效。
