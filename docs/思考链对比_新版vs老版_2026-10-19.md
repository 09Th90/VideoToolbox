# 思考链对比评估：新版（终末地 Si）vs 老版（鸣潮 Suoming）

> 样本：同一条流水线、同一个模型、同一套术语库（`subtitle_calib_merged` + 对象级 KB）
> 新片：`Our Proxy can't be this CUTE! | Arknights: Endfield Operator Story: Si`（59 cue，两轮）
> 老片：`Suoming Combat Showcase Reaction! | Wuthering Waves`（165 cue，一轮）
> 依据：两片的完整运行日志、`.calib.md` 报告、`.srt` 产物（逐字节比对）

---

## 一、结论

**同一模型，新版退化不在模型能力，在于「喂给它的知识」是空的，而且是错的。**

- 老版：知识库命中了本片真正需要的规则（Suming / Chisa / Sheen / Yinlin），模型逐条核对 → **6 处改动全部正确**；
- 新版：知识库只喂进去 **1 条**规则，还是**跨作品的**（`Mizuki → 水月`，鸣潮实体），模型被这条规则带偏 20 秒，最后提议把「水木茂」改成「水月茂」，被评审拦下 → **0 处改动**。

新版的两轮 AI 都在做「自我辩论」，老版在「逐条核对」。差别不在思考深度，在**输入质量**。

## 三、新版的四个失效点（按严重度）

### 1. 片源识别失败 → 终末地词条整表没加载（致命）

```
[3/8] 载入对象级术语知识库（模式 bi）…
→ 实体 1766 个 → 规则 2144 条
```

片源被当成纯 `bi`，因为 `endfield_auto_markers` 在本片返回 **`[]`**（需 ≥2 个特征词才并入 `ENDFIELD_BI_TERMS`）。

后果直接可测：

```
ENDFIELD_BI_TERMS["操作员"] = "干员"     ← 词条在库里
BILINGUAL_TERMS["操作员"]  = None       ← 但 bi 模式取不到
```

所以「操作员文件」原样留在产物里，而报告自己写着「应为干员档案，把握：高」。

### 2. 唯一注入的规则是跨作品的，把模型带偏

`Mizuki → 水月` 是**鸣潮**的实体（角色「水月」），却进了终末地片源的注入。模型拿到唯一一条知识，只能拿它去套所有命中：

> 「水木茂」（Mizuki Shigeru，漫画家）→ 按规则应改「水月」→ 得到「水月茂」

这是**对象缺少「作品维度」**的直接后果：`Entity.modes` 只有 `bi/ja/ko/endobi` 这类**语言/流程维度**，没有「这个对象属于鸣潮还是终末地」的维度。`bi` 是通用双语模式，于是两个作品的词条混在一个池子里。

同一机制在老片上是正收益（鸣潮词条喂鸣潮片），在新片上是负收益（鸣潮词条喂终末地片）。

### 3. 报告识别了，产物没落盘

新版报告第四节（官方中文核对）明确列出两条高把握修正：

| 字幕写法 | 建议官方中文 | 把握 |
|---|---|---|
| 操作员 | 干员 | 高 |
| 操作员文件 | 干员档案 | 高 |

但产物 0 改动。原因是「校准风格：术语级（只替换名词）」的 AI 通道只认**知识库规则**，报告生成走的是另一条通道（`official_terms`），两条通道之间没有回写。

**这不是模型问题，是管道断裂**：识别 → 报告 → 人工复制，中间少了一步自动采纳。

### 4. tag 佐证只看字幕正文，作品名全被剔除

两轮都出现：

```
⚠ tag 佐证过滤剔除（字幕无据/疑似幻觉）：终末地 / 明日方舟终末地 / 明日方舟 / Si / 干员档案 / 鹰角网络
```

最终 tag 是「管理员 / 萝莉 / 游戏杂谈 / 剧情 / 可爱 / 二次元 / 搞笑 / 教程攻略 / 二游 / 动作游戏」——**一个作品名都没有**。

根因：`_tag_attested()` 只在 `hay_zh / hay_en`（字幕正文）里找佐证，而「终末地」只出现在**标题**里（`Arknights: Endfield Operator Story: Si`），字幕正文一次都没提。

对 B 站分发来说这是硬伤：没有作品名的 tag 等于放弃搜索流量。

## 四、老版值得保留的行为

1. **严格的「无据不动」**：`千鹤`（Chizuru 不在库）、`明霞`（无法确认）、`她`（代词不能换名词）全部放过，并写下理由。
2. **ASR 误听的正确归因**：`swimming` → 判定为 `Suming` 的误听，中文已是「锁暝」→ 不动。这类判断比机械替换更有价值。
3. **reason 格式规范**：`银琳 → 吟霖`，可直接进学习库。
4. **逐条编号核对**：165 条全部过一遍，没有跳读。

## 六、改进方向（按 ROI）

| 优先级 | 动作 | 依据 |
|---|---|---|
| P0 | 片源识别加**标题/文件名通道**：`endfield_auto_markers` 同时扫标题，或直接读文件名（`Operator Story: Si` + `Arknights: Endfield` 已足够判定） | 新版 0 改动的根因 |
| P0 | 知识注入加**作品维度过滤**：`bi` 模式下按片源作品筛实体，别把鸣潮词条喂给终末地片 | `水月茂` 的根因 |
| P1 | 评审拒绝理由**回灌下一轮**（现在是模型自己重新想一遍才纠正，浪费一轮 112 s） | 新版两轮才收敛 |
| P1 | `official_terms` 高把握条目**一键采纳**（进术语表或直接改产物），别只写进报告 | 新版「操作员→干员」识别了却不改 |
| P1 | `hay_zh/hay_en` 并入**原始标题 + 文件名** | tag 作品名全丢 |
| P2 | 技能名对象化：`Nine shadows / Metal canopy / Sundering peace / Seal evil rain / Five old sever` 建 Entity（`category=术语`，`modes` 覆盖对应作品） | 老版 5 条技能名全未覆盖 |

## 七、对「对象级」评估的印证

这两段日志正好实测了上一轮报告里的三条判断：

| 上一轮的判断 | 本次证据 |
|---|---|
| `modes` 只有语言维度，缺作品维度 | `Mizuki→水月`（鸣潮）被注入终末地片 |
| 没有 mention 级对齐，字符串命中即替换 | 「水木茂」被当成 `Mizuki` 的错形候选 |
| 执行层不认识对象，检测强于修复 | 「操作员→干员」在库里、在报告里，就是不在产物里 |

**结论不变，但优先级要调**：原报告把 P2（mention 消歧）当分水岭，现在看 **P0 的「作品维度隔离」更紧急**——它直接决定一部片是 6 处改动还是 0 处改动。
