# 校准知识更新库 —— 管理员手册（独立程序 kb_admin.exe）

- 版本：v1.12.2（2026-09-14；恢复 GitHub 收集通道，管理员侧全面独立成 exe）
- 实现位置：项目根 `kb_admin.exe`（源码 `kb_admin.py`，**完全独立程序**：不
  import 工具箱任何模块；合并/校验逻辑与客户端脚本同口径独立复刻）
- 布局要求：把 exe 与 `github_proxy.yaml`、`subtitle_calib_merged.py` 放同一
  目录（即工具箱程序根），即自动读取内置连接配置；也可用环境变量
  `VT_GITHUB_YAML` 指定 yaml 路径
- 自动验证：`kb_admin.exe selftest`（init→上传→collect→compact→prune 全链）

## 与工具箱的分工（v1.12.2 架构边界）

| 角色 | 动作 | 载体 |
|------|------|------|
| 普通用户 | **更新**：从 GitHub 拉全体使用者沉淀并条目级合并（可选叠加共享库增量） | 启动自动 / 设置页「立即更新」 |
| 普通用户 | 上传：全自动、隐藏后台（learn 实时写学习库；退出派生隐藏子进程推送 GitHub） | 无任何界面入口 |
| 管理员（kb_admin.exe） | 建库、收编、折叠、清理、跨机分发 | 本手册全部命令 |

GitHub 连接参数（owner/repo/branch/kb_branch/files/token）统一在维护者本机
`github_proxy.yaml` 的 `vt-github` 段——**换仓库只改 yaml，代码与 exe 都不动**。
（该文件含代理节点凭据，属维护者本机配置，不随工具箱安装包分发。）

## 一、首次部署（管理员）

1. 生成首版基线（AST 静态读脚本内置表，不执行脚本）：

   ```
   kb_admin.exe init
   ```

   产出 `<root>\baseline.json`（seq=1，约 1500 条，author=system）。
   `<root>` 默认 `<exe所在目录>\data\calib_sync_remote\`，可用 `--root` 或
   `VT_SYNC_ROOT` 指定。

2. 选一种更新库分发方式：
   - **GitHub 收集（默认，零配置）**：各机工具箱退出时自动把「校准脚本 +
     学习库」推到 `vt-github.branch`（缺省 main）；管理员定期
     `collect → compact → publish` 把收集内容收编进更新库、折进基线、
     发布到 `kb_branch`（缺省 kb-repo）分支；各机「更新」从收集分支拉取，
     新装/学习库缺失自动采用远程版——普通用户无感；
   - **局域网共享盘**：把 `<root>` 放共享路径，客户端设
     `VT_SYNC_ROOT=\\server\kb\`，工具箱自动叠加启用条目级增量通道
     （learn 实时上传到各自收件箱 inbox/<client_id>/，只新建不改写）；
   - **局域网 HTTP 镜像**：管理员机 `kb_admin.exe serve --port 8123`
     只读分发更新库供 pull。

3. 验证：`kb_admin.exe status` 显示基线 seq=1、维护者 ['system']；
   `kb_admin.exe collect` 能从收集分支收编学习库 confirmed 候选进
   `inbox\collect\`（幂等，重复跑不产生重复条目）。

## 二、日常运维

```
kb_admin.exe status                     # 盘点：基线/增量/生效/冲突/可回收
kb_admin.exe collect                    # 收编 GitHub 收集分支（工具箱自动上传处）
kb_admin.exe compact                    # 折叠全部增量进新基线（seq+1）
kb_admin.exe prune --days 30            # 过期清理预览（dry-run）
kb_admin.exe prune --days 30 --apply    # 执行回收（只移不删）
kb_admin.exe cycle --collect --days 30 --apply --publish
                                        # collect→compact→prune→publish 一条链
kb_admin.exe maintainers list           # 维护者名单（信任分级依据）
kb_admin.exe schedule                   # 打印定期维护计划任务命令（不自动注册）
```

### collect 做什么（新增，v1.12.2）
从内置 yaml 的 `collect_branch`（缺省 main）拉 `vt-github.files`：
- `.json`（学习库）→ confirmed、非冲突候选转成增量条目写入
  `inbox\<author>\*-collect.jsonl`（`--author` 可改署名，缺省 collect）；
  按条目 id 与基线+全部增量幂等去重，重复执行不翻倍；
- `.py`（校准脚本）→ 存 `<root>\collect\` 作为对照快照，供 compact 用
  `--script` 指向最新版折叠内置表增长。

### compact 做什么
1. 重新合并（基线 ∪ 全部 inbox 增量，含 collect 收编的条目）；
2. 淘汰（只从通道移除，不物理删除）：`superseded`（被取代）、`tombstone`
   （人工否决）、`promoted`（已固化进脚本内置表）、`conflict`（冲突隔离，
   **不折叠**，留档待人工裁决）；
3. 写新 `baseline.json`（seq 递增），旧基线 + 全部 inbox **只移不删**归档到
   `archive\seq_<N>\`。共享盘模式客户端下次「更新」自动以新基线对齐；
   GitHub 收集模式需 `publish` 发布后各机 pull 镜像生效。

**建议节奏**：增量积压数百条以上，或每次发布新脚本版本（promoted 变多）后。

### prune（过期清理）安全语义
一个超龄（默认 >30 天）inbox 文件，**当且仅当**把它移除后全局生效集
（含冲突隔离）逐字节不变（leave-one-out 判定），才被回收进
`archive\pruned_<时间戳>\` 并生成 `prune_report.json`。未折叠、仍影响他人
的增量永不回收；物理删除永远不存在于 prune。

### 冲突处理
`status` 可见冲突组数。处置：裁决后由权威用户以 `supersedes` 增量覆盖，
或直接改内置表发新版本 → `compact`（promoted 淘汰），冲突组自然退出通道。

## 三、回滚与应急

| 手段 | 效果 |
|------|------|
| 客户端设置页关闭「启用自动同步」 | 停止更新与上传（持久） |
| 客户端 `VT_NO_CALIB_SYNC=1` | 临时强制关闭同步 |
| 客户端 `VT_SYNC_MODE=legacy` | 停用条目级增量镜像（不影响 GitHub 通道） |
| 客户端 `config.json → disabled_keys` | 条目级封禁坏数据（`[["LEARNED_CANDIDATE","bi","词"],...]`） |
| 管理员 `archive\` 回溯 | 任一次 compact / prune 前状态可整包还原（只移不删） |
| 管理员 `init --force` | 灾难重建：由当前脚本内置表重新生成基线（客户端以新基线对齐） |

## 四、目录与日志

```
<更新库 root>\
  ├─ baseline.json          权威基线（seq / meta / entries）
  ├─ inbox\<client_id>\*.jsonl   各客户端增量（只新建，绝不改写他人文件）
  ├─ inbox\collect\*-collect.jsonl  管理员收编的收集分支学习库条目
  ├─ collect\               收集分支脚本快照（对照用）
  └─ archive\seq_<N>\       compact 归档（旧基线 + 旧增量，可回溯）
     archive\pruned_<ts>\   prune 归档 + prune_report.json
客户端本机（工具箱数据目录）：
  data\calib_sync_base.py / calib_sync_kb_base.json   GitHub 三方合并公共祖先快照
  data\calib_sync\config.json     client_id / 水位线 / disabled_keys
  data\calib_sync\applied.json    生效集（增量通道；校准运行时兜底注入）
  data\calib_sync\conflict.json   冲突隔离区（永不自动应用）
  data\calib_sync\pushed_ids.json 已上传台账（增量通道只传没传过的）
  data\calib_sync\local_log\      断网留档（下次自动补传）
  logs\calib_sync.log             同步日志（更新/后台上传/合并/拒绝原因）
```

## 五、命令速查

| 命令 | 用途 |
|------|------|
| `init [--force]` | 生成/重建首版基线 |
| `status [--days N]` | 盘点更新库 |
| `collect [--branch B] [--author A]` | 收编收集分支 → 更新库收件箱（幂等） |
| `compact` | 折叠增量进新基线 + 淘汰 + 归档 |
| `prune [--days N] [--apply]` | 回收超龄无贡献增量（leave-one-out 无损） |
| `archive-prune [--days N] [--delete --force]` | 清理过旧归档（默认移 _cold） |
| `publish / pull` | 更新库 ⇄ GitHub kb_branch 分支 |
| `cycle [--collect] [--apply] [--publish]` | 维护一条链（可挂计划任务） |
| `maintainers list/add/remove` | 维护者名单 |
| `serve [--port 8123]` | 局域网 HTTP 镜像 |
| `schedule` | 打印定期维护计划任务命令（需自行确认执行） |
| `selftest` | 隔离环境端到端断言（不联网） |
| （工具箱内部）`kb-sync` / `kb-push` | 条目级增量通道的两个子命令 |
