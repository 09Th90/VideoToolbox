## 一、项目概述

**视频工具箱**（VideoToolbox）是一个 Windows 桌面视频工具集，基于 PyQt5 + PyQt-Fluent-Widgets 构建，主要能力：

- **视频下载（含音画合并）**：调用 yt-dlp / ffmpeg 下载 YouTube、B 站等站点视频，自动检测画质、下载字幕、打包独立文件夹（视频 + 1280x720 封面 + 信息 txt + srt）；页内分段「音画合并」按文件名与时长自动配对 mp4 + m4a/weba + srt/ass 并合成（v1.13.0 起并入本页）；该子板块内再分「自动配对 / 手动合并」两个子页——手动合并允许用户把任意视频/音频（+ 可选 srt/ass 字幕）拖入直接合成，音频编码由 `probe_audio_codec()` 实测决定 copy 或转 AAC，视频 copy 失败自动以 `merge_pair(reencode_video=True)` 重编码回退（v1.18.0）；
- **视频库**：本地视频扫描，缩略图卡片浏览与播放；
- **字幕处理（含字幕校准）**：内嵌开源字幕引擎 VideoCaptioner v1.4.2（GPL-3.0）提供转录 / 优化 / 翻译 / 配音 / 合成（工作台分段项「字幕优化与翻译」v1.13.0 起更名「字幕翻译」）；页内分段「字幕校准」调用自研术语库脚本 `subtitle_calib_merged.py` 做名词级原位校准，可选 **AI 校准（Agent 级）**，由大模型逐块复校残留错形（`src\calib_ai_agent.py`）；
- **字幕编辑（打轴）**：程序内播放视频 + 波形时间轴 + 字幕表，边看边调字幕起止时间（`src\subtitle_editor_core.py` / `subtitle_editor_media.py` / `subtitle_editor.py`）；v1.14.0 起支持**字幕内嵌**（把当前字幕挂成 mov_text 独立轨道、流复制不重编码，`src\subtitle_compose.py`）与**画面字幕层**（透明顶层窗口实时预览字幕样式，`src\subtitle_overlay.py`）；播放组件为 **LGPL** 构建的 libmpv，按需运行时下载，不随包分发；
- **全流程流水线（v1.14.0 新增）**：链接任务（粘贴链接 → 下载 → 翻译 → 校准 → AI 二次校准 → 成品输出）与目录任务（监视目录 → 下载完成判定 → 可选智能合并 → 同一条链）两种任务链，事件驱动阶段状态机、单并发 FIFO、断点幂等（`src\pipeline.py` + `media_registry.py`，状态文件 `data\pipeline_state.json`，在「流水线」页可视化）；成品不另建「成品」目录，直接增量写回下载时生成的原视频文件夹，字幕按「字幕翻译」输出格式（`【字幕】名-谷歌翻译.srt`、译文在上）；
- **界面主题体系（v1.14.0 新增）**：深色 / 浅色 / 跟随系统三档 + 8 预设主题色 + 背景模糊与每导航板块自定义背景图，全局 QSS / 卡片 / 遮罩全部跟随（`src\ui_theme.py`，配置 `data\ui_custom.json`）；
- **全局 AI（单通道）**：一套 OpenAI 兼容地址 / 密钥 / 模型，供工具箱、字幕引擎优化翻译、AI 校准共用；另可单独配置 **ASR 语音识别**（自有服务或本地独立模型）；
- **校准知识同步**：两套并存 —— 引擎侧 GitHub 文件级并集同步（启动拉取 / 退出推送），以及脚本侧 v1.11.0 起的**条目级增量日志通道**（哑远端 + 收件箱，管理员用 `kb_admin.py` 运维）。

技术栈：Python 3.12（内嵌运行时）、PyQt5、qfluentwidgets、yt-dlp、ffmpeg、VideoCaptioner、Qt Installer Framework / Inno Setup（打包）。

### 4.2 `deploy_installer_ghpages.py`（⚠ v1.18.0 起已被取代，仅作历史保留）

- **用途**：把 `installer_repository\`（在线安装器组件仓库）部署到 GitHub 仓库 `09Th90/VideoToolbox` 的 `gh-pages` 分支并启用 GitHub Pages，供在线安装器远程拉取组件。
- **使用说明**（命令）：
  ```bat
  python packaging\deploy_installer_ghpages.py --check-size   :: 只量体积，检查 100 MiB 硬限
  python packaging\deploy_installer_ghpages.py                :: 默认 git 通道发布
  python packaging\deploy_installer_ghpages.py --dry-run      :: 只镜像不推
  ```
  只有 `--mode api` 才需要先 `gh auth login`（token 已改为惰性获取，git 通道不需要）。
- **可选环境变量**：`VT_REPO_DIR` —— 仓库根目录覆盖（脚本被复制到其它位置运行时用）。
- **⚠️ 两种通道（2026-10-08 起默认 git）**：
  - `--mode git`（默认）：把 `installer_repository\` 镜像到 `build\ghpages_push\`，作为**独立 git 仓库** `git push --force origin HEAD:gh-pages`。走 pack 协议，只要**单文件** ≤100 MiB 就能推（实测 103MB 约 36s）。
  - `--mode api`：GitHub Git Data API 逐 blob 上传。**对当前体积已不可用**——98 MiB 的 `content.7z` 经 base64 后 >130MB，GitHub 回 `422 Sorry, your input was too large`（urllib 与 curl 通道均失败）。保留仅为小体积仓库与历史参考。
- **⚠️⚠️ 目录层级必须与安装器内嵌 URL 对齐（2026-10-08 事故根因）**：安装器 `config.xml` 写的是 `https://09th90.github.io/VideoToolbox/`，IFW 会在其后拼 `Updates.xml`，所以仓库内容**必须放在 gh-pages 分支根**。历史上曾把整个 `installer_repository\` 目录（连目录名）推上去，实际路径成了 `.../VideoToolbox/installer_repository/Updates.xml`，而安装器去取 `.../VideoToolbox/Updates.xml` 得 **404** ⇒ 向导 Welcome 页红字 **`Cannot retrieve remote tree`**。**别把仓库目录名带进 gh-pages。**
- **⚠️⚠️ GitHub 单文件硬限 100 MiB**：主程序 exe 是 PyInstaller onefile（内部已压缩）⇒ 7z 只能再压 0.06%，故 `content.7z` ≈ exe 体积。v1.18.0 的 exe 因引入 onnxruntime 涨到 106.3MB ⇒ `content.7z` 101.3 MiB **越线，push 必被拒**；靠从 exe 里剔掉 **8.2MB 无人引用的 QML 运行时**（`Qt5Qml.dll` / `Qt5Quick.dll` / `Qt5QmlModels.dll`，见 `packaging\视频工具箱.spec` 的 `_DROP_BINARIES` 长注释）才压回 **98.24 MiB，余量仅 1.76 MiB**。**每次发布前先跑 `--check-size`**。这层墙是结构性的：exe 再涨 2MB 就会再次越线，真要治本得改挂 **GitHub Releases**（单 asset 上限 2GB）。
- **备注**：完成后在线仓库地址为 `https://09th90.github.io/VideoToolbox/`（部署后拉 `Updates.xml` 核对 `<Version>`；⚠ GitHub Pages CDN 生效需 **30~60s**，刚推完就探测会看到旧的 404）。

### 4.4 `subtitle_calib_merged.py`

- **用途**：字幕校准统一脚本（唯一入口）。对 SRT 做**名词级术语原位校准**：只替换中文行术语，严格保留序号、时间轴、空行、换行（CRLF/LF）与 BOM 一字不变。由「字幕处理」页工作台「字幕校准」分段以 `tools\python` 子进程调用，也可命令行直接使用。
- **使用说明**：
  ```bat
  :: A. 术语校准（按片源模式）
  python subtitle_calib_merged.py <输入.srt> [--out 输出.srt] [--report 对照.md]
       [--bi|--ja|--jpe|--ko|--ak|--akko|--endo|--zho|--pgr|--pgren|--wwoc|--react]
       [--fix-en] [--kb 学习库.json]
  :: 不传 --out 只做术语命中统计，不改写文件；默认输出「原名.calib.srt」，绝不覆盖原字幕

  :: B. 流水线子命令
  python subtitle_calib_merged.py extract   <源.srt> <cues.tsv>          :: 抽 cue 表
  python subtitle_calib_merged.py split     <cues.tsv> <前缀> --n 6      :: 切分段并行校准
  python subtitle_calib_merged.py merge     <源.srt> <表|目录> --out 输出.srt [--compare 对照.tsv] [--side 覆盖.tsv]
  python subtitle_calib_merged.py verify    <源.srt> <输出.srt>          :: 校验结构零改动
  python subtitle_calib_merged.py compare   <源.srt> <输出.srt> <对照.tsv>
  python subtitle_calib_merged.py scan      <cues.tsv> [--min 2]         :: 扫描高频英文词
  python subtitle_calib_merged.py subfix    <源.srt> <fix.tsv> --out 输出.srt
  python subtitle_calib_merged.py terms-check [表名...]                  :: 术语表二次命中自查

  :: C. 对象级知识库（ENTITIES + 学习系统）
  python subtitle_calib_merged.py kb-export [--json] [--out 路径]        :: 导出知识库
  python subtitle_calib_merged.py kb-lookup <词>                         :: 反查实体全部知识
  python subtitle_calib_merged.py kb-lint                                :: 对象级体检
  python subtitle_calib_merged.py learn <原始.srt> <人工校准.srt> [--mode bi]
  python subtitle_calib_merged.py learned-show / learned-promote / learned-reject

  :: D. 条目级增量同步通道（v1.11.0；默认，详见 docs\校准知识增量同步_管理员手册.md）
  python subtitle_calib_merged.py kb-baseline-init   :: 管理员：由内置知识生成首版 baseline
  python subtitle_calib_merged.py kb-sync            :: 拉取+合并+三道门+应用（校准入口自动执行，幂等）
  python subtitle_calib_merged.py kb-push            :: 导出/上传本次增量（learn 收尾自动调用）
  python subtitle_calib_merged.py kb-compact         :: 管理员压缩：折叠增量进新 baseline
  python subtitle_calib_merged.py sync-status        :: 本机状态：client_id / 水位线 / 生效 / 冲突 / 日志
  ```

- **内部结构**：`BILINGUAL_TERMS`（中英双语专名表）、`CONTEXT_MAP`（上下文佐证规则）、`WORD_MAP`（机翻错词）、`KO_TERMS / JA_TERMS / JA_ENDFIELD_TERMS / ENDFIELD_TERMS / AK_TERMS / PGR_EN_TERMS / ZH_ONLY_TERMS` 等按模式分离的术语表，以及对象级 `ENTITIES` 知识层与第 8 节增量同步实现；新对照统一以 `Entity` 追加进第 6 节，勿另建平行脚本。

### 4.9 `文件版本清单.md`（v1.12.1 新增，自动生成）

- **用途**：**逐条核验「线上文件 = 当前版本代码」的清单**。由 `src\stamp_versions.py` 自动生成，列出仓库内**全部已跟踪文件**（当前 **132 个**，清单自身不计入；分类计数：当前版本 69 / 第三方合规原件 17 / 历史归档 39 / 运行期数据占位 7）的：归类、`@version` 标记状态、git blob SHA-1、字节数。
- **四类归类**：**当前版本**（构成当前版本的自研代码 / 脚本 / 配置 / 文档）、**第三方 / 合规原件**（上游或法律原件，逐字节保持原样）、**历史归档**（`history\` 与早期版本留档）、**运行期数据 / 占位**。
- **SHA-1 口径（关键坑）**：清单列的是 **git blob SHA-1**（对 `blob <长度>\0<内容>` 计算，并经 git filters 归一化——`core.autocrlf=true` 下 CRLF 已转 LF），**与 GitHub tree API 的 blob `sha` 同口径**，可直接逐条比对。**普通文件 SHA-1（`sha1sum` 那种）与此不相等**，拿它去比会全部对不上（v1.12.1 写清单时踩过）。
- **怎么用**：拿 GitHub 上某文件的 blob `sha` 与本清单同名条目比对，一致即证明内容完全相同——**同名不同内容**（本地已改未推、线上仍旧版）这种肉眼查不出的问题，靠它一查就现。也可 `grep -rn "@version" .` 直接看每个文件属于哪一版。
- **使用说明**：不要手工编辑（会被下次生成覆盖）；版本升级时由 `apply_version.py` 自动重生成，也可单独跑 `cd src && python stamp_versions.py`。
- **备注**：清单自身不计入统计。`.vscode\extensions.json`（JSON 无注释语法）与 `docs\界面预览.png`（二进制）无法打标，但在清单里标注为「未打标：…」，不会漏掉。

### 4.10 `packaging\online_release\` —— 自研在线引导安装器（v1.18.0 新增）

- **用途**：取代 Qt IFW 的在线安装器。把「下载并覆盖安装目录」这件事自己做，从而不再受
  IFW 的**目录层级**要求与 gh-pages 的**单文件 100 MiB** 限制。
- **为什么必须换**（2026-10-08 实测，三条都验过）：
  1. IFW 取归档的 URL 是 `<仓库基址>/<组件名>/<归档名>`，**天然多一层目录**；而 GitHub Releases
     的资产是**平铺**的 ⇒ `.../releases/download/<tag>/<组件名>/<归档>` 实测 **404**；
  2. 「用带斜杠的 tag 冒充目录」单测可行（`.../download/X/comp/asset` → 200），但 `<X>` 与
     `<X>/comp` 在 git 里是 **D/F 冲突**（先建 `refs/tags/dfprobe/child` 成功、再建
     `refs/tags/dfprobe` → **HTTP 500**），而 IFW 恰好同时需要这两层；
  3. 能承载目录结构的 gh-pages 走 git，**单文件硬限 100 MiB** —— 主程序 exe 已 103MB，
     `content.7z` 实测 101.3 MiB，`git push` 必被拒；exe 是 PyInstaller onefile（内部已压缩），
     7z 只能再压 0.06%，换压缩级别救不回来。
- **组成**：
  - `build_online_release.py` —— 打包侧：按组件打 **zip**、生成 `manifest.json`、上传为
    Release 的**平铺资产**。固定 tag（默认 `repo-latest`）原地更新，资产名带版本号可累积。
    启动时会 import `installer_src\build_online_installer.py` 的 `COMPONENTS` 做**同源比对**，
    两边清单不一致直接报错（防漂移）。
  - `vt_update_core.py` —— 纯逻辑，**只用标准库**：清单解析（支持 http(s) / 本地路径 / `file://`，
    后者供离线自测）、sha256、下载（先写 `.part` 再改名，中断不留半成品）、zip 解压
    （含 **zip-slip 路径穿越防护**）、安装目录探测（读 Inno 写的注册表 `InstallLocation`）、
    空间检查、快捷方式、总流程。
  - `vt_online_setup.py` —— tkinter 界面（版本信息 / 目录选择 / 进度 / 日志），
    CLI 支持 `--manifest` `--dir` `--base-url` `--silent` `--no-shortcuts`。
  - `vt_online_setup.spec` —— PyInstaller 单文件配置，`excludes` 掉 PyQt5/numpy/onnxruntime 等。
- **产物**：`installer\视频工具箱_在线安装_v<版本>.exe`，**11.4MB**（IFW 版 33.3MB）。
- **发布**：
  ```bat
  python packaging\online_release\build_online_release.py --dry-run   :: 只打包+出清单
  python packaging\online_release\build_online_release.py             :: 打包并上传
  ```
  ⚠ 本机对 `uploads.github.com` 的**大文件**上传会偶发 TLS 中断
  （`EOF occurred in violation of protocol (_ssl.c:2427)`）——几字节的探测上传从不失败，
  99MB 实测会断。脚本已带「urllib 重试 + curl 兜底」两级通道。
- **自检**：`scripts\dev\_selftest_online_setup.py`（离线 38 项，含 zip-slip 防护、
  sha256 不符中止、缓存命中不重下、清单坏值拒绝）。真机端到端：以默认线上 manifest
  跑 `--silent` 安装，50/50 文件与 `dist\` 逐字节一致，装完的 exe 自检 PASS。

### 4.11 在线更新包的资产约定（schema=1）

  ```python
  merged, added, conflicts = core.merge_calib_script(local, remote, base)
  ```

### 5.4 `calib_ai_agent.py` —— AI 校准 Agent（v1.11.0 新增）

- **用途**：Agent 级字幕校准（无界面、无第三方依赖）。把「基于脚本 subtitle_calib_merged 校准字幕，不允许改变时间轴和格式，仅调整文字内容，一次读不完就自行拆分，最后合并」这套要求实现成可复用的流水线，供界面（`engine.calib_ai_run`）、命令行与自检脚本共用。
- **使用说明**（作为库引用）：
  ```python
  import calib_ai_agent as agent
  res = agent.calibrate(src, out="x.calib.srt", report="x.calib.md",
                        mode_flag="--ko", log=print, chat=my_chat, round_no=1)
  ```
  `chat(prompt, system=None, max_tokens=...) -> str` 由调用方注入（引擎走全局 AI 单通道）。
- **八步流程**：① 术语脚本基线（机械部分兜底）→ ② `extract` 抽取 cue 表（剥离时间轴）→ ③ `kb-export --json` 载入知识库并展开成「错形 → 官方名」规则 → ④ 自行分块（条数 + 字符预算双约束）→ ⑤ 逐块 LLM 复校（返回截断/超时自动拆半重试）→ ⑥ 证据校验（改动必须能被知识库解释；行数变化、整句改写、无依据改动一律拒绝并写报告）→ ⑦ 按 cue 边界合并回填（只替换中文行，序号/时间轴/参考行/换行/BOM 一字不动）→ ⑧ 独立校验（调脚本 `verify` 断言结构全一致，不通过即判失败）。
- **再次校准**：`round_no > 1` 时以本轮输出为输入再跑一轮，提示词要求只挑残留错形；界面按 `原名.calib.rN.srt` 命名。
- **v1.15.0 优化**：`concurrency` 逐块 LLM 受控并发（默认 1＝串行，只并发「取回模型提议」一步，证据校验/合并仍串行）；`select_rules_for_chunk` 块级规则裁剪（hot=本块中文行命中、warm=本块参考行命中，只裁提示词规模不改采纳）；内置 JSON 抢救 `_repair_json`（逐条抢救 + 轻度修补，不再依赖可选库 json_repair）；重试带反馈（invalid/truncated 的失败原因与整改要求写进重问提示词）；`_unesc` 与 `_esc` 对称（ckpt 断点续跑含反斜杠文本的转义修复）；`_protect_ref_lines` 参考行保护（基线跑完按 cue 序号把参考行还原成 src 原样，`--endo` 等「统一全部文本行」模式不再污染英文行）。
- **v1.16.1 新增（思考轮次 + Agent 集群）**：
  - `think_rounds`：每块「思考 → 联网查证 → 再思考」的往返轮数上限。**0＝关闭（不限）**，内部以 `HARD_MAX_THINK_ROUNDS=32` 兜底防死循环；旧行为等价于 1。截断重问的输出加倍上限同步提到 1M，且**绝不低于**用户配置值（旧 512K 硬顶会把配了 1M 的用户反向打回）。

### 5.7 `push_via_git_api.py` —— GitHub 不可达时的推送通道（v1.12.0 新增）

- **用途**：本机 `git push`（走 github.com）直连与内置代理均不通，而 `api.github.com` 直连可用；本脚本用 **GitHub Git Data API** 把当前本地 HEAD 的完整文件树同步到远端分支，等价于一次 `git push`（内容级一致，不搬运 git 历史对象）。
- **使用说明**：
  ```bat
  cd src
  python push_via_git_api.py --dry-run     :: 只报告差异（必跑，先看差异集）
  python push_via_git_api.py               :: 真推送
  ```
- **流程**：取远端 `ref/heads/<branch>` → commit → tree(recursive) ↔ 本地 `git ls-tree -r HEAD` 逐文件比对 → 只上传差异 blob（`git cat-file blob <sha>` 取规范化字节 → base64）→ 建 tree（远端有而本地无的条目用 `sha:null` 删除）→ 建 commit（parent=远端 head）→ `PATCH /git/refs/heads/<branch>`（`force:false`，非快进即失败，绝不覆盖他人提交）。
- **三个必须记住的点**：① **所有 git 调用加 `-c core.quotepath=false`**，否则中文路径被转义成 `\344\275...`，与 API 返回的真实路径对不上会把远端中文文件全判为「待删除」；② **必须强制直连**（`build_opener(ProxyHandler({}))`），urllib 默认会走沙箱/系统代理并被 502 拦下；③ 先 `--dry-run` 再推。

### 5.12 `stamp_versions.py` —— 文件级版本标记与核验清单（v1.12.1 新增）

- **解决什么问题**：光看文件名无法判断一份文件属于哪一版——「本地已改未推送」「线上还是旧版」这两种情况，文件名完全一样，肉眼查不出来（v1.12.1 发布前实测就踩到：线上 `main` 有 9 个文件与本地同名而内容不同）。
- **用途**（两件事）：
  1. **首行打标**：给每个**自研当前版本文件**的首行插入统一标记行 `@version <版本>`，按文件类型套用该类型的注释语法（`.py/.spec/.ps1`→`# `、`.iss`→`; `、`.qs`→`// `、`.xml/.md/.html`→`<!-- -->`、`.bat`→`rem `、`.txt`→裸行）。插入位置会自动避让 `#!` shebang、`# -*- coding` 编码声明、XML 声明与 `@echo off`，保证不破坏语义。再次运行时按新版本号**原地改写**，幂等。
  2. **生成清单**：生成根目录 `文件版本清单.md`，逐条列出**全部已跟踪文件**的归类、`@version` 标记状态、**git blob SHA-1** 与字节数，用于与 GitHub 上的同名文件逐条比对（blob SHA 一致即内容相同，口径见 4.9）。
- **使用说明**：
  ```bat
  cd src
  python stamp_versions.py            :: 打标 + 重生成《文件版本清单》
  python stamp_versions.py --check    :: 只报告会改哪些文件（空跑）
  ```
- **刻意不打标的文件**（改动它们有害，不是遗漏）：

### 5.13 `subtitle_editor_core.py` —— 字幕编辑数据层（新增）

- **用途**：字幕编辑页的**纯逻辑层**（不依赖 Qt、不依赖第三方库），可单独测试与复用：`Cue`（起止为 int 毫秒）、`SubtitleDoc`（条目文档 + 编解码 + 原样回写）、`UndoStack`（快照式撤销栈，`depth=100`），以及一组纯函数编辑算子。
- **使用说明**（作为库引用）：
  ```python
  import subtitle_editor_core as secore
  doc = secore.SubtitleDoc()
  n, skipped = doc.load_bytes(raw, path)          # decode_any：utf-8-sig→utf-8→gb18030→big5→shift_jis→latin-1
  secore.split_cue(doc.cues, idx, at_ms)          # 切分（过短会返回 False，由调用方回滚）
  secore.merge_cues(doc.cues, rows)               # 合并多选
  secore.set_boundary(doc.cues, idx, "start", ms) # 取起点 / 取终点
  secore.shift_cues(doc.cues, rows, -100)         # 平移选中（另有 shift_all 整轨平移）
  secore.fix_overlaps(doc.cues); secore.clamp_zero_length(doc.cues); secore.renumber(doc.cues)
  doc.save_file(path)                             # 换行与 BOM 按源文件原样保留
  ```
- **关键约定**：**时间一律 int 毫秒**；`ms_to_clock` / `clock_to_ms` 负责与 `时:分:秒.毫秒` 互转（解析失败返回 `None`，界面据此还原原值）；`MIN_DURATION_MS = 40`（25fps 一帧）为条目最短时长，任何会把它压得更短的操作一律拒绝；`stats()` 给出条数 / 字数 / 重叠数 / 过短数，供状态栏与体检使用。
- **撤销语义**：`UndoStack.push(cues, label="", snapshot=None)` 的 `snapshot` 参数专供「拖动改时间」——拖动开始时先 `doc.snapshot()` 存下拖动前的整档，真正移动时才压栈，因此撤销能精确回到拖动前，而不是回到「拖了一下之后」。`snapshot()` / `restore()` 即基于此。
- **备注**：`decode_any` 是编解码守门函数（GBK 片源全靠它），重构时勿删；写出统一 UTF-8，换行（CRLF/LF）与 BOM 保持原样。

### 5.14 `subtitle_editor_media.py` —— 字幕编辑媒体层（新增）

- **用途**：播放与波形两件事的实现层，对上只暴露信号与几个方法，不碰界面。
  - `load_mpv(mpv_dir)`：**先注入 `PATH`**（`tools\mpv`）再 `import mpv`，返回 `(module, error)`；
  - `MpvPlayer(QObject)`：`attach(widget)` 内嵌播放窗口（`MPV(wid=str(hwnd))`），信号 `position_changed / duration_changed / playing_changed / loaded`，方法 `load / play / pause / toggle_play / set_speed / seek_ms / nudge_ms / step_frame / terminate`，属性 `position_ms / duration_ms / fps / available / error`；
  - `extract_peaks(ffmpeg, path, peaks_per_sec=200, on_progress, should_stop)`：ffmpeg 解 **16kHz 单声道 s16le** 后按窗口取峰值；

  ```python
  from subtitle_editor_media import MpvPlayer, WaveformCache
  player = MpvPlayer(os.path.join(engine.TOOLS_DIR, "mpv"))
  player.attach(video_host)          # 必须在窗口 show() 之后，否则句柄绑到会被销毁的原生窗口

  ...

  ```
- **关键约定**：**`import mpv` 之前必须先把 `tools\mpv` 放进 `PATH`**；`attach()` 不可提前（页面构造时主窗口还没 `show()`，此时拿到 winId 会绑到随后销毁的原生窗口上，表现为「有声音没画面」）；**退出必须 `terminate()`**——onefile 打包版不释放 libmpv 会在退出后留下删不掉的 `_MEI***` 临时目录（v1.12.0 踩过）；mpv 的 `time-pos` 有精度漂移，故对外一律换算成 int 毫秒；`seek_ms` 用 `absolute+exact` 做帧对齐，`step_frame` 精确到 0.0400s@25fps。
- **备注**：libmpv 必须是 **LGPL** 构建（GPL 版不可接受），且**不进安装包**——由 `tools\download_open_source_deps.py --only mpv` 运行时拉取（约 40MB，带 sha256 校验 + 手动 URL 兜底）；缺失时本页只提示、不崩。

### 5.17 `pipeline.py` —— 全流程流水线状态机（v1.14.0 新增）

- **用途**：事件驱动的阶段状态机，把「下载 → 翻译 → 校准 → AI 二次校准 → 成品输出」串成自动链。两种任务链（`Job.kind` / `chain`）：**链接任务**（界面填链接 `add_link`）= download→translate→calib1→calib2→package；**目录任务** = download（文件出现）→merge（可选）→translate→calib1→calib2→package。旧 state 里的 calib 阶段自动迁移为 calib1。
- **关键语义**：单并发 FIFO；阶段状态 WAITING / READY / RUNNING / DONE / FAILED / SKIPPED；状态文件 `data\pipeline_state.json` 原子写，**重启后 DONE 跳过、RUNNING 归位 READY**（断点续跑）；失败隔离到当前 job（一个 job 失败不拖垮队列）；产物复用带输入指纹 `<out>.src.json`（输入没变就不重跑）；`ignite_existing=False`——存量文件不自动点火；`Pipeline.close()` 后禁 emit。

- **阶段要点**：下载（链接）走 `_download_link_run`，**全复用 engine 原语**（`fetch_info_json` / `parse_qualities` / `output_template` / `normalize_rolling_srt` / `write_info_txt` / `make_cover`），最高画质，412 重试退避；翻译走谷歌 gtx 端点（批量 1200 字符 / 40 行，行数不齐逐行兜底，代理走 `ytdlp_proxy_args`），产物**双语**，中文占比 >0.3 判已翻译 → SKIPPED；校准 CALIB1 = 纯脚本基线，CALIB2 = `engine.calib_ai_run(resume_from=calib1 产物, round_no=2)`（与校准页「再次校准」同入口），AI 未启用 → SKIPPED；配对只走 `engine.smart_pair()`（`find_pairs` 返回 4 元组取 `[0]`）。写 srt 一律先 `_normalize_nl` 归一坏换行（修复 v1.14~v1.17 文本自带 `\r\n` 经 `write_text_utf8` 二次翻译成 `\r\r\n`、每行间多空行的老毛病）。
- **使用说明**：界面在「流水线」页查看状态；配置开关 `data\config.json` 的 `pipeline_auto` / `pipeline_ai_calib`；`VT_NO_PIPELINE=1` 完全关闭。

### 5.23 `check_names.py` —— 未定义全局名静态体检（2026-09-14 引入）

- **用途**：找出「引用了但整个模块里没有定义」的全局名字。
- **为什么需要**：PyQt5 里**槽函数 / 回调中抛出的未捕获异常默认会让进程直接 abort**，表现就是「点一下按钮程序突然没了」。这类异常最常见的原因是写错或漏定义了一个全局常量 / 函数（例如 `duration=INFOBAR_DURATION_SUCCESS` 而该常量从未定义）——`python -m py_compile` 查不出来（语法没错），只有真的点到那行才炸。v1.12.2 修的「开始校准一点即崩」（误引用设置页控件）就是同一类问题。
- **使用说明**（命令）：
  ```bat
  python src\check_names.py                    :: 扫描本目录下所有 .py
  python src\check_names.py video_toolbox_qt.py
  python src\check_names.py -q                 :: 只输出汇总
  ```
  退出码：`0` = 干净，`1` = 发现问题（可直接接进自检 / CI）。
- **原理**：用标准库 `symtable` 做**作用域级**静态分析，无第三方依赖——在函数 / 类作用域里以「全局」身份被引用、但模块顶层既没定义也没有 import、且不是内置名的标识符，一律报出。
- **备注**：属于**维护者工具，不随安装包分发**。入库于提交 `20e0a2b`（2026-09-14，与 inbox/outbox 目录同批），此前一直未在本说明书中建档，v1.15.7 整理时补入。

### 5.28 `speaker_voiceprint.py` —— 主播声纹筛选（v1.18.0 新增）

- **用途**：把「只出主播的字幕」做成本地**后处理**——`音频/视频 + 带 [说话人N] 标注的 SRT → 只保留主播的 SRT`。
- **为什么必须本地做**：服务端 ASR 只回 `[说话人N]` 标签，**既不给声纹向量、也不回传音频片段**，无法在云端判定「谁是主播」。故用本地声纹模型把每个说话人簇的音频提成向量，与用户录入的主播模板算余弦相似度。
- **依赖**：只需**已随包**的 `onnxruntime` + `numpy`。特征提取是**纯 numpy 实现的 kaldi 兼容 fbank**（`povey` 窗、`snip_edges=False`、`high_freq=-400`→7600Hz、`use_energy=False`），**不引入任何新的第三方包**（无 torch / librosa / kaldi-native-fbank）。
- **⚠ 打包口径（v1.18.0 已拍板：打进包）**：`packaging\视频工具箱.spec` 里 `hiddenimports += ['onnxruntime']` + `collect_dynamic_libs('onnxruntime')`，并**必须同时把它从 `excludes` 里摘掉**——`excludes` 优先级高于 `hiddenimports`，只加不摘等于白声明（exe 里照样没有）。代价约 +40MB（主要是 18MB 的 `onnxruntime.dll`）。声纹**模型** 27MB 仍按需下载、不进包。
- **关键内容**：
  - `fbank()`：kaldi 兼容 80 维 log-mel；与 `kaldi-native-fbank` 逐元素比对，高能量帧 `max|Δ| < 1e-3`，最终 embedding 余弦 > 0.999；
  - `normalize_peak()`：**峰值归一化（不可省）**——log 前的 `max(·,eps)` 截断会破坏「减全局均值」的增益不变性，实测不归一化时增益降到 0.1 同段自比掉到 0.977，归一化后各增益恒为 1.0000；
  - `VoiceprintEncoder`：onnxruntime 会话（惰性、可复用），`embed()` → 192 维 L2 归一化向量；**v1.18.3 起长输入自动分块**（`EMBED_MAX_FRAMES=6000` ⇒ 60 秒/块，各块子向量取均值后再归一化；全局均值仍在分块**前**对整段减，否则每块直流偏置不同会与单跑产生系统性偏差）。为什么要分块：单次推理内存随输入时长**线性**增长（≈2.2MB/秒），而簇打分把同一说话人全部 cue 拼接后**一次**推理，长片素材直接 `bad allocation`（实测 647 秒峰值 **1.5GB → 0.34GB 封顶**；240 秒分块与单跑余弦 **0.99987**、对模板得分偏差 **0.00025**）；
  - `read_pcm()`：走 `tools\ffmpeg.exe` 一次性解码成 16k 单声道 float32（**整段解码后按时间轴切片**，比逐条 cue 各调一次 ffmpeg 快得多）；
  - `enroll()` / `save_template()` / `load_template()` / `list_templates()`：模板落 `data\voiceprint\<名>.json`（192 个浮点，便于人工查看）；
  - `score_by_speaker()`（**推荐**，先按 `[说话人N]` 聚簇、簇内音频拼接后算**一个**向量再比对——短 cue 单独提向量极不稳）/ `score_by_cue()`（无标注时兜底）；
  - `decide()`：三分支 `keep`（≥ threshold）/ `drop`（< low）/ `review`（存疑区，**默认保留并标记**，交人工复核；分数为 NaN 时也走 review，保守不误杀）；
  - `filter_srt()`：端到端筛选，并在产物旁写 `*_报告.txt`（各说话人得分 + 被丢弃条目）。
- **命令行**（可脱离界面验证）：
  ```bat
  python src\speaker_voiceprint.py enroll --src 视频.mp4 --start 12 --dur 20 --name 主播
  python src\speaker_voiceprint.py score  --src 视频.mp4 --srt 字幕.srt --name 主播
  python src\speaker_voiceprint.py filter --src 视频.mp4 --srt 字幕.srt --name 主播 --out 主播.srt
  ```
- **阈值**：`DEFAULT_THRESHOLD=0.55` / `DEFAULT_LOW=0.45`。依据是 3 位说话人 14 条样本的实测：同人余弦 min 0.681 / mean 0.784，异人 max 0.450 / mean 0.174。
  - 决策边界取 同人 min 与异人 max 的中点 ≈ 0.566，**向上取整到 0.55**；
  - 存疑区下界取**异人实测上限 0.450**——低于它基本可断定「不是主播」，不必再留宽。
- **⚠⚠ 阈值踩坑（2026-10-09，别再拍宽）**：初版取 0.5 / 0.35（凭感觉留宽）。真实素材里「游戏官方中文旁白」聚成一簇、相似度 **0.390**，正好落进 `[0.35, 0.55)` 存疑区被**保留**——用户侧表现是「**依旧多人混合输出**」（164 秒旁白没筛掉）。
  教训：**存疑区要窄且贴着决策边界**，不能一路宽到「看起来还行」。现在 0.390 落在下界之下，会被正确丢弃。自检已钉死两个默认值并加了 0.390 的回归断言。
- **⚠ 已知边界（务必对用户讲清）**：
  1. **重叠说话**（两人同时开口）时切出的是混合信号，相似度会掉、可能误杀主播——彻底解决要声源分离，而 `_asr_separate_audio` 目前**仍是占位接口**，这是最大硬伤；
  2. **主播唱歌**会被判为不像说话声而误杀；纯 BGM 段则会被正确丢弃（BGM 不属于「说话人」，靠声纹不匹配被一并滤掉，不是被「分离」出来）；
  3. **短 cue**（< 0.8s）单独提向量不稳 → 必须走 `score_by_speaker()` 聚簇，或短 cue 跟随同簇邻居；
  4. **换麦 / 混响**会拉低相似度 → 建议多段录入 + 阈值可调。
- **配套**：
  - 界面 `src\speaker_voiceprint_page.py`（见 5.29）；
  - 探针 `scripts\dev\voiceprint_probe.py`——正式用之前先拿真实素材量分离度（按说话人打分 / 无 SRT 滑窗两种模式），给出「建议阈值 + 排序后最大空档」，并判定分离度是「良好 / 偏窄 / 不足」；
  - 自检 `src\_selftest_speaker_voiceprint.py`——离线（不联网、不依赖 ffmpeg），含 fbank 黄金值回归、三分支判定、聚簇打分、`filter_srt` 端到端（注入假编码器 + 假 PCM）、**路径解析回归**（第 9 组）。
- **模型获取**：`model_present()` / `download_model(progress)`。界面上「主播声纹」卡片在模型缺失时显示提示 + **「下载模型」按钮**（后台线程 + 进度条），普通用户不必碰命令行；命令行等价物是 `tools\download_open_source_deps.py --only speaker-model`。
  - 落盘固定为 `MODEL_PATH`（= `TOOLS_DIR\asr_model\`），先写 `.part` 再 `os.replace`，中断不留半截；下完按 `MODEL_SHA256` 校验，不一致即丢弃。
  - **直连失败或太慢都自动切内置 mihomo 代理**。⚠ 速率判据必须**反复抽检**：每收满 2MB 复算一次平均速率，任一次低于 500KB/s 即换代理。实测本机直连 27MB 要 **125~149 秒**（~190KB/s）、代理只要 **8 秒**（~3.3MB/s）；只探一次不够——直连开头有突发，2MB 处看着还行、之后才掉速，只探一次时总耗时仍有 **77 秒**。
- **⚠⚠ 路径解析硬约束**：`TOOLS_DIR` / `DATA_DIR` **必须取自引擎**（`_resolve_dirs()` 优先 `import video_toolbox`），**不要按 `__file__` 推层级**。引擎那套同时处理了源码运行、**打包后**（`sys.frozen` ⇒ `APP_DIR = exe 所在目录`，而非 PyInstaller onefile 的 `_MEIPASS` 临时目录）、以及用户在「设置 → 工具设置 → 数据目录」改过数据根（`data_dir.txt` / `VT_DATA_ROOT`）三种情形。
  按 `__file__` 推在打包后**必错**：onefile 把模块解压到 `%TEMP%\_MEIxxxx`，算出的 tools 就成了 `%TEMP%\tools` —— 用户侧表现是「**声纹模型缺失：C:\Users\…\Temp\tools\asr_model\…**」（v1.18.0 实测踩过，模型与模板双双落到 C 盘临时目录、模板退出即丢）。自检第 9 组用 `_engine_tools_matches()` 把这条钉住。
- **多声纹（v1.18.0 补）**：`_as_template_list()` 统一「单个模板 / 模板名 / 列表」，**并集语义**——一条 cue 与任意一个声纹够像即算主播。启用名单单独落 `data\voiceprint\selection.json`（**刻意不写进 `data\ai_config.json`**：那个文件由设置页 `_collect_ai()` 按 UI 控件整份重写，未进 schema 的键会被静默丢弃）。CLI 增 `list` / `use <名,名>` / `delete`。
- **⚠⚠ 硬约束：onnxruntime 必须在 PyQt5 之前进入进程**。`PyQt5\Qt5\bin` 自带一份 `msvcp140.dll` / `vcruntime140.dll`（实测 **14.26.28720.3**），系统 System32 是 **14.50.35719.0**；`PyQt5.QtCore` 一导入就把 Qt5\bin 加进 DLL 搜索路径，**旧版顶掉新版**，之后加载 onnxruntime 必报
  `ImportError: DLL load failed while importing onnxruntime_pybind11_state: 动态链接库(DLL)初始化例程失败`。
  已在 `src\video_toolbox_qt.py` 的 **PyQt5 导入之前**加 `_fix_msvc_runtime_shadow()`：先把 System32 的同名运行时按名字装进进程（同名已在进程时 Windows 直接复用，开销可忽略），从而挡住 Qt5\bin 的旧副本。
  **将来任何引入 onnxruntime 的功能都受这条约束——别把那段挪到 PyQt5 导入之后，也别在别的入口绕过它。**（另一条可行但更贵的路是「先 import onnxruntime 再导 PyQt5」，实测多付 ~250ms 启动开销。）

### 6.1 `ai_client.py` —— 全局 AI 客户端

- **用途**：全局 AI 客户端（v1.12.0 起为**单通道**——OpenAI 兼容 `/chat/completions`，工具箱标题/语言识别、视觉识别、字幕引擎优化/翻译/拆分、AI 校准全程序共用一套地址/密钥/模型）。另提供 ASR 配置读取与连通性自检。仅依赖 Python 标准库（urllib），无第三方依赖。
- **使用说明**：被 `video_toolbox.py` 以 `ai_mod()` 导入调用；配置持久化在 `data\ai_config.json`。作为库使用：
  ```python
  import sys; sys.path.insert(0, r"tools")
  import ai_client
  print(ai_client.quick_test())               # 连通性自检 (ok, 回复信息)
  print(ai_client.asr_test_connection())      # ASR 配置自检
  print(ai_client.channel_config())           # 归一化配置（地址/密钥/模型）
  ai_client.detect_language("Hello world")    # 语言识别 -> "en"
  ```
- **关键能力**：`channel_config()` / `asr_config()` 提供归一化配置；`_chat_url()` / `_asr_url()` / `_models_url()` 做地址归一化（裸域名、`/v1`、`/chat/completions` 都能填）；`chat_text()` 文本、`chat_vision()` 图片+文本、`detect_language()` 先用本地 Unicode 启发式（假名→ja、谚文→ko、汉字→zh），拉丁语种才调 AI 细分；Azure OpenAI 自动改 `api-key` 头与 `api-version`；智谱 1305 / overloaded / 429 / 5xx 自动退避重试；视觉模型拥堵自动降级到 `vision_fallback_model`；v1.15.0 起 `chat()` 支持 `on_reasoning` 思考链上报回调（取自 `reasoning_content` / thinking 块，回调异常自动吞掉），配置新增 `calib_concurrency`（校准 Agent 逐块并发路数，默认 1，未暴露 UI）。
- **备注**：`set_enabled(False)` 可强制关闭（对应 `--no-ai`），`is_enabled()` 供翻译兜底与引擎 LLM 注入做门禁；`get_client()` / `reset_clients()` 管理客户端单例。**v1.12.0 合并说明**：原接口 A（Anthropic）与接口 B（OpenAI）合并为单通道，`channel` 参数保留仅为兼容（忽略），`calib_channel` 已废弃；旧双通道配置在 `load_config()` 时自动迁移（`base_url` 仍是 Anthropic 地址则用旧 `llm_base_url`/`llm_model` 顶上）。

## 七、installer_src 安装器源码目录

### 7.1 `build_online_installer.py`

- **用途**：构建 Qt Installer Framework（IFW 4.7）**在线安装器**：暂存组件 → repogen 打包 7z 组件仓库 → binarycreator 生成在线安装器 exe。
- **使用说明**（命令）：
  ```bat
  python installer_src\build_online_installer.py                                  :: 全流程
  python installer_src\build_online_installer.py --repo-url http://192.168.1.10:8123/   :: 重写主源（局域网/自建）
  python installer_src\build_online_installer.py --mirror-url https://<镜像>/VideoToolbox/  :: 追加加速镜像源（默认禁用，可重复）
  python installer_src\build_online_installer.py --mirror-url <镜像> --mirror-enabled  :: 镜像默认启用（仍排在官方源之后）
  python installer_src\build_online_installer.py --force-copy                    :: 禁用硬链接
  python installer_src\build_online_installer.py --compression 9                 :: 7z 高压缩
  python installer_src\build_online_installer.py --skip-repo --skip-installer    :: 只暂存组件
  ```
- **仓库源**：config.xml 可声明多个 `<Repository>`，**顺序即下载优先级**（IFW 取第一个可用的源）；生成的安装器里各源可在「设置」页勾选切换。`--repo-url` 只重写主源（第一个 `<Url>`），`--mirror-url` 追加镜像（默认 `Enabled=0`，避免不可达时拖慢安装）；脚本会在打包前打印最终源清单供核对。
- **组件映射**（`COMPONENTS`）：只打包自研内容——主程序 exe、校准脚本、`src`（整目录）、`docs`、`tools\ai_client.py`、`tools\download_open_source_deps.py`；Python / Chromium / ffmpeg 等开源组件**不参与打包**，由安装后运行时下载。⚠️ `github_proxy.yaml` 与 `tools\mihomo\` **严禁收录**（节点凭据，v1.14.1 整改，见 4.3 / 6.6）。
- **前置**：`aqt` 安装 IFW 到 `.buildvenv\qtifw`（镜像：`https://mirrors.aliyun.com/qt/`，命令见脚本报错提示）。
- **产物**：`installer\视频工具箱_在线安装_v1.15.7.exe`（约 32MB） + `installer_repository\`（Updates.xml + 组件 7z）。
- **备注**：在线（IFW）安装形态**不带 `tools\python`**，故其「字幕处理」页会提示改用完整版离线安装包。

### 7.2 `repo_server.py`

- **用途**：本地 / 局域网组件仓库镜像服务器（http.server 实现，零依赖，监听 `0.0.0.0`），服务 `installer_repository\` 目录，供本机与同网段机器安装。
- **使用说明**（命令）：
  ```bat
  python installer_src\repo_server.py           :: 默认端口 8123
  python installer_src\repo_server.py 9000      :: 指定端口
  ```
  启动后打印本机与局域网地址；把 `config.xml` 的 `<Url>` 指向 `http://<局域网IP>:<端口>/`，或直接用安装器的 `--set-temp-repository http://<IP>:<端口>/`（推荐，不改包）。
- **为什么重要**：在线安装器的默认源在 GitHub Pages，国内直连常只有几十 KB/s。走本机/内网源实测 **104MB / 约 1 秒（150 MB/s 级）**，是「自己装 / 同事内网装」的根治手段（配套脚本见 7.7）。
- **前置**：`installer_repository\Updates.xml` 必须存在（先运行 `build_online_installer.py`）。

### 7.3 `config\config.xml`

- **用途**：IFW 在线安装器总配置：安装名「视频工具箱 v1.12.0（在线安装）」、默认安装目录 `D:\VideoToolbox`、远端组件仓库列表、启动后运行主程序等。
- **仓库列表（多源，v1.12.0 起）**：`<RemoteRepositories>` 下按优先级排列——① 官方源 GitHub Pages（`https://09th90.github.io/VideoToolbox/`，`Enabled=1`）② 本机/局域网自建源 `http://127.0.0.1:8123/`（`Enabled=0`，需先跑 `repo_server.py`）③ 加速镜像位（由 `--mirror-url` 注入）。**下载时取第一个可用的源**，用户可在安装器「设置」页取消慢的、勾选快的。
- **使用说明**：`build_online_installer.py` 会把它复制到 `build\ifw_config\config.xml` 再按参数重写/追加源（源文件保持默认）；<Version> 由 `src\apply_version.py` 统一维护（**同一文件里 `<Version>` 只允许出现一次**，加源时别复制这一行）。

### 7.7 `install_local_repo.py` —— 内网全速安装（v1.12.0 新增）

- **用途**：把在线安装器的下载源换成**本机/局域网仓库**，绕开 GitHub Pages 的国际链路瓶颈。原理是用 IFW 的 `--set-temp-repository <url>`（图形模式同样生效）把仓库地址临时替换，必要时顺带拉起 `repo_server.py`。
- **使用说明**（命令）：
  ```bat
  python installer_src\install_local_repo.py                        :: 本机源（自动起 repo_server，装完自动关）
  python installer_src\install_local_repo.py --port 9000
  python installer_src\install_local_repo.py --repo-url http://192.168.1.10:8123/   :: 用别人的内网源
  python installer_src\install_local_repo.py --file                 :: 直接用 file:/// 本地目录（不起服务）
  python installer_src\install_local_repo.py --dry-run              :: 只打印将执行的命令
  ```
- **行为**：自动定位 `installer\视频工具箱_在线安装_v*.exe`（取最新）与 `installer_repository\`；端口已占用则复用现有服务；起服务后用强制直连的探测请求确认 `Updates.xml` 可读再拉起安装器；安装器退出后关闭服务。
- **实测**：104MB 从本机仓库下载约 1 秒（150 MB/s 级），对比公网源 3 KB/s 的 5 小时级等待。
- **备注**：探测/等待一律用 `build_opener(ProxyHandler({}))` 强制直连——本机环境变量里的 `http_proxy` 会把 `127.0.0.1` 也送进代理导致 502。

### 13.2 打包环境与已知坑

- **必须用带 Qt 的构建环境**：`C:\bld\qt_build`（venv，Python 3.12 + pyinstaller + PyQt5 5.15.11 + PyQt-Fluent-Widgets 1.8.4）。系统 Python 没有 PyQt5。
- **必须从 ASCII 路径打包**：`C:\vt_build` 是项目目录的**目录联接（Junction）**，`workpath` / `distpath` 也用 ASCII 路径——PyInstaller 的 Qt 钩子在中文项目路径下会把 `QLibraryInfo` 返回的路径读成 `?????`（UTF-8 模式无效）。项目改名/搬家后联接会失效，用 PowerShell `New-Item -ItemType Junction` 重建（bash 里 `mklink` 会被安全策略拦）。
- **用 `python -m PyInstaller`**：`pyinstaller.exe`（entry-point 启动器）在本 shell 下会 1 秒静默退出。
- **构建前先挪走将被覆盖的旧产物（safe-delete shim 拦覆盖写，2026-09-17 实测三次失败教训）**：本机安全删除保护（safe-delete shim）每轮累计删除超 50 个"文件当量"会拦截批量删除，**构建工具的覆盖写也算**——PyInstaller 覆盖 `dist\视频工具箱.exe`、重建 `build_ascii\...\base_library.zip`、ISCC 覆盖 `installer\Setup exe` 都会被 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` 拦死（脚本内无法确认，直接失败）。**规避方案（已验证有效）：打包前把将被覆盖的产物 / 缓存 rename 到 `data\tmp\_stale_builds\`（rename 不触发删除拦截），构建完确认产物无误再清理**。需挪走的清单：`dist\*.exe`、`installer\*.exe`、`installer_repository\` 全部内容、`build_ascii\`（整个缓存目录）、`build\ifw_config\`。另外 shim 在中文路径下会误报 `[safe-delete][SAFE_DELETE_FAIL_CLOSED] trash-failed`，**判断失败要复核文件是否还在**。
- **PyInstaller isolated 子进程偶发 0xC0000005**（如 hook-chardet 的 `collect_submodules` 崩溃）：原样重跑即可；重跑时日志出现 "Building because excludes changed" 属 Junction 环境正常现象（全量重建，约 2.5 分钟）。
- **不要用静默安装验证安装包**：`/VERYSILENT` 覆盖式安装 1GB+ 极慢且易被文件占用卡死；内容验证改用「exe 自检 + iss 编译日志（各文件被 Compression 列出）」。
- **`sys.executable` 在冻结后就等于本程序 exe（v1.12.1 血泪教训，最严重的一坑）**：任何把它当「Python 解释器」去 `subprocess.Popen` 的地方，打包后都会**拉起一个新主程序实例**。v1.12.0 的退出同步正是这么写的，结果「点退出 → 程序反复重启」，并伴随 `Failed to remove temporary directory: _MEI***`（新旧实例互抢 `_MEI` 解压目录）与 `no Qt platform plugin could be initialized`（平台插件已被对方删掉）两个错误框；同时 `%TEMP%` 会残留一堆 `_MEI*`。**防线**：解析解释器一律走 `system_python()` / `_calib_py()` / `calib_ai_agent.resolve_python()`，并由 `_is_self_exe()` 兜底——拿不到真实解释器就**返回空串让调用方跳过，绝不回退到 exe**。排查手法：把 exe 当 zip 读 CArchive → `open_embedded_archive('*.pyz')` → `extract('<模块名>')` 拿到 **code object**（注意入口脚本在 CArchive 层、不在 PYZ 里），递归 `co_consts` / `co_names` 比对字符串指纹，即可判定某份 exe 出自哪版源码。
- **大文件不能用 Git Data API 推 gh-pages**：`content.7z` 87MB 经 base64 后请求体 117MB，GitHub 直接回 `422 Sorry, your input was too large to process`（blob 有体积上限，压缩已到极限也救不回来）。正解是 `build\ghpages_push\`（**独立 git 仓库**，已被 `.gitignore` 忽略）里 `git push origin master:gh-pages`——实测 3.4MB/s、100MB 约 40 秒。`deploy_installer_ghpages.py` 的 urllib / curl 通道只适合小文件。（v1.14.1 部署 89.2MB 组件时再次复现 422，改用 `git worktree add --detach C:\vtgh origin/gh-pages` + push 方式，104.1MB 约 1 分钟成功，见 13.1；核验线上生效拉 `Updates.xml` 看 `<Version>`/`<ReleaseDate>`。）
- **后台任务的网络出口受限**：同一网络脚本丢到后台必然超时/被拦（401/422/504），在前台跑就成功。长任务别丢后台，改用「断点续传 + 分批」；GitHub 写请求走 `gh api`（Go 栈）在前台连续写最稳。
- **给文件加版本标记后要重打包**：`.py` 只加注释不改字节码，但 `subtitle_calib_merged.py`、`docs\*`、`installer_src\*` 这些**以独立文件分发**的内容字节会变，所以打标后必须重打 exe 与两个安装包，否则包内文件与仓库不一致。
- **wildcard Source 必须逐条确认 `Excludes`（v1.12.1 教训）**：`视频工具箱.iss` 里 4 处 `recursesubdirs` 的 wildcard，原先只有 `tools\python\*` 带了 `Excludes: "*.pyc,__pycache__"`，结果 `docs\vc_translate_impl\__pycache__\*.cpython-313.pyc` 被一起打进包（见 4.7）。**`__pycache__/` 在 `.gitignore` 里，所以 `git status` 永远看不到，仓库干净不代表包干净**——必须审计 ISCC 日志的 `Compressing:` 清单（顺手脚本：读日志抽 `Compressing: ` 行按可疑后缀过滤；注意日志换行可能是纯 `\r`，`^...$` 多行正则匹配不到，先 `\r`→`\n`）。
- **长编译（Inno / IFW repogen）必须在所有会进包的文件冻结后启动**：本轮曾在 Inno 编译途中改 `docs\程序说明书.md`，只能杀掉重来（半成品 <550MB 要删掉，正常约 574MB，别和新产物混在一起）。在线安装器 staging 的是**整个 `src\` 与 `docs\`**，这两个目录也必须先冻结。
- **git 长操作（fetch/clone/rebase/gc）一律后台跑**，且**绝不轻易 rebase**——本环境对长 git 任务易发 SIGTERM，中止的 rebase/gc 会摧毁 `.git/refs/` 并连带丢失对象；出现对象缺失时移走损坏 `.git` 后从远端重新 clone 到 **ASCII 原生路径**，再拷回工作区。克隆后必做 `git add --renormalize .`（`core.autocrlf=true` 会冒出大量纯换行符噪音的假 ` M`）。
