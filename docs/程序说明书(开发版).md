## 一、系统概览

### 1.1 产品定位

一个 Windows 桌面工具，把「下载 → 转写 → 翻译 → 校准 → 合成」串成可视流程，
同时提供 CLI、Python API 与 **MCP 工具面**供批处理与外部 Agent 接入。核心差异点是
**术语校准**：只改文字，不改字幕结构，并把校准知识沉淀为可同步的规则库。

### 1.2 能力矩阵

| 域 | 能力 | 主要入口 |
| --- | --- | --- |
| 下载 | yt-dlp 主链 + NewPipe 兜底、内置代理内核、字幕、Cookie | GUI 视频处理、`agent_cli download` |
| 转录 | 云端/本地 ASR 真切换、faster-whisper、说话人分离、语音分离影子后端 | GUI 字幕处理、`agent_cli transcribe` |
| 翻译 | 微软/谷歌/DeepLx，双语排版 | GUI 字幕处理、`agent_cli translate` |
| 校准 | 31 种模式、对象级知识、上下文正则、AI 校准、知识同步 | GUI 校准段、`agent_cli calibrate`、校准脚本 |
| 编辑 | SRT/VTT/ASS/SSA，逐帧对轴，撤销/边界保护 | GUI 字幕编辑 |
| 合成 | 软字幕、硬字幕、MKV 封装 | GUI、`agent_cli compose` |
| 切片 | 视频分段切割（逐段校验可播放） | GUI 视频处理切片段、`agent_cli split` |
| 流水线 | 链接链、下载目录监控、断点续跑 | GUI 流水线、`features/pipeline/pipeline.py` |
| 声纹 | 声纹筛选（precision 默认）、第二音色影子、按说话人拆分 | GUI 字幕/编辑、`features/voiceprint/` |
| 自动化 | B 站投稿 GUI 自动化、CLI UIA 自动化 | GUI 自动化、`bili_auto_submit.py` |
| 托管 | 内置 harness 适配层 + MCP stdio 入口 | GUI AI 托管页、`harness_bridge.py`、`src/mcp_server.py` |
| 视频库 | 本地视频后台扫描、缩略图、播放 | GUI 视频库、`media_registry.py` |

### 1.3 技术栈

| 层 | 选型 |
| --- | --- |
| 界面 | PySide6 6.12 + PySide6-Fluent-Widgets 1.11.3；自研主题层 `src/vt_fluent` |
| 引擎 | 自研 `src/core` + `engine_*.py` 接缝；字幕引擎组件在 `tools/videocaptioner` |
| 校准真源 | 自研 `src/calib_core`（引擎/词表/模式注册/对象索引） |
| 下载 | yt-dlp + NewPipe Extractor；代理内核 mihomo（`tools/mihomo`） |
| 媒体 | FFmpeg / ffprobe / libmpv |
| ASR | OpenAI 兼容接口 / faster-whisper；分离后端 torch/modelscope 可选 |
| 打包 | PyInstaller onedir + Inno Setup |
| 更新 | 自研在线安装器 + GitHub Releases 平铺资产 |

### 1.4 运行时约束

- Windows 10/11 64 位；安装器 `ArchitecturesAllowed=x64compatible`；安装版免管理员
  （`PrivilegesRequired=lowest`），默认 `D:\VideoToolbox`。
- 源码态需要 Python 3.12，且必须在仓库根运行（按 cwd 定位 `tools/`、`data/`）。
- 构建机需要 PyInstaller 6.22.3、onnxruntime，以及 ASCII junction 构建根。
- `tools/python` 是内嵌解释器，系统 Python 缺依赖，统一用它跑脚本。
- 语音分离后端的 torch / modelscope / demucs 是**可选依赖**，未安装时功能静默降级
  （见 4.2），不影响转录主链。

### 1.5 演进与兼容包袱

- v2.1.0 从 PyQt5 迁到 PySide6；旧主题与控件仍有兼容分支。
- 字幕引擎源自第三方 videocaptioner，逐步通过 `engine_*` 接缝自研化；
  `src/vt_engine` 是并行完整包，尚未接入主程序。
- v2.6.0 起安装形态从 onefile 改为 onedir，去掉每次启动的解包时间。
- v3.1.5 起各版本演进摘要见 11.2；历史版本留下的多入口（GUI/CLI/脚本/MCP）需要
  保持行为一致，改动要有回归。

## 二、总体架构

### 2.1 分层

```
壳层     src/video_toolbox_qt.py（薄入口：VERSION/main/MSVC 修复/兼容再导出）
         src/vt_app（boot/widgets/scheduler/lazy_shell/engine_ui/win_resize/bus/home_page/settings_page/main_window）
功能层   src/features/<id>（feature.py 清单 + cli.py + page.py，17 个功能包）
表现层   src/vt_fluent、src/vt_engine_ui、各功能页 page.py
接口层   src/agent_cli.py（注册表驱动薄壳）、src/api_worker.py（JSON-RPC 工作进程）、
         src/mcp_server.py（MCP stdio 壳）、subtitle_calib_merged.py、bili_auto_submit.py
业务域   src/core/{download,asr,translate,calibrate,pipeline}、src/features/<id>/ 域模块
校准真源 src/calib_core（引擎/词表/MODE_REGISTRY/对象索引 + data/ 知识表）
接缝层   src/engine_*.py、src/vt_engine（并行）
底座     src/core/shared（路径/日志/进程/配置）、tools/
```

17 个功能包：`automation/calibrate/compose/download/harness/info/library/mcp/merge/
pipeline/split/status/subtitle_edit/transcribe/translate/voiceprint/workbench`。
其中 `merge` 与 `workbench` 没有 `cli.py`，仅提供 GUI 页与服务；`mcp` 只提供服务
（工具面经 `src/mcp_server.py` 暴露）。

### 2.2 依赖红线与入口隔离

通用红线：

- `src/core` 不得 import Qt。
- 表现层不得直接 import videocaptioner；必须经 `vt_engine_ui/_seams.py`。
- `src/vt_engine` 不依赖 videocaptioner，但当前未接线。
- 第三方只读目录：`harness/`、`tools/` 的运行时本体。
- **功能层适配器（feature.py / cli.py）模块级禁 Qt 与重依赖**；后端在
  handler/方法体内惰性 import。
- **功能页（page.py）只经 vt_app 基建 + 注册表服务取能力，禁止反向 import
  入口 video_toolbox_qt**；壳层 vt_app 不 import 具体功能实现（注册表由入口注入）。
- **功能间互相调用一律经 `features.registry().service(fid, name)`**，禁止跨
  功能直接 import 后端。

MCP/API 与 CLI 入口隔离（`scripts/dev/check_entry_isolation.py`，R1-R4）：

- **R1** `features/mcp/**` + `src/mcp_server.py`：禁 import `agent_cli` /
  `features.*.cli` / CLI 入口层（含路径字符串出现）。
- **R2** `features/*/cli.py` + `agent_cli.py` + `features/_cli.py`：禁 import mcp。
- **R3** `features/_api/**` + `src/api_worker.py`：禁 import CLI/MCP 入口层、禁 Qt。
- **R4** L0 纯度：`core/**`、`calib_core/**`、`video_toolbox.py`、
  `features/<id>/<实现模块>.py` 不得反向依赖入口/接口层。

### 2.4 线程与进程

- 长任务走 QThread；翻译/校准另有线程池；子进程统一收口到 `core/shared/proc.py`，
  便于超时/取消。
- 定时器：mpv 进度 40ms、下载目录轮询 5s。
- GUI 主线程不做阻塞 IO；耗时操作必须放进工作线程或子进程。
- 校准/声纹同步带**进程锁**（`core/calibrate/sync.py`，msvcrt 互斥 + 重入防护），
  防止 GUI 与 CLI/更新链并发跑同一轮同步。

### 2.5 启动时序

1. `setswitchinterval(0.001)`；2. `prepare_runtime_env()`；3. crash guard；
4. QApplication；5. StartupScheduler；6. `applyAppStyleSheet()`（必须在建窗前）；
7. QLockFile 单实例；8. 主题/字体；9. MainWindow + `fit_to_screen()` + show；
10. 首帧后 `_defer()` 加载惰性页与同步线程；11. `exec_()`。

v3.1.5 起，首帧后的后台任务改为**单线程顺序 + 错峰**：`startup_sync` 25s→**45s**、
`prewarm_import` 30s→**75s**（`vt_app/boot.py`、`vt_app/main_window.py`），与媒体库
后台扫描拉开窗口，避免多任务同时抢 GIL 造成主线程连续冻结。

### 2.6 惰性加载与降级开关

- 功能页由注册表 GuiSpec 驱动挂载：`lazy=True` 用 `_LazyPageShell` 占位、
  首次显示/取用才构造真身；`lazy=False`（字幕工作台）常驻。
- 功能缺席或 builder 失败只跳过该页（导航缺席 + startup.log 留痕），绝不影响其它页
  与程序启动；容器页（视频处理）的 merge/split 子板块经注册表服务组装，缺失时板块
  与分段自动缺席。
- 校准/声纹同步在首页就绪后 45s 顺序执行（daemon 线程；见 2.5 错峰）。
- 常用降级环境变量：`VT_NO_SYNC`、`VT_NO_CALIB_SYNC`、`VT_NO_VP_SYNC`、
  `VT_NO_PIPELINE`、`VT_NO_SCHED`、`VT_NO_SPLASH`、`VT_NO_UPDATE_CHECK`、
  `VT_CALIB_OPT`、`VT_ENGINE_UI`、`VT_USE_BUILTIN_PROXY`（内置代理内核，见 4.1）、
  `VT_YTDLP_LIVE_FROM_START`（直播从头拉流开关，见 4.1）。

### 2.7 功能注册表与扩展接口（2026-11-15 功能解耦）

每个功能 = `src/features/<id>/` 一个独立包：

- `feature.py` 暴露 `FEATURE = FeatureSpec(...)`：id（须与包名一致）/title/
  backend（惰性后端模块）/requires（外部依赖键，仅展示）/services（对外服务
  表 name→"module:attr"）/cli（CliCommand 子命令声明）/gui（GuiSpec 挂载声明：
  nav/builder/position/order/object_name/icon/attr/lazy/sep_before/messages）/
  check（轻量无副作用可用性探针）。
- `cli.py`：子命令 setup + handler（模块级仅标准库 + features._cli 信封）。
- `page.py`：GUI 页（只经 vt_app 基建 + 注册表服务；消息经 app.q + bus 自订阅）。

注册表（`features/_registry.py`，纯标准库）：pkgutil 发现**非下划线子包 = 功能**，
逐包 try/except 隔离——单包损坏/缺失只记录 reason 到 `_errors`，不外抛、不影响启动。
`registry().service(fid, name)` 惰性解析服务（`resolve("module:attr")`）；`probe(fid)`
零副作用探活；`ensure()` 惰性 import 后端。CLI 子命令与 GUI 页按 GuiSpec/CliCommand
的 `order` 装配。

**新增功能三步**：复制 `features/_template/` 为 `features/<name>/` → 改清单 →
完成。CLI 子命令自动装配、GUI 页自动挂载、打包自动收集（spec
`collect_submodules('features')` + iss 整目录 recursesubdirs），无需改入口/
主窗口/打包清单。护栏：`scripts/dev/_selftest_features.py`。

消息总线（`vt_app/bus.py`）：页面按前缀订阅（如 download 页订阅
detect_done/sys_log/dl_），主线程 120ms 泵、每轮≤200 条；旧 `_dispatch`
路由表已整体删除，壳层编排消息 pipe_ready 由主窗口订阅。

### 2.8 模块位置约定（2026-11-15 模块独立文件夹）

- **功能专属实现模块一律放 `src/features/<id>/`**：28 个实现模块已归位
  （split/translate/compose/transcribe/subtitle_edit/library/pipeline/download/
  calibrate/voiceprint/automation/harness），与适配器 feature.py/cli.py/page.py
  同包；后续新功能照此办理。
- **硬搬迁、无转发壳**：引用一律 `features.<id>.<模块>` 单一路径——双路径可
  导入会产生双模块实例，破坏 selftest monkeypatch 与 calib_merge_core._log
  单例注入。
- core 层跨层例外见 `core/__init__.py` 依赖规则（download/calibrate/asr/shared
  可 import 功能专属实现，仍禁 Qt）。
- 打包零手工：spec `collect_submodules('features')` + iss `src\features\*`
  recursesubdirs 自动收集，新增模块无需改打包清单。

最小化**）：

- **主模型四职责**：①全局计划与分期；②逐步任务派发；③综合子模型结论后编写
  最终生产代码/最终文档；④编写最终报告。其余一律下沉。
- **下沉规则**：所有探测/调研/只读源码扫荡 → Explore 子模型；临时/一次性脚本
  （`data\tmp\`）的编写与运行 → general-purpose 子模型。主模型不亲自 grep/read
  漫游、不亲自写一次性脚本。
- 数据盘点、基线测量、原型验证、代码模块起草同样打包派发，不占用主模型轮次。
- **并发上限 3**：任一子模型完成腾出槽位即补派新任务，保持流水线满载。
- **任务包互不重叠**，每个任务包给出明确输入/产出/验收标准。
- 失败子模型用 SendMessage 携带其已完成的结论恢复继续；若覆盖面已被其它子模型
  报告涵盖，可不重派。

### 4.10 视频库与媒体注册

- 入口：`src/features/library/media_registry.py`、GUI 视频库页。
- v3.1.5 起，目录扫描由**后台合并式 worker** 执行（复用 pipeline 评估线程范式）：
  `os.scandir`+`DirEntry.stat()` 替代 `os.walk`+独立 stat（省一半 syscall）；新增
  目录 mtime **纳秒精度快路径**，空闲且全部落盘时跳过整轮扫描。扫描 IO 完全不持
  索引锁（仅合并结果短暂持锁），主线程查询/事件循环不再被占住；Qt 亲和尾部
  （watcher 增删路径、变更通知）经 queued 信号回主线程。`refresh/poll_once`
  保留同步语义（CLI 自检与流水线 evaluate 同步链依赖）。
- 缩略图取第 5 秒（短片取 0 秒），缓存 `data/thumb_cache`。
- 单击打开文件夹并调用系统播放器；右键只开文件夹。

- 页面之间通过信号/回调解耦，不直接操作对方控件。

- 自研 QSS/控件层，逐步替换 qfluentwidgets 的外观。

- QSS 资源缺失会导致 UI 退化；`_selftest_qss_pack.py` 检查打包后的资源路径。

### 5.5 冻结态与源码态差异

- 冻结态 `sys.executable` 是 exe，不是 Python 解释器；资源路径走 `_MEIPASS`/exe
  目录，源码态走仓库路径。
- `data/`、`logs/`、`tools/` 的定位必须同时适配两种形态。
- 部分 lambda/子进程调用在冻结态会失效，需用命名函数或显式参数。

```bash
# 机械校准
tools\python\python.exe subtitle_calib_merged.py src.srt --out out.srt --mode endo-bi
# 结构校验
tools\python\python.exe subtitle_calib_merged.py verify src.srt out.srt
# 行宽门禁（超限退出码 1）
tools\python\python.exe subtitle_calib_merged.py length out.srt
# 学习
tools\python\python.exe subtitle_calib_merged.py learn orig.srt calibrated.srt --mode bi
tools\python\python.exe subtitle_calib_merged.py learned-show
tools\python\python.exe subtitle_calib_merged.py learned-reject "<错形>"
```

`learned-promote --entities` 只把 confirmed 规则导出为 Entity 桩代码，**不写文件**；
必须人工审阅后才能并入脚本。禁止把通用中文词作为裸键。

### 8.5 MCP 接口（v3.2.5 新增）

外部 MCP host（Claude Desktop 等）以 stdio 方式接入：

```json
{ "command": "<程序根>\\tools\\python\\python.exe",
  "args": ["<程序根>\\src\\mcp_server.py"] }
```

- **入口壳** `src/mcp_server.py`（单文件 ~40 行 stdio 壳）：只做 chdir（CWD 契约：
  学习库相对路径落程序根）/sys.path/惰性装配；**禁 import CLI 入口层**（门禁 R1）。
  协议与工具面在 `features/mcp/server.py`，业务在 `features/_api`（经
  `api_worker.py` 子进程执行）。
- **工具清单** `features/mcp/tool_specs.py`：`TOOL_PREFIX = "vt_"`、
  `EXCLUDED = {"bili-submit"}` → **10 个工具**（`vt_status`/`vt_info`/`vt_download`/
  `vt_transcribe`/`vt_translate`/`vt_calibrate`/`vt_stabilize`/`vt_audit`/
  `vt_compose`/`vt_split`），inputSchema 由 spec.py 派生。
- **参数通道**：`input`（登记参数）+ `mode_flag`（校准模式旗标枚举）+ `extra_args`
  白名单透传；**未登记旗标一律拒绝**。`mode_flag` 与 `mode` 只能给一个。
- **超时档**：fast 30s / medium·async 300s（与 spec CommandSpec 一致）。
- **进程模型**：`features/mcp/runner.py` 以子进程运行 `src/api_worker.py`，stdout
  隔离——业务子进程的任何 print 都不会污染 JSON-RPC 通道。
- **结果映射**（`features/mcp/server.py`）：`structuredContent`（payload 原样信封）
  + `text`（人读摘要 ≤2KB）+ `resource_link`（产物文件链接）；**audit 退出码 1
  不置 is_error**（「有候选」是检查结果不是故障）。
- 运行期常量 `API_VERSION = "1.0.0"`；接入示例与排障见
  `docs/MCP接入说明.md`（@version 3.3.1）。

### 8.6 calib_entity CLI

### 8.7 实时字幕（features/live）

- 长生命周期服务：`features/live/page.py` + `soundcard_source.py`，无 CLI 子命令。
- 音源 WASAPI loopback / 麦克风 / WAV；ASR 复用设置页 `ai_config.json`，密钥只读 `credentials.json`。

### 9.7 构建侧已知坑

- 中文路径 → PyInstaller Qt 钩子读成 `?????`，必须用 ASCII junction。
- `PYTHONPATH` 上的 sitecustomize 会被收进 PYZ；必须 `env -u PYTHONPATH` 并在 spec
  `excludes` 中剔除 `sitecustomize/usercustomize`。
- `excludes` 优先级高于 `hiddenimports`；漏摘 excludes 会导致模块缺失。
- 顶层自研模块必须同时进 spec hiddenimports 与 iss 的 Source 白名单。
- QSS `datas` 目标目录写错会导致运行时 UI 退化。
- gh-pages 单文件 100MiB 上限；改用 GitHub Releases 平铺资产。
- 冻结态 `sys.executable` 不是解释器；零参 lambda 可能崩。
- Inno 静默安装可能按注册表 `PreviousAppDir` 选目录。
- 递归删除在本机可能触发安全删除钩子；批量清理用 rename 或 Win32 API。
- torch/modelscope 分离依赖**不进安装包**（可选依赖，缺失即降级）；spec excludes
  必须持续排除，否则包体积失控。
