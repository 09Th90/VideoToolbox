## 〇、文档信息与版本纪律

### 0.1 版本号来源

唯一来源是 `src/video_toolbox_qt.py` 的 `VERSION = "3.0.0"`。
`scripts/dev/apply_version.py` 负责把版本号同步到 16 个固定位置（13 个文件），包括：

- `packaging/视频工具箱.spec`
- `packaging/视频工具箱.iss`
- `packaging/installer_src/` 的在线安装器配置
- `packaging/online_release/vt_update_core.py`、`vt_dl.py`
- `src/vt_update_check.py`
- `docs/使用说明.txt`、两份程序说明书、英文说明书

`README.md` 等文件首行的 `@version` 标记与《文件版本清单》由 `stamp_versions.py` 统一处理。

改号后还会调用 `stamp_versions.py`：

- 为自研源文件重打首行 `# @version x.y.z`；
- 重新生成 `文件版本清单.md`（SHA-1 清单）。

`stamp_versions.py` 从 **git index（暂存区）** 读取 blob SHA，因此运行前要先
`git add`，并保证工作区与暂存区一致；否则清单会出现假阴性。

## 一、系统概览

### 1.1 产品定位

一个 Windows 桌面工具，把「下载 → 转写 → 翻译 → 校准 → 合成」串成可视流程，
同时提供 CLI 与 Python API 供批处理。核心差异点是**术语校准**：只改文字，
不改字幕结构，并把校准知识沉淀为可同步的规则库。

### 1.2 能力矩阵

| 域 | 能力 | 主要入口 |
| --- | --- | --- |
| 下载 | yt-dlp 主链 + NewPipe 兜底、字幕、Cookie、代理 | GUI 视频处理、`agent_cli download` |
| 转录 | 在线 ASR、本地 faster-whisper、说话人分离 | GUI 字幕处理、`agent_cli transcribe` |
| 翻译 | 微软/谷歌/DeepLx，双语排版 | GUI 字幕处理、`agent_cli translate` |
| 校准 | 19 种模式、术语表、上下文正则、AI 校准、知识同步 | GUI 校准段、`agent_cli calibrate`、校准脚本 |
| 编辑 | SRT/VTT/ASS/SSA，逐帧对轴，撤销/边界保护 | GUI 字幕编辑 |
| 合成 | 软字幕、硬字幕、MKV 封装 | GUI、`agent_cli compose` |
| 流水线 | 链接链、下载目录监控、断点续跑 | GUI 流水线、`src/features/pipeline/pipeline.py` |
| 声纹 | 声纹筛选、按说话人拆分 | GUI 字幕/编辑、`speaker_voiceprint*` |
| 自动化 | B 站投稿 GUI 自动化、CLI UIA 自动化 | GUI 自动化、`bili_auto_submit.py` |
| 托管 | 内置 harness 适配层 | GUI AI 托管页、`harness_bridge.py` |
| 视频库 | 本地视频扫描、缩略图、播放 | GUI 视频库、`media_registry.py` |

### 1.3 技术栈

| 层 | 选型 |
| --- | --- |
| 界面 | PySide6 6.12 + PySide6-Fluent-Widgets 1.11.3 |
| 自研主题 | `src/vt_fluent` QSS/控件层 |
| 引擎 | 自研 `src/core` + `engine_*.py` 接缝；字幕引擎组件在 `tools/videocaptioner` |
| 下载 | yt-dlp + NewPipe Extractor |
| 媒体 | FFmpeg / ffprobe / libmpv |
| ASR | OpenAI 兼容接口 / faster-whisper |
| 打包 | PyInstaller onedir + Inno Setup |
| 更新 | 自研在线安装器 + GitHub Releases 平铺资产 |

### 1.4 运行时约束

- Windows 10/11 64 位；安装器 `ArchitecturesAllowed=x64compatible`。
- 安装版免管理员（`PrivilegesRequired=lowest`），默认 `D:\VideoToolbox`。
- 源码态需要 Python 3.12，且必须在仓库根运行（按 cwd 定位 `tools/`、`data/`）。
- 构建机需要 PyInstaller 6.22.3、onnxruntime，以及 ASCII junction 构建根。
- `tools/python` 是内嵌解释器，系统 Python 缺依赖，统一用它跑脚本。

### 1.5 演进与兼容包袱

- v2.1.0 从 PyQt5 迁到 PySide6；旧主题与控件仍有兼容分支。
- 字幕引擎源自第三方 videocaptioner，逐步通过 `engine_*` 接缝自研化；
  `src/vt_engine` 是并行完整包，尚未接入主程序。
- v2.6.0 起安装形态从 onefile 改为 onedir，去掉了每次启动的解包时间。
- 历史版本留下的双入口（GUI/CLI/脚本）需要保持行为一致，改动要有回归。

## 二、总体架构

### 2.1 分层

```
壳层     src/video_toolbox_qt.py（薄入口：VERSION/main/MSVC 修复/兼容再导出）
         src/vt_app（boot/widgets/scheduler/lazy_shell/engine_ui/win_resize/
                     bus/home_page/settings_page/main_window）
功能层   src/features/<id>（feature.py 清单 + cli.py + page.py，16 个功能包）
表现层   src/vt_fluent、src/vt_engine_ui、各功能页 page.py
接口层   src/agent_cli.py（注册表驱动薄壳）、subtitle_calib_merged.py、src/features/automation/bili_auto_submit.py
业务域   src/core/{download,asr,translate,calibrate,pipeline}、src/features/<id>/ 域模块
接缝层   src/engine_*.py、src/vt_engine（并行）
底座     src/core/shared（路径/日志/进程/配置）、tools/
```

依赖红线：

- `src/core` 不得 import Qt。
- 表现层不得直接 import videocaptioner；必须经 `vt_engine_ui/_seams.py`。
- `src/vt_engine` 不依赖 videocaptioner，但当前未接线。
- 第三方只读目录：`harness/`、`tools/` 的运行时本体。
- **功能层适配器（feature.py / cli.py）模块级禁 Qt 与重依赖**；后端在
  handler/方法体内惰性 import。
- **功能页（page.py）只经 vt_app 基建 + 注册表服务取能力，禁止反向 import
  入口 video_toolbox_qt**；壳层 vt_app 不 import 具体功能实现（注册表由入口注入）。
- **功能间互相调用一律经 `features.registry().service(fid, name)`**，禁止跨
  功能直接 import 后端。

### 2.2 目录映射

| 目录 | 职责 |
| --- | --- |
| `src/features` | 功能层：注册表（_registry.py）+ 16 个功能包（清单/CLI/页面）+ _template 模板 + _media 共享常量 |
| `src/vt_app` | GUI 壳基础设施：启动诊断/崩溃守卫/控件基建/启动调度器/惰性外壳/消息总线/引擎预热/边框热区/首页/设置页/主窗口 |
| `src/core/shared` | 路径解析、日志、子进程、配置、缓存 |
| `src/core/download` | yt-dlp、Cookie、NewPipe |
| `src/core/asr` | 在线/本地 ASR、协议适配 |
| `src/core/translate` | 微软/谷歌/DeepLx、双语排版 |
| `src/core/calibrate` | 校准规则、学习库、同步 |
| `src/core/pipeline` | 编排、状态机 |
| `src/vt_engine` | 自研完整引擎（26 模块 + 5 线程） |
| `src/vt_engine_ui` | 引擎 UI 适配层，12 文件 |
| `src/vt_fluent` | 自研 Fluent QSS/控件库，12 文件 |
| `src/calib_entity` | 对象级知识层与 CLI，只读 |
| `scripts/dev` | 开发、自检、构建、探针脚本 |
| `packaging` | spec、iss、在线安装/更新链 |
| `docs` | 说明书、许可、提示词与补丁 |

### 2.3 线程与进程

- 长任务走 QThread；翻译/校准另有线程池。
- 子进程统一收口到 `core/shared/proc.py`，便于超时/取消。
- 定时器：mpv 进度 40ms、下载目录轮询 5s。
- GUI 主线程不做阻塞 IO；耗时操作必须放进工作线程或子进程。

### 2.4 启动时序

1. `setswitchinterval(0.001)`；
2. `prepare_runtime_env()`；
3. crash guard；
4. QApplication；
5. StartupScheduler；
6. `applyAppStyleSheet()`（必须在建窗前）；
7. QLockFile 单实例；
8. 主题/字体；
9. MainWindow + `fit_to_screen()` + show；
10. 首帧后 `_defer()` 加载惰性页与同步线程；
11. `exec_()`。

### 2.5 惰性加载与降级开关

- 功能页由注册表 GuiSpec 驱动挂载：`lazy=True` 用 `_LazyPageShell` 占位、
  首次显示/取用才构造真身；`lazy=False`（字幕工作台）常驻。
- 功能缺席或 builder 失败只跳过该页（导航缺席 + startup.log 留痕），绝不
  影响其它页与程序启动；容器页（视频处理）的 merge/split 子板块经注册表
  服务组装，缺失时板块与分段自动缺席。
- 校准/声纹同步在首页就绪后 25s 启动，两条 daemon 线程。
- 常用降级环境变量：
  - `VT_NO_SYNC`、`VT_NO_CALIB_SYNC`、`VT_NO_VP_SYNC`
  - `VT_NO_PIPELINE`、`VT_NO_SCHED`、`VT_NO_SPLASH`
  - `VT_NO_UPDATE_CHECK`、`VT_CALIB_OPT`、`VT_ENGINE_UI`

### 2.6 功能注册表与扩展接口（2026-11-15 功能解耦）

每个功能 = `src/features/<id>/` 一个独立包：

- `feature.py` 暴露 `FEATURE = FeatureSpec(...)`：id（须与包名一致）/title/
  backend（惰性后端模块）/requires（外部依赖键，仅展示）/services（对外服务
  表 name→"module:attr"）/cli（CliCommand 子命令声明）/gui（GuiSpec 挂载声明：
  nav/builder/position/order/object_name/icon/attr/lazy/sep_before/messages）/
  check（轻量无副作用可用性探针）。
- `cli.py`：子命令 setup + handler（模块级仅标准库 + features._cli 信封）。
- `page.py`：GUI 页（只经 vt_app 基建 + 注册表服务；消息经 app.q + bus 自订阅）。

注册表（`features/_registry.py`，纯标准库）：pkgutil 发现非下划线子包，逐包
try/except 隔离——单包损坏/缺失只记录 reason，不外抛、不影响启动。
`registry().service(fid, name)` 惰性解析服务；`probe(fid)` 零副作用探活。

**新增功能三步**：复制 `features/_template/` 为 `features/<name>/` → 改清单 →
完成。CLI 子命令自动装配、GUI 页自动挂载、打包自动收集（spec
`collect_submodules('features')` + iss 整目录 recursesubdirs），无需改入口/
主窗口/打包清单。护栏：`scripts/dev/_selftest_features.py`。

消息总线（`vt_app/bus.py`）：页面按前缀订阅（如 download 页订阅
detect_done/sys_log/dl_），主线程 120ms 泵、每轮≤200 条；旧 `_dispatch`
路由表已整体删除，壳层编排消息 pipe_ready 由主窗口订阅。

### 2.7 模块位置约定（2026-11-15 模块独立文件夹）

- **功能专属实现模块一律放 `src/features/<id>/`**：28 个实现模块已归位
  （split/translate/compose/transcribe/subtitle_edit/library/pipeline/download/
  calibrate/voiceprint/automation/harness），与适配器 feature.py/cli.py/page.py
  同包；后续新功能照此办理。
- **src 顶层只留**：入口三件（video_toolbox_qt/agent_cli/video_toolbox facade）、
  壳层三件（ui_theme/qt_compat/vt_update_check）、共享接缝六件（engine_asr_data/
  engine_entities/engine_cache/engine_paths/engine_task_factory/subtitle_editor_core）。
  禁止新增顶层功能域模块。
- **硬搬迁、无转发壳**：引用一律 `features.<id>.<模块>` 单一路径——双路径可
  导入会产生双模块实例，破坏 selftest monkeypatch 与 calib_merge_core._log
  单例注入。
- core 层跨层例外见 `core/__init__.py` 依赖规则（download/calibrate/asr/shared
  可 import 功能专属实现，仍禁 Qt）。
- 打包零手工：spec `collect_submodules('features')` + iss `src\features\*`
  recursesubdirs 自动收集，新增模块无需改打包清单。

## 四、业务域

### 4.1 下载域

- 入口：`src/core/download/*`、`src/video_toolbox.py` 的下载原语。
- 主链 yt-dlp，NewPipe 兜底（`tools/newpipe-cli`）。
- 清晰度只列 ≥720p，每个分辨率一档，优先 >30fps，再取最大文件。
- 默认下载目录 `data/downloads`；可配置。
- Cookie：自动/浏览器读取/cookies.txt/游客，支持 8 种浏览器。
- 代理由后台兜底，GUI 不暴露开关。
- 输出：视频、可选字幕（转 SRT）、元信息。

### 4.2 转录域

- 入口：`src/core/asr/*`、`features/transcribe/engine_asr*`、`src/vt_engine_ui/transcription_interface.py`。
- 两种来源：自有 ASR 服务（Whisper 兼容）/ 本地 faster-whisper。
- 识别语言默认自动；可在转录页命令栏指定。
- 说话人分离：调用方在导出时选择合并或按说话人拆分。
- 语音分离只有占位，不内置模型。

### 4.3 翻译域

- 入口：`src/core/translate/*`、`features/translate/engine_translate.py`。
- 服务：微软（默认）、谷歌、DeepLx；LLM 翻译已移除。
- 双语排布：译文在上/原文在上/仅译文/仅原文。
- 输出 SRT，保留时间轴；翻译失败时保留原文并可重试。

### 4.4 校准域

- 入口：`subtitle_calib_merged.py`、`src/core/calibrate/*`、`src/features/calibrate/calib_ai_agent.py`。
- 机械校准：术语表 + 上下文正则 + 学习库；只改中文行。
- AI 校准：分块、上下文预算、思考强度、联网查证、音画证据、集群/协作。
- 结构契约：序号/时间轴/空行/CRLF-LF/BOM 不变；参考行默认不动，
  仅 `--fix-en` 允许修参考行。
- 学习库：`subtitle_learned_kb.json`，confirmed 规则自动注入；支持同步。
- 模式：19 种（默认 `bi` + 18 个旗标），详见 8.2。

### 4.5 字幕编辑与合成域

- 入口：`src/features/subtitle_edit/subtitle_editor*.py`、
  `src/features/compose/subtitle_compose*.py`（subtitle_editor_core 共享接缝留顶层）。
- 读取 SRT/VTT/ASS/SSA；导出 SRT/ASS。
- 撤销 100 层；边界最小 40ms；重叠/过短提示。
- 合成三种：软字幕（内嵌）、硬字幕（烧录）、MKV 封装。
- ASS 烧录需要重编码；软封装不重编码。

### 4.6 流水线域

- 入口：`src/features/pipeline/pipeline.py`。
- 链接链：下载→（无字幕自动语音转录）→翻译→校准→二次校准→成品。
- 目录监控：盯下载目录的新视频；没有独立文件夹选择器。
- 自动开关默认开；并发 1–8，默认 3。
- 状态：`data/pipeline_state.json`，原子写；重启时 DONE 跳过、RUNNING 转 READY。
- 产物复用需要 `.src.json` 指纹一致。

### 4.7 声纹域

- 入口：`src/features/voiceprint/speaker_voiceprint*.py`、
  `src/features/voiceprint/voiceprint_sync.py`。
- 声纹筛选、按说话人拆分、同步。
- 模型与模板属于运行期数据；清理 `data/` 后需重新录入/下载。
- 本地聚类第二遍先合并近重复簇，再用冻结簇心对全部有效 cue 重指派；离群
  cue 只在彼此之间重新立簇。回归用例钉住了「合并结果必须影响最终整体标签」，
  不是简单重复第一遍。
- `filter_srt()` 保留 `[(cue, state, score)]` 公共判定契约，另返回 `decisions`：
  每条含原序号、起止毫秒、状态、分数、来源、原因、ASR 说话人与本地簇。
  初次 `review` 才做逐 cue 兜底；短 cue 只有逐条打分仍失败、且前后邻居同属
  一个有效本地簇时才借簇分（`short_context`），其余无证据情况继续保持存疑。
- 模式：`recall`（默认，review 进入正式 SRT）/ `precision`（正式 SRT 只含
  keep，review 写 `<原名>_待复核.srt`，同名追加序号，不覆盖历史文件）。
  旧 `keep_review=False` 与 CLI `--strict` 均映射为 precision；独立 CLI 也可
  显式传 `--mode precision`。报告同时列存疑与丢弃条目、时间轴、来源和原因。
- GUI 声纹选择器的策略与名单、自动筛选开关同存 `_selection.json` 的
  `filter_mode`；三个写入函数都保留未知键。自动/手动执行入口未显式传模式时，
  统一由 `core/asr/voiceprint.py` 读取该策略。

Jev / System One 结构化影子决策（`decision-model-preview`）：

- 客户端为 `tools/decision_client.py`，共享加载缝为 `core/shared/decision.py`；
  请求严格使用官方 `POST /compatible-mode/v1/systemone`，正文只含
  `model/state/questions`，支持 choice/noul/score 响应校验，不生成文本。
- 激活条件必须同时满足：全局 AI 启用、`decision_mode=shadow`、全局 AI 密钥存在、
  HTTPS 地址的主机名为 `token-plan.*.maas.aliyuncs.com`。普通百炼按量/工作空间
  端点、火山方舟 Token Plan、QwenCloud 和其他 OpenAI 兼容端点均不激活，也不会
  自动改地址或回退到别的服务商。设置页可关闭，关闭后零 Jev 请求。
- 复用全局 AI 的 `base_url/api_key`，不新增第二套决策凭据；配置新增
  `decision_mode/decision_timeout/decision_max_items/decision_batch_size`。默认每次
  业务流程最多 32 条、每批 8 条、单批超时 12 秒，异常按批降级并记录原因。
- 声纹侧只对本地二次判定后仍为 review 的 cue 路由为 `routine_review`、
  `priority_manual` 或 `insufficient_evidence`。Jev 听不到音频，不得凭台词猜身份；
  它只安排复核优先级，不改变 CAM++ 分数、keep/review/drop、正式 SRT 或待复核 SRT。
- 校准侧只复核已通过机械校验的 accepted 改动，路由为 `consistent`、
  `manual_review` 或 `questionable`；不生成替换文本、不撤销采纳、不修改时间轴。
  结构化选项、概率、置信度、request_id 与降级原因写入结果和报告，供后续标注评估。
- 校准侧在 Jev 之前增加**本地证据闸门**（2026-11-18）：`status=conflict` 直接
  `questionable`，`status=missing` 或 `clean_replacement=false` 直接
  `manual_review`，只有“证据 ok 且只做错形到官方名的最小替换”才送 Jev。
  闸门是确定性规则，不发网络请求，不依赖模型置信度；结论写入
  `decision.gated/gate_reasons`，Jev 明细单列 `jev_evaluated`。
- Jev 校准评测（2026-11-18，399 条本地一致性样本，310 train / 89 eval；
  `.calib.srt` 为规则/模型产物，不是人工金标，数字只表示与本地官方名的一致性）：
  baseline choice accuracy 0.382、负例拦截 0；evidence choice accuracy 0.382、
  负例拦截 0.1818；evidence_text_noul_fewshot accuracy 0.6966、正例召回 0.6471、
  负例拦截 0.7273。结论：Jev 单独仍不足以自动放行术语校准，只能做影子建议。
- 本地闸门 + Jev 风险分数（阈值 0.70）在留出集上 binary accuracy 0.9888、
  正例召回 0.9706、consistent precision 1.0、review rate 0.6292；只用本地闸门
  时 precision 1.0、正例召回 1.0、review rate 0.618。生产策略因此定为
  “本地闸门定分流，Jev 只补充语义风险提示”，不把 Jev 作为唯一裁决器。
- 阿里云官方文档列出的 System One 地址是业务空间端点；共享 Token Plan 是否实际
  开放 `decision-model-preview` 必须以真实服务响应为准。代码门控通过不等于已验证
  模型权限或业务效果，失败时保持本地结果，不切换到未授权端点。

### 9.7 构建侧已知坑

- 中文路径 → PyInstaller Qt 钩子读成 `?????`，必须用 ASCII junction。
- `PYTHONPATH` 上的 sitecustomize 会被收进 PYZ；必须 `env -u PYTHONPATH`
  并在 spec `excludes` 中剔除 `sitecustomize/usercustomize`。
- `excludes` 优先级高于 `hiddenimports`；漏摘 excludes 会导致模块缺失。
- 顶层自研模块必须同时进 spec hiddenimports 与 iss 的 Source 白名单。
- QSS `datas` 目标目录写错会导致运行时 UI 退化。
- gh-pages 单文件 100MiB 上限；改用 GitHub Releases 平铺资产。
- 冻结态 `sys.executable` 不是解释器；零参 lambda 可能崩。
- Inno 静默安装可能按注册表 `PreviousAppDir` 选目录。
- 递归删除在本机可能触发安全删除钩子；批量清理用 rename 或 Win32 API。
