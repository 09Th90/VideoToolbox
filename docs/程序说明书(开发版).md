## 一、系统概览

### 1.1 产品定位

视频工具箱（VideoToolbox）是一个面向**视频本地化生产**的 Windows 桌面工具集：把「下载素材 → 出字幕 → 翻译 → 术语校准 → 对轴编辑 → 合成成品」这条原本需要五六个工具接力完成的链路，收敛到一个程序、一套配置、一条流水线里。

它的差异化不在单点功能，而在三件事：

1. **术语校准**——针对游戏剧情、反应视频这类专有名词密集的片源，用「脚本级术语表 + AI Agent 复校 + 实体对象层」三层结构把机翻的错形压下去，且只改文字、不动时间轴。
2. **全链路可编排**——同一条链既能手动一步步走，也能交给流水线无人值守，还能通过命令行交给外部 Agent 驱动。
3. **运行时自包含**——内嵌 Python、ffmpeg、yt-dlp、deno、libmpv、字幕引擎运行时，用户机器上不需要预装任何环境。

### 2.4 并发与线程模型

程序的并发由四类机制承担，混用且各有边界，排障时必须先分清是哪一类。

| 机制 | 使用场景 | 约束 |
| --- | --- | --- |
| **QThread** | 长任务不阻塞界面：下载、转录、翻译、校准、声纹筛选、投稿、流水线阶段 | worker 必须挂到界面对象属性上（如 `iface._vt_vp_worker`），否则随局部变量出作用域被 GC，表现为「进度条一闪、什么都没发生」 |
| **线程池** | 引擎内部翻译/优化并发、AI 校准块级并发 | 翻译 LLM 并发上限 `_LLM_THREAD_CAP=5`；校准并发由 `calib_concurrency` 控制，默认 1（串行） |
| **子进程** | ffmpeg、yt-dlp、NPE(java)、harness(node)、退出同步、AI 校准脚本 | 一律经 `core\shared\proc.py`（窗口隐藏 / 进程树杀灭 / 可取消睡眠）；**绝不回退到 `sys.executable`**（冻结后即 exe 自身，会无限重启） |
| **QTimer 调度** | 启动期惰性任务、mpv 播放位置轮询（40ms）、目录监视轮询（5s） | 启动期统一走 `_StartupScheduler`，禁止散落 `singleShot` |

**取消语义**：下载链支持可中止（`_selftest_download_cancel.py` 覆盖）；任务取消需立即停掉翻译/优化线程池，不能只置标志位等当前批次跑完。

### 2.5 启动时序

`main()`（`video_toolbox_qt.py:11005`）的步骤顺序是硬契约，多处注释标明「改顺序会出事」。

| 序 | 步骤 | 关键点 |

| 5 | `configure_qt_plugins()` | frozen 下直接 return（Qt 插件已由打包配置处理） |
| 6 | 高 DPI 舍入策略 | 必须在 `QApplication` 之前 |
| 7 | `QApplication(sys.argv)` | — |
| 8 | `_StartupScheduler(app)` | 惰性任务调度器 |
| 9 | `app.setStyle("fusion")` | 自绘控件依赖 fusion 基线 |

| 11 | 窗口图标 + `QLockFile` 单实例 | 双实例会写穿同一份配置 |

- `stackedWidget` 的 sizePolicy 置 `Ignored` 必须在**第一次 `addSubInterface` 之前**（`:9611-9621`），否则页面切换会被 sizeHint 撑大窗口。
- `applyAppStyleSheet` 早于 `MainWindow`，但 `ui_theme` 的普通 Qt 控件 accent 表走全局 Polish 钩子，可在任意时刻增量刷新。

### 2.6 惰性加载与启动调度

启动期性能是刻意设计的，不是偶然：

| 机制 | 作用 | 代价 / 收益 |

## 三、引擎接缝与自研化

### 3.1 为什么有「接缝」这一层

程序早期直接依赖一个内嵌的字幕引擎包，所有功能都长在它上面。自研化不能一次换掉——那等于同时改 ASR、翻译、缓存、任务工厂、UI 五条线。于是采用**先换接缝、再换整包**的两阶段策略：

- **阶段一（已完成）**：把引擎的每个可替换点抽成平铺模块 `engine_*.py`，行为与原实现逐字节对齐，由自检脚本证明等价；业务代码改为 import 这些接缝模块。
- **阶段二（进行中）**：`src\vt_engine\` 提供一个不依赖原引擎的完整包；切换方式是把 `vt_engine_ui\_seams.py` 的后端取值从 `videocaptioner.*` 改为 `vt_engine.*`。

### 3.2 `engine_*` 平铺接缝

## 四、业务域层

本章每个域按同一模板描述：**职责 → 入口 → 数据流 → 失败模式**。正文只讲机制，不逐文件罗列——文件职责见附录 A。

### 4.1 下载域

#### 职责

把一条链接（或分享文案、`.url` 文件、含链接的 txt）变成一份**自包含的素材文件夹**：视频 + 1280×720 封面 + `视频信息.txt` + 外挂字幕。同时承担音画合并（把分离的音视频流合成成品）。

#### 入口

| 入口 | 位置 | 场景 |
| --- | --- | --- |
| `_download_link_run` | `pipeline.py:746` | 流水线 / 下载页共用主链 |
| `agent_cli.cmd_download` | `agent_cli.py` | 命令行 |
| `core\download\urls.py` | — | 链接识别与提取（`.url`/txt/分享文案 → URL） |
| `core\download\media.py` | — | 媒体扫描、智能配对、音画合并 |

#### 数据流

```
链接 → urls.extract() 规范化
     → ytdlp_util.fetch_info_json() 探测画质/字幕/格式
     → 判定下载模式（视频 / 仅音频 / 指定轨）
     → yt-dlp 执行（八阶段，可中止）
     → util.write_info_txt() + make_cover_1280x720()
     → 字幕轨归一（滚动式重叠整理见 4.6）
     → 落盘 <下载目录>\<片名>\{视频, 封面.jpg, 视频信息.txt, *.srt}
```

#### 失败模式与降级

下载域是全程序降级链最长的地方，顺序是刻意设计的：

| 序 | 降级手段 | 触发条件 | 实现 |
| --- | --- | --- | --- |
| 1 | `--load-info-json` 复用探测结果 | 二次重试时 | 避免重复解析 |
| 2 | 链接重新提取（4 次） | CDN 直链过期 | `_ytdlp_with_retry:721` |
| 3 | HLS ↔ 直链互换 | 某一形态被风控 | `hls_alt_format` |
| 4 | NPE 第二解析引擎 | yt-dlp 全链失败 | `core\download\npe.py` + `npe_backend.race_engines:320` |

**NPE 的定位**：它不是代理，是 NewPipe Extractor（Java jar，GPL-3.0）驱动的**第二解析引擎**。`npe_engine_mode` 取 `auto/off/only`；它只解析流地址并拼 ffmpeg 命令，不拉流；音视频**分两次串行下载再本地合流**（ffmpeg 同时对 googlevideo 开两条连接会触发限流）。需 JDK 17+，`VT_JAVA` 可指定。

**Cookie 三通道**（`cookies.py`，754 行）：

| 通道 | 说明 |
| --- | --- |
| 游客 cookie | 无登录态时的基础通道 |
| 浏览器直读 | 从浏览器数据库读取；App-Bound 加密下**已失效** |
| CDP 导出 | 唯一可靠通路——驱动已登录浏览器导出 cookie |

⚠⚠ **cookie 一律预检门控 + 逐级降级**：读不到 cookie 绝不判任务失败，而是降级到下一通道或匿名下载。反过来，把「cookie 读不到」当失败上报是本域最常见的误判。

⚠⚠ **代理节点锁定**：YouTube 直链签发时绑定出口 IP，下载中途换节点会让已签发分片全部失效，表现为 `EOF occurred in violation of SSL protocol`。`proxy_lock_acquire/release()` 以引用计数锁定策略组，下载期间不允许切节点。

#### 音画合并

| 规则 | 内容 |
| --- | --- |
| 扩展名唯一权威 | `engine.MERGE_VIDEO_EXTS` 是唯一口径，`scan_media` / `media_registry.PAIR_EXTS` / `pipeline._stage_merge_ready` 三处同步派生——**改一处必须同步另两处** |
| 音频编码 | `probe_audio_codec()` 实测决定 `-c:a copy` 还是转 AAC |
| 视频编码 | VP9 / AV1 **能**直接 `-c:v copy` 进 mp4 且无损；真正失败的是 **VP8**（容器不支持），copy 失败后以 H.264 重编码重试一次 |
| 产物容器 | **恒定 `.mp4`**。webm 容器装不了 h264/aac，不要提「输出扩展名跟随输入容器」——照做必炸 |

### 4.2 转录域

#### 职责

把音频变成带时间轴的字幕。核心难点不在「调一次 ASR 接口」，而在**协议差异、长音频切分、缓存一致性、失败可解释**四件事。

#### 入口

| 入口 | 位置 | 场景 |
| --- | --- | --- |
| `engine_asr.transcribe` | `engine_asr.py:661` | 引擎内转录 |
| `agent_cli.cmd_transcribe` | `agent_cli.py:386` | 命令行 |
| `core\asr\protocol.py` | 2674 行 | 协议推断、各服务商 submit、词级聚合 |

#### 协议矩阵

`ASR_PROTOCOLS` 共 **13 项**：

```
auto, openai, azure, chat_audio, dashscope, deepgram, elevenlabs,
gemini, volcengine, assemblyai, dashscope_realtime, dashscope_native,
dashscope_filetrans
```

`_infer_asr_protocol()`（`protocol.py:200`）按域名与模型名推断；`asr_protocol_fix()`（`:250`）做**双向纠偏**：

- 「实时模型 + 非实时协议」→ 自动改走文件识别；
- 「实时协议 + 非实时模型」→ 同样改走文件识别（v1.15.3 补的反向守卫）。

`TranscribeModelEnum` 有 5 个值，实际只用两项：`WHISPER_API`（HTTP 服务）与 `FASTER_WHISPER`（本地）。`BIJIAN`/`JIANYING`/`WHISPER_CPP` 仅用于迁移旧配置，不要在新代码里引用。

#### 数据流与几何参数

```
音频 → 预处理（只接受 flac/m4a/mp3/wav；其余 ffmpeg 抽 192k aac）
     → 切块（pydub → ffmpeg → 整段兜底三级回落）
     → 并发提交（HTTP）或串行（本地）
     → 词级聚合 → ASRData → SRT
```

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `CHUNK_LENGTH_SEC` | 600 | 单块时长 |
| `OVERLAP` | 10 | 块间重叠，防切断词 |
| `CONCURRENCY` | 3 | 默认并发 |
| 本地模式 | `chunk_concurrency=1`，块长翻倍 | 本地模型并行无收益且吃内存 |
| `ASR_CACHE_EXPIRE` | 2 天 | 过期即重算 |
| 缓存键 | `WhisperAPI:{crc32}-{model}-{lang}-{prompt}` | 落 `data\cache\asr_results` |

#### 失败模式

| 现象 | 处理 |
| --- | --- |
| 握手 401/403 | **不降级重试**，直接给出可操作结论（密钥/权限问题重试无意义） |
| 服务端报 too long | 自动对半切分重试 |
| 音频超限 | 自动压成低码率 MP3 后重试 |
| 8k 采样率模型 | 自动 ffmpeg 转 8kHz 单声道 wav |
| 实时 WS 推帧过快 | 按采样率折算 **20 倍实时速率**（`VT_ASR_WS_SPEED` 可调），全速灌发会撑爆服务端缓冲 |
| 实时 WS 无 Close 码断连 | 自动降级同端点文件识别（`qwen3-asr-flash`），并做**会话级降级记忆**避免重复尝试 |
| 国内端点 ProxyError | 对国内端点强制直连，不走系统代理 |

### 4.3 翻译域

#### 职责

把原文 SRT 变成双语 SRT。**只做翻译与排版，不做术语纠正**——术语是 4.4 校准域的职责，两者不重叠。

#### 两条翻译路径（重要）

程序里有两条独立的翻译实现，用途不同，不要混为一谈：

| 路径 | 实现 | 使用场景 | 引擎选择 |
| --- | --- | --- | --- |
| **引擎路径** | `engine_translate.py` + `core\translate\route_patch.py` | GUI 字幕处理页、CLI `translate` 子命令 | 微软 / 谷歌 / DeepLx 三选一 |
| **流水线直连** | `pipeline._translate_srt_file`（`pipeline.py:1060`） | 流水线阶段 | 固定 Google `translate_a/single` |

流水线直连不经过 `engine_translate`：每批 1200 字符 / 40 行，重试 3 次，产出「原文在上、译文在下」；若正文汉字占比 > 0.3 则抛 `SkipStage`（已中文，无需翻译）。

#### 引擎与端点

| 引擎 | 端点 | 注意 |
| --- | --- | --- |
| 微软 | `edge.microsoft.com/translate/translatetext` | `trust_env=False`，不走系统代理 |
| 谷歌 | `translate_a/t`（抓 Chrome 内置翻译同源） | `direct_ok=False` 时直接短路，不探测 |
| DeepLx | 自建实例 | 后端地址可配 |

枚举 `TranslatorServiceEnum`（`engine_entities.py:203`），实现表 `TRANSLATOR_PROBES:338`、简码表 `_BY_CODE:344`、工厂 `make_translator:351`（未知标签抛 `KeyError`）。

`route_patch.ensure_translate_patches()` 做两件事：**路由钉死**（不让引擎自行改道）+ **去掉 AI 兜底**（翻译就该走机翻）。它是幂等的，GUI 预热与 `agent_cli` 各自显式安装一次。

#### 缓存与排版

| 项 | 规则 |
| --- | --- |
| 缓存键 | `类名:内容哈希:目标语言` |
| 失败译文 | `ERROR` / 空 / `xxx||ERROR` **一律不写缓存**（否则错误会被永久固化） |
| 排版枚举 | `SubtitleLayoutEnum`，默认原文在上 |
| 流水线成品 | 重排为译文在上，命名 `【字幕】名-谷歌翻译.srt` |

#### 失败模式

⚠ `TranslationIncompleteError`：机翻端点整批失败时条目译文是空串，`ASRData.to_srt` 会**静默回落成原文**——产出「名字叫『-谷歌翻译.srt』、内容其实是原文」的假翻译，且全程零报错。修复后译文缺失一律抛错且**不落盘**；谷歌整批失败时自动改用微软重试一次并提示。

### 4.4 校准域

这是本程序最复杂、也是最有差异化的域。它由**三层结构**叠成，改造时必须先分清在哪一层动刀。

#### 三层结构

| 层 | 载体 | 规模 | 职责 | 可回退 |

### 4.5 字幕编辑与合成域

#### 职责

#### 三层结构

| 层 | 文件 | 内容 | 依赖 |

**视图层只持 cues 引用**，所有改动以信号上报，由页面组装（`video_toolbox_qt.py:7520` 的 `SubtitleEditPage`）统一落盘。

| 机制 | 说明 |
| --- | --- |

#### 字幕层（overlay）

mpv 侧同时设 `sub_auto=no` / `sid=no`，预览改由 Qt 自绘，样式字典与 ASS 渲染共用同一份，做到所见即所得。

#### 内嵌字幕

`subtitle_compose.build_command:65`：

```

-c:v copy -c:a copy -c:s srt          # mkv → srt
```

**不重编码**，因此秒级完成。硬烧录或带独立音轨的场景走 `merge_pair`（`agent_cli.cmd_compose:647`，`--mode soft|burn|mkv`）。

⚠ 两条合成路径的分工必须分清，否则会误以为「程序不能硬烧录」：

| 路径 | 实现 | 是否重编码 | 用途 |
| --- | --- | --- | --- |
| 编辑页「内嵌字幕」 | `subtitle_compose.build_command` | **否**（`-c:v copy -c:a copy`） | 秒级挂轨，只做流复制 |
| CLI `compose --mode burn` | `agent_cli.cmd_compose` → `merge_pair` | **是**（重编码） | 需要烧进画面时 |
| CLI `compose --mode mkv` | 同上 | 否 | 封装进 MKV |

编辑页不做硬烧录是**刻意选择**：在 GUI 线程里对全时长视频重编码，既卡界面又极易触发 ffmpeg 超时中断。需要烧录时走 CLI 或流水线，由后台子进程承担。

### 4.6 流水线域

#### 职责

把「下载 → 翻译 → 校准 → 成品」串成无人值守的链，支持两种起点：**链接任务**（粘贴链接）与**目录任务**（监视下载目录，下载完成即接链）。核心要求是**断点幂等**——重启后不重复劳动、不产出半成品。

#### 状态机

```
状态：WAITING → READY → RUNNING → DONE
                        └→ FAILED（停住该 job 的链）
                        └→ SKIPPED（可选阶段被判定无需执行）
```

六个阶段（`pipeline.py:69-75`）：

| 阶段 | 内容 | 可选 |
| --- | --- | --- |
| `download` | 下载素材 | 否 |
| `merge` | 音画合并 | 否（仅 `CHAIN_WATCH` 链有） |
| `translate` | 机翻 | **是** |
| `calib1` | 脚本校准 | 否 |
| `calib2` | AI 二次校准 | **是** |
| `package` | 成品落盘 | 否 |

两条链（`:82-85`）：`CHAIN_LINK`（链接任务，无 merge）、`CHAIN_WATCH`（目录任务，含 merge）。

#### 断点幂等

| 机制 | 实现 | 说明 |
| --- | --- | --- |
| 状态持久化 | `data\pipeline_state.json` | 原子写 |
| 重启恢复 | DONE 跳过、RUNNING 复位为 READY | 避免「重启后卡在 RUNNING」 |
| 产物复用 | 输入指纹 `<out>.src.json`（`_fingerprint:107` / `_reusable:121`） | 输入未变则直接复用产物 |
| AI 校准续跑 | `ckpt.tsv` / `ckpt.done` | 块级断点 |

#### 事件契约

`_Emitter.state_changed`（`:1139`，`Signal(object)`）+ `add_listener`。payload 的 `type` 取四个值：

| type | 含义 |
| --- | --- |
| `auto` | 自动调度状态变化 |
| `workers` | 工作线程数变化 |
| `log` | 阶段日志行 |
| `jobs` | job 列表快照 |

**阶段执行体只能拿到 `Ctx`**（`:1096`），它提供 `log` / `progress` / `ffmpeg` / `proxy` / `ai_enabled` 五项能力——这是刻意的能力收窄，阶段实现不能直接摸全局状态。

#### 并发与调度

| 项 | 值 / 规则 |
| --- | --- |
| 并发上限 | `max_workers` 1~8，默认 3 |
| 调度泵 | `_pump:1574` 在锁内清理死线程、取队列、置 RUNNING、起线程 |
| ⚠ 释放顺序 | `_run_stage:1609` 的 finally **先释放槽位再补泵**——顺序反了会卡死（已记录 bug） |
| 失败重试 | **无自动重试**。FAILED 即停住该 job 的链，需 `retry(jid, stage)`（`:1803`）人工点火 |

#### 成品落盘

`_stage_package_run:479` 的规则：

- **不另建「成品」目录**，直接增量写回下载时生成的原视频文件夹；
- 字幕经 `_to_translate_on_top:468` 重排为**译文在上**；
- 命名 `【字幕】名-谷歌翻译.srt`；
- **已存在的文件不覆盖**。

#### 失败模式

| 现象 | 处理 |
| --- | --- |
| 下载 CDN 过期 | 阶段内部自带 4 次重试 + NPE 兜底 |
| 字幕已是中文 | `translate` 阶段抛 `SkipStage` |
| AI 校准 cue 表为空 | `calib2` 阶段抛 `SkipStage`（非失败） |
| 某 job 失败 | 隔离到当前 job，不污染其他 job 的链 |

### 4.7 声纹域

#### 职责

服务端 ASR 只回 `[说话人N]` 标签，既不给声纹向量也不回传音频——所以要「只出主播字幕」，判定必须放在本地。本域做两件事：**录入主播模板**、**按模板筛字幕**。

#### 技术路线

| 项 | 内容 |
| --- | --- |
| 模型 | 3D-Speaker CAM++ ONNX，输出 192 维向量 |
| 特征 | **纯 numpy 复刻的 kaldi 兼容 fbank**（povey 窗 / `snip_edges=False` / `high_freq=-400`→7600Hz） |
| 不引入 | torch / librosa（体积与启动成本不可接受） |
| 模型体积 | 27MB，按需下载，**不进安装包** |

#### 判定链

```
gate_speech_runs:1240（频谱门控，跳过静音段）
  ├─ 有 [说话人N] → score_by_speaker:1911（按簇打分）
  └─ 无标签     → cluster_cues:2016（本地聚类）
        → decide:2186（keep / review / drop 三分支）
        → filter_srt:2217（保留 + 写复核报告）
```

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `DEFAULT_THRESHOLD` | **0.55** | 判定为同一人的下界 |
| `DEFAULT_LOW` | **0.45** | 存疑区下界 |
| 存疑区行为 | 默认**保留**待人工 | 宁留勿杀 |
| 多模板 | **并集**——与任一模板够像即算主播 | 启用名单 `data\voiceprint\selection.json` |

⚠⚠ **阈值取值的依据**：同人实测最低 0.681、异人实测最高 0.450，取中点 ≈0.566 上取整为 0.55；存疑区下界取异人实测上限 0.45。存疑区要**窄且贴着决策边界**，不能一路宽到「看起来还行」——初版宽区间曾把官方中文旁白聚成一簇（相似度 0.390）并保留，用户看到的是「依旧多人混合输出」。

⚠⚠ **长音频分块推理**：`EMBED_MAX_FRAMES=6000`（100 帧/秒 ⇒ 60 秒/块）。onnxruntime 跑 CAM++ 的内存随时长**线性**增长（≈2.2MB/秒：1200 秒≈2.7GB），十几分钟素材在低内存机器上直接 `bad allocation`。分块后峰值内存封顶 0.34GB 且与时长无关。

⚠ 分块的数学约束：**全局均值必须在分块前对整段减**。各块分别减均值会让每块直流偏置不同，与单跑产生系统性偏差。

#### 界面集成

- 转录完成后自动接声纹筛选，`voiceprint_filter_subtitle()` 就地覆盖前**先备份** `<名>_未筛选.srt`（筛选是启发式的，误杀还能拿回全文）；
- 跑在 `QThread`（18 分钟素材约 27 秒，同步会冻界面）；
- ⚠ worker 必须挂 `iface._vt_vp_worker` 防 GC。

#### 多用户同步（独立通道）

`voiceprint_sync.py`（1078 行）与校准知识同步**完全隔离**：

| 项 | 规则 |
| --- | --- |
| 命名空间 | `vp_inbox\`（校准用 `inbox\`），互不可见 |
| 幂等 | 条目 `uuid5` |
| 生效集 | 全部收件箱按 `(ts, id)` 重放 |
| 折叠 | 同 key 按向量加权并集（`fold_leaves:294`） |
| 删除 | tombstone 需**指纹一致**才允许删 |

### 4.8 自动化与投稿域

#### 职责

驱动**用户自己已登录的浏览器窗口**完成 B 站投稿：抓帧 → 识别 → 声明式任务 → 鼠标键盘注入。不碰目标进程内存、不注入脚本、不接管浏览器（因此不需要 UIA / CDP / Playwright）。

#### 视觉引擎（四段式）

`auto_vision_core.py`（1208 行），参考 MAA 的四段设计：

| 段 | 函数 | 内容 |
| --- | --- | --- |
| ① 感知 | `list_windows:95` / `capture_window:159` | 枚举窗口、抓取客户区 |
| ② 识别 | `match_template:345` / `match_color:441` | numpy FFT 归一化互相关 / 颜色匹配 |
| ③ 任务 | `parse_pipeline:521` + `PipelineRunner:592` | 声明式管线解析与执行 |
| ④ 动作 | `click:900` | `SendInput` 绝对坐标注入 |

动作集：`ClickSelf` / `Click` / `TypeText` / `Key` / `Scroll` / `Wait` / `Activate`，另有 `None` / `JustReturn`（恒命中）算法。管线字符串统一支持 `{{变量}}` 替换；`maxTimes` 是**真重试**（每次重新抓帧，配合 `preDelay` 即「等元素出现」），`exceededNext` 做熔断。

⚠⚠ **`INPUT` 结构必须用 union**（鼠标/键盘共用 40 字节），否则 `SendInput` 整批拒绝、键盘注入**静默失效**。

#### ⚠⚠ 性能硬约束

这些数值都是实测值，写在源码注释里。它们决定了「为什么主题不能这么改」。

| 事实 | 数值 | 推论 |
| --- | --- | --- |
| `app.setStyleSheet` 单次耗时 | **3~13 秒，且与内容大小无关**（空表同样贵；同内容第二次 0ms） | 这是 Qt 全应用 re-polish。**主题切换绝不重设 app 级表** |
| `setTheme` 全量 vs lazy | 43 秒 → 亚秒 | 必须走 `lazy=True` |
| 逐控件刷新 vs 全量 | ~30ms vs 355ms | 全局规则一律逐控件化 |
| 冷缓存首轮 | ≈1.8 秒 | 首帧前有预热价值 |
| `renderQss` 缓存 | LRU 128 | — |
| 合并 QSS 体积 | ~29KB，按选择器切片 | 只补给用到的控件类 |
| `set_accent` | lazy ~5ms vs 全量 ~800ms | 改色走 `setThemeColor(lazy=True)` |

实现要点：

- **普通 Qt 控件**（非 vt_fluent 注册控件）的 accent 走 `ui_theme.plain_accent_qss:469` + `_PlainAccentFilter:651` 全局 Polish 钩子 + `refresh_plain_accent:542`；该机制**明确排除** vt_fluent 注册控件（`:479-481`）。
- lazy 改色后，dirty-qss 由 `DirtyStyleSheetWatcher` 在首绘前补齐，不会出现旧样式帧。
- ⚠⚠ **逐控件表必须过 `renderQss`**：直接拼字符串会把 `--Token` / `--FontFamilies` 直通给 Qt，造成大面积视觉回归。
- ⚠ **QSS 切片只补给容器类**（`_NATIVE_HOST_CLASSES`）：原生子控件（QScrollBar / QHeaderView / QAbstractItemView / QWidget…）的规则若直接下发，滚动条箭头会露出来。
- ⚠ `updateStyleSheet` 的 lazy 判定必须先 `isinstance(widget, QWidget)`（`QApplication` 没有 `visibleRegion`）；lazy 分支**不得再 register**（会套娃 compose）。

### 6.1 字幕文本契约

字幕是全程序的核心数据形态，改动写入逻辑前必须遵守四条：

| 约束 | 内容 | 违反后果 |
| --- | --- | --- |
| 结构原样 | 序号、时间轴、空行、换行符、BOM **全部保持输入原样** | 播放器识别失败或时间轴错位 |
| 换行符 | 跟随输入（多数为 CRLF），不强制转换 | 逐行 diff 全红，人工复核成本剧增 |
| BOM | 输入有 BOM 则输出保留 | Windows 播放器中文乱码 |
| 编码 | 统一走 `core\shared\textio.py`（UTF-8 / GBK / ASCII 通吃） | 遇到 GBK 字幕直接崩 |

**双语排版**：`SubtitleLayoutEnum` 控制顺序，默认原文在上。流水线成品会重排为**译文在上**（`_to_translate_on_top:468`）。

**行宽约束**：AI 校准侧 `MAX_LINE_WIDTH=32`；脚本侧 `--layout` 模式在 ≥14 字时于标点处拆两行，断点不切括号、不落在官方专名内部。

### 7.4 路径解析

#### 三个根

| 根 | 解析规则 | 出处 |

### 9.1 构建环境

构建**不在仓库目录里跑**，而是在一个 ASCII 路径的独立构建根里跑。

| 项 | 值 | 原因 |
| --- | --- | --- |
| 构建根 | `D:\Agent Work\_bld\qt_build` | 与仓库解耦，产物不污染工作区 |
| 链接 | `D:\Agent Work\_vt_build`（junction） | 短路径便于命令行 |
| 驱动脚本 | `scripts\dev\_build_onefile.py`、`scripts\dev\_build_inno.py` | 2026-10-21 收编进仓库 |

### 10.3 版本打标与文件清单

体系由两个脚本构成，互为校验：

| 脚本 | 作用 |
| --- | --- |
| `stamp_versions.py`（392） | 给自研当前版本文件首行打 `@version <版本>` 标记，并生成根目录 `文件版本清单.md` |
| `apply_version.py`（169） | 一键同步版本号（幂等），改号后自动调用 `stamp_versions.py` |

**清单口径**：`文件版本清单.md` 列出的是 **git blob SHA-1**（经 git filters 归一化，`core.autocrlf=true` 下 CRLF 已转 LF），与 GitHub 上同名文件的 blob sha **同口径、可直接比对**。普通 `sha1sum` 的值与此**不相等**，不能拿来比。

⚠⚠ `apply_version.py` 会把 `src\video_toolbox_qt.py` 与两份说明书**转成 LF**——改号后必须手动转回 CRLF（或跑 `_eol_normalize_worktree.py`）。这是本项目最容易在无意中破坏的约定。

### 附录 B：术语表

| 术语 | 含义 |
| --- | --- |
| **ASR** | 自动语音识别，本程序中指「音频 → 带时间轴字幕」 |
| **cue** | 字幕条目，一条 = 一段起止时间 + 文本 |
| **双语字幕** | 同一条 cue 内上下两行（原文 + 译文） |
| **校准** | 名词级原位替换，只改文字不动时间轴 |
| **错形** | ASR 或机翻产生的错误写法（如 `Endfield` → 「恩德菲尔德」） |
| **正形 / canonical** | 官方正确写法 |
| **参考行** | 字幕中未经翻译的原文行，用作校准的上下文证据 |
| **锚点（ctx）** | 校准规则的上下文条件，`(锚, 错形)` 二元组 |
| **侧车（subfix）** | 逐 cue 修正的旁路通道，不改主术语表 |
| **稳定化（stabilize）** | cue 级别的丢弃 / 合并 / 拆分，解决时间轴碎裂与重叠 |
| **声纹** | 说话人身份特征向量（本程序为 192 维） |
| **流水线阶段** | 六阶段之一：download / merge / translate / calib1 / calib2 / package |
| **接缝（seam）** | 可替换的模块边界，用于分阶段替换第三方引擎 |
| **facade** | 对外统一入口模块（`video_toolbox.py`） |
| **惰性外壳** | 首次访问才构造真身的页面代理 |
| **降级开关** | `VT_NO_*` 系列环境变量，用于排障时剥离功能 |
| **平铺资产** | GitHub Release 里不带目录层级的 zip 文件 |

### 附录 D：运行侧排障速查

| 症状 | 首要怀疑 | 处理 |
| --- | --- | --- |
| 启动白屏 | `applyAppStyleSheet` 时序被改 / QSS 缺失 | 查 `logs\startup.log`；确认 `vt_fluent\_qss` 在包内 |
| 界面按钮点了没反应 | 零参 lambda 在冻结包抛错 | 改 `lambda *_:`；查 `logs\crash.log` |
| 错误气泡刷满界面 | `FIF.X` 图标未登记进 `USED` | 跑 `_check_vt_fluent_icons.py` |
| 切主题后颜色不统一 | 逐控件 accent 表未刷新 / 有硬编码色 | 跑 `_probe_theme_switch_guard.py` |
| 切主题卡顿数秒 | 有人重设了 app 级样式表 | 见 5.5 性能约束，改走 lazy |
| 机翻全部失败但网络正常 | `cache.db` 损坏 | 见 6.5，删除缓存后重试 |
| 下载报 `EOF ... SSL` | 下载中途换了代理节点 | 节点锁定失效，查 `logs\mihomo.log` |
| 下载永远 0 配对 | 视频扩展名不在 `MERGE_VIDEO_EXTS` | 见 4.1，三处同步 |
| 声纹筛选「什么都没发生」 | worker 被 GC | 挂到 `iface._vt_vp_worker` |
| 声纹 `bad allocation` | 长音频未分块 / 内存不足 | 确认 `EMBED_MAX_FRAMES` 生效 |
| AI 托管「没有产出最终答复」 | node 版本 < 22.19 静默退出 | `node --version` 核对 |
| 安装版 ImportError，源码正常 | 顶层模块漏进 iss | `check_iss_sources.py` + 补 iss |
| 退出后程序反复重启 | 退出同步回退到 `sys.executable` | 见 B7，用 `system_python()` |
| 页面把窗口最小尺寸钉住 | sizeHint 撑大 | 跑 `_probe_window_resize.py` |
| 校准改了没生效 | 被 `applied.json` 回灌覆盖 | 见 4.4 戒律 C5 |
| 日语片校准全失效 | 忘了 `--ja` | 见 4.4 戒律 C1 |
