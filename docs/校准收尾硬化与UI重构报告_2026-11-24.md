## 1. A · 不动点非收敛根因与修复

### 1.1 现象定位
`calib_ai_agent.py` 8c 段对部分片报 `fixed_point=False`。用 `data/tmp/p3_idem.py` 对 A/B 产物（353 例）再跑一遍引擎逐例比 SHA：**仅 1 例非幂等**——`corpus_wuwa36__pgr-en`，20 处差异全是 `term` 规则，模式「超频演算 → 超频演算演算」。

### 1.2 根因
- `PGR_EN_TERMS: '超频' → '超频演算'`：**错形是官方名的子串**。
- 术语主路径（`replace.py::_replace_report` / `acindex.py::replace_serial_ac` / `ModeIndex.replay_serial` / `calib_entity/index.py::replay_serial`）是裸 `str.replace`：第一遍「超频→超频演算」，第二遍「超频演算」里的「超频」再命中 → 每跑一遍多一个「演算」。
- ctx 路径 `_ctx_replace` 早有哨兵保护（wrong in right 时先保护已有 right），**术语路径没有**。
- 静态扫描（`p3_a_scan.py`）：23 张术语表里自子串规则 7 条（ark.PGR_EN_TERMS 超频→超频演算；bilingual 血与净雨→罪血与净雨、先约电台→鸣潮先约电台；endfield 热队→灼热队、在前作，罗德岛→华法琳在前作，罗德岛；ko.KO_ASR_TERMS 랑자랑→방랑자랑；misc.REACT_TERMS 先约电台→鸣潮先约电台），按模式并表可达 5 条；跨条目二次命中隐患 2 条（血债与净雨→罪血与净雨 与 血与净雨→罪血与净雨 的级联，同根）。

### 1.3 修复
- `src/calib_core/replace.py` 新增 `_apply_pair(text, k, v)`：`k != v and k in v` 时走 `_ctx_replace`（哨兵保护），否则 `text.replace`。`_replace_report` 改用它；**无实际改动且 k≠v 时不计命中**（已完整的官方名既不叠字也不虚报命中）。

- `_check_term_hazards`（inspect terms-check / sync 远端条目门禁）**刻意未改**——自子串规则运行期已安全，加进去会让 sync 误拒。

## 2. B · `_verified_hit` 覆盖率守卫

- 新增 `_VERIFIED_COVER_MIN = 0.6`：扫描佐证片段时累计 `covered = ∪(changed ∩ [i,j))`，`best` 取最长；**`not best or len(covered) <= 0.6*len(changed)` 返回 ""**。
- **刻意用严格大于**（任务给的 `>= ceil(0.6*n)` 对 3/5 会放行）：「余烬燃起→永明的烈焰燃起」只佐证前缀「永明的」（3/5）**挡下**；「卡提希娅很强！」2/3 **放行**；一行两个官方名各自佐证并集 3/3 **放行**；W1 原例「永明官员的余烬→永明的烬焰」changed={4} 1/1 **放行**；「永明的烈焰」仍拒。
- 召回权衡：阈值 0.6 下 W1-① 14 例无回归（`_selftest_calib_ai.py` 全套 235 OK / 0 FAIL，含 2b 段新增 5 个 check：半佐证拒 / 完整佐证放行 / 两名并集 / 名+标点 / 常量=0.6）。若线上出现「长名只差尾字」被误拒，优先降阈值到 0.5 而不是回 0。

## 3. C · 会话固化（VT_SESSION_PROMOTE）安全评审与建议

**现状**：`_promote_session_canonicals`（calib_ai_agent.py:2089）仅 `VT_SESSION_PROMOTE=1` 时执行：取 confidence ≥ 0.85 的 A 级条目 → 追加 `Entity(...)` 到真源 `src/calib_core/data/entities_part2.py` 尾部 → `py_compile` → 重建 monolith + `CHECK OK`；任一步失败回滚真源并重建旧版。撞名审查只比对 canonical（`Entity("…"` 正则）。

**风险点（默认开启时）**
1. 真源是**共享知识库**的一部分：一条错固化的「官方名」会随知识同步通道扩散到所有安装，且回滚只覆盖本次进程，重启后无痕。
2. 置信度是 Agent **自评**（无独立复核），W1 类「半佐证」刚被 B 守卫挡在采纳闸门外，固化路径却没有同等证据门槛。
3. 撞名审查只查 canonical，不查 variant：同 variant 挂到两个 Entity 的冲突只在 merge 阶段识别，构建期不拦。
4. 写入与重建非原子：cancel/崩溃落在「真源已写、monolith 未重建」之间，下次 `--check` 必失败；两个并发 GUI/CLI 同时固化无锁。
5. 打包版无 `scripts/dev/` 与 `src/`，自动跳过（安全），但功能等于不存在。

**建议：保持关（env-gated），下一轮做半自动**
- 本轮不暴露界面开关（`calib_session_promote` 不进三处），日志已提示「设 VT_SESSION_PROMOTE=1 可当轮写入真源+重建」。
- 半自动路径：A 级条目自动写入**模式侧车 TSV**（`data\calib_sidecars\`，用户本地、运行期装配、无需重建、不进共享真源）；界面「固化为真源」按钮走 `--dry-run` diff（canonical + variant 双向撞名）→ 用户确认 → 复用现有原子流程（写→compile→build→check→rollback）+ 文件锁。

## 6. 性能回归修复（本轮新发现，归入收尾硬化）

- **现象**：任何校准 CLI 入口（GUI 脚本模式子进程、AI 基线/audit/verify 每次 `run_script`）固定多耗 **~55s**，与片长无关。
- **根因**：P2-4d 把 `_learn_canonicals()`（＝重建整张 `_kb_view`，~0.1s）放进 `_sync_apply_learned_batch` 的**逐条循环**；`applied.json` 762 条 ⇒ 762×0.1s；`_cmd_kb_sync` 与 `_sync_inject_all` 各跑一次 `_sync_apply` ⇒ 再翻倍。自检因 `CLI_ENV` 设 `VT_NO_SYNC=1` 不走此路径，故上一轮未暴露。
- **修复**（`src/calib_core/sync.py`）：① `_cons = _learn_canonicals()` 提到循环外算一次（既有官方名集合只取决于静态表 + ENTITIES，批内不变；`learn.py` 本地 learn 本就是批内算一次传 `canonicals=`）；② `_sync_apply` 的「内建表保护」告警由逐条 `_sync_log`（每条 open/append/close，1080 条 ≈ 6s）改为收集后 `_sync_log_batch` 一次落盘（行格式不变，同批共用秒级时间戳），汇总行追加「内建表保护挡下 N 条」。
- **效果**：同一文件同一模式 **55s → 9.5s**；不动点 SHA 不变（自动同步注入的规则集未变，只是算得快了）。
