## 一、项目概述

**视频工具箱**（VideoToolbox）是一个 Windows 桌面视频工具集，基于 PyQt5 + PyQt-Fluent-Widgets 构建，主要能力：

- **视频下载**：调用 yt-dlp / ffmpeg 下载 YouTube、B 站等站点视频，自动检测画质、下载字幕、打包独立文件夹（视频 + 1280x720 封面 + 信息 txt + srt）；
- **视频库**：本地视频扫描，缩略图卡片浏览与播放；
- **音视频智能合并**：按文件名与时长自动配对 mp4 + m4a/weba + srt/ass 并合成；
- **字幕处理**：内嵌开源字幕引擎 VideoCaptioner v1.4.2（GPL-3.0）提供转录 / 优化 / 翻译 / 配音 / 合成；
- **字幕校准**：调用自研术语库脚本 `subtitle_calib_merged.py` 做名词级原位校准；可选 **AI 校准（Agent 级）**，由大模型逐块复校残留错形（`src\calib_ai_agent.py`）；
- **全局 AI（单通道）**：一套 OpenAI 兼容地址 / 密钥 / 模型，供工具箱、字幕引擎优化翻译、AI 校准共用；另可单独配置 **ASR 语音识别**（自有服务或本地独立模型）；
- **校准知识同步**：两套并存 —— 引擎侧 GitHub 文件级并集同步（启动拉取 / 退出推送），以及脚本侧 v1.11.0 起的**条目级增量日志通道**（哑远端 + 收件箱，管理员用 `kb_admin.py` 运维）。

技术栈：Python 3.12（内嵌运行时）、PyQt5、qfluentwidgets、yt-dlp、ffmpeg、VideoCaptioner、mihomo（内置代理）、Qt Installer Framework / Inno Setup（打包）。

## 三、运行方式

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 图形界面（推荐） | 双击 `视频工具箱.exe` | 打包产物，免 Python，顶层唯一可执行文件 |

> 未签名提示：exe 未做代码签名，开启 Device Guard / 应用控制策略的电脑可能拦截，此时请改用脚本方式运行。

- **用途**：Git 忽略规则，声明哪些文件不入库。
- **使用说明**：直接随仓库维护，无需手动操作。新增敏感或大体积文件时按注释分组追加条目。
- **关键忽略项**：

  - 大体积 / 可再生物：`tools\python\`、`tools\videocaptioner\`、`tools\mihomo\`、`tools\ffmpeg.exe`、`tools\yt-dlp.exe`、`tools\deno.exe`、`dist\`、`installer\*.exe`、`installer_repository\`、`.buildvenv\`、`build_ascii\`（PyInstaller ASCII 工作目录）；
  - 运行期产物：`data\config.json`、`data\calib_sync\`、`data\calib_sync_remote\`、`data\calib_sync_base.py`、`data\calib_sync_kb_base.json`、`data\_kb_probe.json`、`data\thumb_cache\`、`data\tmp\`、`logs\`（整目录）；
  - 历史大体积留档：`history\build\`、`history\logs\`、`history\data\`、`history\old_builds\`。
- **备注**：v1.12.0 曾因 `git add -A` 把 `data\_kb_probe.json`、`data\calib_sync*` 误入库，已 `git rm -r --cached` 并补规则（提交 `94ea6f7`）。

### 4.2 `deploy_installer_ghpages.py`

- **用途**：把 `installer_repository\`（在线安装器组件仓库）部署到 GitHub 仓库 `09Th90/VideoToolbox` 的 `gh-pages` 分支并启用 GitHub Pages，供在线安装器远程拉取组件。
- **使用说明**（命令）：
  ```bat
  gh auth login                 :: 前置：完成 GitHub 登录，脚本从 gh keyring 取 token
  python deploy_installer_ghpages.py
  ```
- **可选环境变量**：`VT_REPO_DIR` —— 仓库根目录覆盖（脚本被复制到其它位置运行时用）。
- **原理**：走 GitHub Git Data API（curl 直连 api.github.com），直连持续 401/5xx 时自动回退内置 mihomo 代理（仅代理 GitHub 域名）；`gh-pages` 分支只含安装器仓库内容，不污染 `main`。
- **备注**：需要 `09Th90/VideoToolbox` 仓库的写权限；完成后在线仓库地址为 `https://09th90.github.io/VideoToolbox/`。

### 4.3 `github_proxy.yaml`

- **用途**：本机 GitHub 专用代理配置（FlClash / ClashMeta / mihomo 格式）。规则已精简为**只代理 GitHub 相关域名**（github 关键字、ghcr.io、gh.io），其余流量全部直连。
- **使用说明**：导入 FlClash → 配置 → 导入本文件 → 在代理组 SELECT 中手动选择节点（或 AUTO 自动选优）。用于解决本机网络访问 api.github.com / GitHub Releases 不稳定问题。程序侧亦可用「设置 → 目录 → 代理配置」指向本文件（写入 `data\config.json` 的 `proxy_yaml`）。
- **⚠️ 安全提示**：本文件**含代理节点 UUID、密码、secret 等敏感凭据**，已在 `.gitignore` 中排除，严禁提交到任何仓库或随包分发。本文档不展示其具体凭据内容。

### 4.4 `subtitle_calib_merged.py`

- **用途**：字幕校准统一脚本（唯一入口）。对 SRT 做**名词级术语原位校准**：只替换中文行术语，严格保留序号、时间轴、空行、换行（CRLF/LF）与 BOM 一字不变。由「字幕校准」页面以 `tools\python` 子进程调用，也可命令行直接使用。
- **使用说明**：
  ```bat
  :: A. 术语校准（按片源模式）
  python subtitle_calib_merged.py <输入.srt> [--out 输出.srt] [--report 对照.md]
       [--bi|--ja|--jpe|--ko|--ak|--akko|--endo|--zho|--pgr|--pgren|--wwoc|--react]
       [--fix-en] [--kb 学习库.json]
  :: 不传 --out 只做术语命中统计，不改写文件；默认输出「原名.calib.srt」，绝不覆盖原字幕

  :: B. 流水线子命令
  python subtitle_calib_merged.py extract   <源.srt> <cues.tsv>          :: 抽 cue 表
  python subtitle_calib_merged.py split     <cues.tsv> <前缀> --n 6      :: 切分段并行校准
  python subtitle_calib_merged.py merge     <源.srt> <表|目录> --out 输出.srt [--compare 对照.tsv] [--side 覆盖.tsv]
  python subtitle_calib_merged.py verify    <源.srt> <输出.srt>          :: 校验结构零改动
  python subtitle_calib_merged.py compare   <源.srt> <输出.srt> <对照.tsv>
  python subtitle_calib_merged.py scan      <cues.tsv> [--min 2]         :: 扫描高频英文词
  python subtitle_calib_merged.py subfix    <源.srt> <fix.tsv> --out 输出.srt
  python subtitle_calib_merged.py terms-check [表名...]                  :: 术语表二次命中自查

  :: C. 对象级知识库（ENTITIES + 学习系统）
  python subtitle_calib_merged.py kb-export [--json] [--out 路径]        :: 导出知识库
  python subtitle_calib_merged.py kb-lookup <词>                         :: 反查实体全部知识
  python subtitle_calib_merged.py kb-lint                                :: 对象级体检
  python subtitle_calib_merged.py learn <原始.srt> <人工校准.srt> [--mode bi]
  python subtitle_calib_merged.py learned-show / learned-promote / learned-reject

  :: D. 条目级增量同步通道（v1.11.0；默认，详见 docs\校准知识增量同步_管理员手册.md）
  python subtitle_calib_merged.py kb-baseline-init   :: 管理员：由内置知识生成首版 baseline
  python subtitle_calib_merged.py kb-sync            :: 拉取+合并+三道门+应用（校准入口自动执行，幂等）
  python subtitle_calib_merged.py kb-push            :: 导出/上传本次增量（learn 收尾自动调用）
  python subtitle_calib_merged.py kb-compact         :: 管理员压缩：折叠增量进新 baseline
  python subtitle_calib_merged.py sync-status        :: 本机状态：client_id / 水位线 / 生效 / 冲突 / 日志
  python subtitle_calib_merged.py selftest-sync      :: 验收 1-7 + NFR-1/2/5 自动化断言
  ```
- **内部结构**：`BILINGUAL_TERMS`（中英双语专名表）、`CONTEXT_MAP`（上下文佐证规则）、`WORD_MAP`（机翻错词）、`KO_TERMS / JA_TERMS / JA_ENDFIELD_TERMS / ENDFIELD_TERMS / AK_TERMS / PGR_EN_TERMS / ZH_ONLY_TERMS` 等按模式分离的术语表，以及对象级 `ENTITIES` 知识层与第 8 节增量同步实现；新对照统一以 `Entity` 追加进第 6 节，勿另建平行脚本。
- **备注**：算法为「术语表预编译 + 单遍替换」；学习库默认文件名为 `subtitle_learned_kb.json`（cwd 存在时自动加载）。自带 `_decode_any`（UTF-8/GBK 等智能解码），GBK 字幕不再崩、输出规范化为 UTF-8。本文件同时是「校准知识同步」的同步对象。回滚开关：`VT_SYNC_MODE=legacy` 整体退回 v1.10.7 行为，`VT_NO_SYNC=1` 强制关闭增量通道。

### 4.5 `subtitle_learned_kb.json`

- **用途**：字幕校准的**学习库**（JSON）：记录 `learn` 子命令从「原始字幕 ↔ 人工校准字幕」配对里挖出的「错形 → 正形」候选、频次、证据 cue、反例与状态（candidate / confirmed / rejected）。
- **使用说明**：无需手动编辑；`learn` 写入、`learned-show` 查看、`learned-promote` 导出 Entity 桩代码、`learned-reject` 人工否决。校准运行时若当前目录存在本文件会自动加载（也可 `--kb` 显式指定）。
- **备注**：v1.11.0 起，远端 confirmed 候选会在 `kb-sync` 时自动注入本文件；`local_log\` 存离线补传增量。**v1.12.1 起本文件不再入库**——程序运行期会持续改写它，若纳入 git 会让仓库常驻「已修改」状态（曾因此在版本核验里被误判为「同名不同内容」）。`.gitignore` 已加入 `subtitle_learned_kb.json`；程序首次运行时按需自动创建，缺失不影响校准功能。

### 4.6 `kb_admin.py`

### 4.9 `文件版本清单.md`（v1.12.1 新增，自动生成）

- **用途**：**逐条核验「线上文件 = 当前版本代码」的清单**。由 `src\stamp_versions.py` 自动生成，列出仓库内**全部已跟踪文件**（当前 95 个）的：归类、`@version` 标记状态、git blob SHA-1、字节数。
- **四类归类**：**当前版本**（构成当前版本的自研代码 / 脚本 / 配置 / 文档）、**第三方 / 合规原件**（上游或法律原件，逐字节保持原样）、**历史归档**（`history\` 与早期版本留档）、**运行期数据 / 占位**。
- **SHA-1 口径（关键坑）**：清单列的是 **git blob SHA-1**（对 `blob <长度>\0<内容>` 计算，并经 git filters 归一化——`core.autocrlf=true` 下 CRLF 已转 LF），**与 GitHub tree API 的 blob `sha` 同口径**，可直接逐条比对。**普通文件 SHA-1（`sha1sum` 那种）与此不相等**，拿它去比会全部对不上（v1.12.1 写清单时踩过）。
- **怎么用**：拿 GitHub 上某文件的 blob `sha` 与本清单同名条目比对，一致即证明内容完全相同——**同名不同内容**（本地已改未推、线上仍旧版）这种肉眼查不出的问题，靠它一查就现。也可 `grep -rn "@version" .` 直接看每个文件属于哪一版。
- **使用说明**：不要手工编辑（会被下次生成覆盖）；版本升级时由 `apply_version.py` 自动重生成，也可单独跑 `cd src && python stamp_versions.py`。
- **备注**：清单自身不计入统计。`.vscode\extensions.json`（JSON 无注释语法）与 `docs\界面预览.png`（二进制）无法打标，但在清单里标注为「未打标：…」，不会漏掉。

### 5.4 `calib_ai_agent.py` —— AI 校准 Agent（v1.11.0 新增）

- **用途**：Agent 级字幕校准（无界面、无第三方依赖）。把「基于脚本 subtitle_calib_merged 校准字幕，不允许改变时间轴和格式，仅调整文字内容，一次读不完就自行拆分，最后合并」这套要求实现成可复用的流水线，供界面（`engine.calib_ai_run`）、命令行与自检脚本共用。
- **使用说明**（作为库引用）：
  ```python
  import calib_ai_agent as agent
  res = agent.calibrate(src, out="x.calib.srt", report="x.calib.md",
                        mode_flag="--ko", log=print, chat=my_chat, round_no=1)
  ```
  `chat(prompt, system=None, max_tokens=...) -> str` 由调用方注入（引擎走全局 AI 单通道）。
- **八步流程**：① 术语脚本基线（机械部分兜底）→ ② `extract` 抽取 cue 表（剥离时间轴）→ ③ `kb-export --json` 载入知识库并展开成「错形 → 官方名」规则 → ④ 自行分块（条数 + 字符预算双约束）→ ⑤ 逐块 LLM 复校（返回截断/超时自动拆半重试）→ ⑥ 证据校验（改动必须能被知识库解释；行数变化、整句改写、无依据改动一律拒绝并写报告）→ ⑦ 按 cue 边界合并回填（只替换中文行，序号/时间轴/参考行/换行/BOM 一字不动）→ ⑧ 独立校验（调脚本 `verify` 断言结构全一致，不通过即判失败）。
- **再次校准**：`round_no > 1` 时以本轮输出为输入再跑一轮，提示词要求只挑残留错形；界面按 `原名.calib.rN.srt` 命名。
- **备注**：自研 `parse_srt` / `rebuild_srt` 承担回填——脚本 `merge` 逐行读校准文本，**多行文本的续行会被丢弃且 `verify` 不报错**，故不依赖它。`hiddenimports` 需包含 `calib_ai_agent`（`engine.calib_ai_run` 内延迟导入，静态分析跟踪不到）。自检见 `_selftest_calib_ai.py`。

### 5.7 `push_via_git_api.py` —— GitHub 不可达时的推送通道（v1.12.0 新增）

- **用途**：本机 `git push`（走 github.com）直连与内置代理均不通，而 `api.github.com` 直连可用；本脚本用 **GitHub Git Data API** 把当前本地 HEAD 的完整文件树同步到远端分支，等价于一次 `git push`（内容级一致，不搬运 git 历史对象）。
- **使用说明**：
  ```bat
  cd src
  python push_via_git_api.py --dry-run     :: 只报告差异（必跑，先看差异集）
  python push_via_git_api.py               :: 真推送
  ```
- **流程**：取远端 `ref/heads/<branch>` → commit → tree(recursive) ↔ 本地 `git ls-tree -r HEAD` 逐文件比对 → 只上传差异 blob（`git cat-file blob <sha>` 取规范化字节 → base64）→ 建 tree（远端有而本地无的条目用 `sha:null` 删除）→ 建 commit（parent=远端 head）→ `PATCH /git/refs/heads/<branch>`（`force:false`，非快进即失败，绝不覆盖他人提交）。
- **三个必须记住的点**：① **所有 git 调用加 `-c core.quotepath=false`**，否则中文路径被转义成 `\344\275...`，与 API 返回的真实路径对不上会把远端中文文件全判为「待删除」；② **必须强制直连**（`build_opener(ProxyHandler({}))`），urllib 默认会走沙箱/系统代理并被 502 拦下；③ 先 `--dry-run` 再推。

### 5.8 `视频工具箱.bat` —— 脚本版启动器

### 5.12 `stamp_versions.py` —— 文件级版本标记与核验清单（v1.12.1 新增）

- **解决什么问题**：光看文件名无法判断一份文件属于哪一版——「本地已改未推送」「线上还是旧版」这两种情况，文件名完全一样，肉眼查不出来（v1.12.1 发布前实测就踩到：线上 `main` 有 9 个文件与本地同名而内容不同）。
- **用途**（两件事）：
  1. **首行打标**：给每个**自研当前版本文件**的首行插入统一标记行 `@version <版本>`，按文件类型套用该类型的注释语法（`.py/.spec/.ps1`→`# `、`.iss`→`; `、`.qs`→`// `、`.xml/.md/.html`→`<!-- -->`、`.bat`→`rem `、`.txt`→裸行）。插入位置会自动避让 `#!` shebang、`# -*- coding` 编码声明、XML 声明与 `@echo off`，保证不破坏语义。再次运行时按新版本号**原地改写**，幂等。
  2. **生成清单**：生成根目录 `文件版本清单.md`，逐条列出**全部已跟踪文件**的归类、`@version` 标记状态、**git blob SHA-1** 与字节数，用于与 GitHub 上的同名文件逐条比对（blob SHA 一致即内容相同，口径见 4.9）。
- **使用说明**：
  ```bat
  cd src
  python stamp_versions.py            :: 打标 + 重生成《文件版本清单》
  python stamp_versions.py --check    :: 只报告会改哪些文件（空跑）
  ```
- **刻意不打标的文件**（改动它们有害，不是遗漏）：
  - **第三方 / 合规原件**：`docs\VideoCaptioner_GPL-3.0.txt`（GPL 许可全文）、`docs\VideoCaptioner_组件来源.txt`、`docs\vc_prompts_official\*`、`docs\vc_translate_impl\*`、`build\Languages\ChineseSimplified.isl`。其中 prompts 会被当作**提示词投给 LLM**，插入注释会污染提示词；许可全文与组件来源声明属法律文件，必须逐字节保持原样。
  - **`history\` 历史归档**：本就是早期版本快照，标成当前版本是错的。
  - **运行期数据 / 占位**：`subtitle_learned_kb.json`、`inbox\`、`outbox\`。
  - **二进制 / 无注释语法**：`docs\界面预览.png`、`.vscode\extensions.json`（这些仍会进清单，标注为「未打标：…」）。
- **分类口径**写在脚本的 `THIRD_PARTY / HISTORY_* / RUNTIME_*` 常量里；清单生成时会**断言每个已跟踪文件都落进唯一一类**，新增文件不会被静默漏掉。

  启动后打印本机与局域网地址；把 `config.xml` 的 `<Url>` 指向 `http://<局域网IP>:<端口>/`，或直接用安装器的 `--set-temp-repository http://<IP>:<端口>/`（推荐，不改包）。
- **为什么重要**：在线安装器的默认源在 GitHub Pages，国内直连常只有几十 KB/s。走本机/内网源实测 **104MB / 约 1 秒（150 MB/s 级）**，是「自己装 / 同事内网装」的根治手段（配套脚本见 7.7）。
- **前置**：`installer_repository\Updates.xml` 必须存在（先运行 `build_online_installer.py`）。

### 7.3 `config\config.xml`

- **用途**：IFW 在线安装器总配置：安装名「视频工具箱 v1.12.0（在线安装）」、默认安装目录 `D:\VideoToolbox`、远端组件仓库列表、启动后运行主程序等。
- **仓库列表（多源，v1.12.0 起）**：`<RemoteRepositories>` 下按优先级排列——① 官方源 GitHub Pages（`https://09th90.github.io/VideoToolbox/`，`Enabled=1`）② 本机/局域网自建源 `http://127.0.0.1:8123/`（`Enabled=0`，需先跑 `repo_server.py`）③ 加速镜像位（由 `--mirror-url` 注入）。**下载时取第一个可用的源**，用户可在安装器「设置」页取消慢的、勾选快的。
- **使用说明**：`build_online_installer.py` 会把它复制到 `build\ifw_config\config.xml` 再按参数重写/追加源（源文件保持默认）；<Version> 由 `src\apply_version.py` 统一维护（**同一文件里 `<Version>` 只允许出现一次**，加源时别复制这一行）。
- **备注**：IFW 默认使用 Windows 系统代理（`--system-proxy`），这正是「开着代理软件时安装器会变快」的原因；亦可用 `--set-temp-repository` 在图形模式临时替换整个源。

### 7.4 `packages\com.videotoolbox.base\meta\package.xml`

- **用途**：主程序组件元数据（显示名「视频工具箱 主程序」、版本 1.12.0、发布日期、必装 `ForcedInstallation=true`、关联安装脚本）。
- **使用说明**：发布新版本时同步更新 `<Version>` 与 `<ReleaseDate>`（版本号可由 `src\apply_version.py` 一并同步）。

### 7.5 `packages\com.videotoolbox.base\meta\installscript.qs`

- **用途**：IFW 组件安装脚本（Qt Script），创建目录壳与快捷方式。
- **操作内容**：创建 `data\downloads`、`data\thumb_cache`、`data\videocaptioner` 目录；创建开始菜单 / 桌面快捷方式（主程序 + 维护工具=卸载入口）。

### 7.6 `installer_repository\`（产物，不入库）

- **用途**：`build_online_installer.py` 的组件仓库输出（`Updates.xml` + 各组件 `.7z` + `.sha1`），供在线安装器与 `repo_server.py` / `deploy_installer_ghpages.py` 使用。
- **使用说明**：由脚本生成，无需手动编辑；已在 `.gitignore` 排除。发布流程：`build_online_installer.py` → `deploy_installer_ghpages.py`（推到 `gh-pages`）。
- **体积参考（v1.12.0）**：共 104MB —— `1.12.0content.7z` 88.1MB（主程序 exe）、`1.12.0tools.7z` 15.5MB、`1.12.0{src,docs}.7z` 各 0.1MB。

### 7.7 `install_local_repo.py` —— 内网全速安装（v1.12.0 新增）

- **用途**：把在线安装器的下载源换成**本机/局域网仓库**，绕开 GitHub Pages 的国际链路瓶颈。原理是用 IFW 的 `--set-temp-repository <url>`（图形模式同样生效）把仓库地址临时替换，必要时顺带拉起 `repo_server.py`。
- **使用说明**（命令）：
  ```bat
  python installer_src\install_local_repo.py                        :: 本机源（自动起 repo_server，装完自动关）
  python installer_src\install_local_repo.py --port 9000
  python installer_src\install_local_repo.py --repo-url http://192.168.1.10:8123/   :: 用别人的内网源
  python installer_src\install_local_repo.py --file                 :: 直接用 file:/// 本地目录（不起服务）
  python installer_src\install_local_repo.py --dry-run              :: 只打印将执行的命令
  ```
- **行为**：自动定位 `installer\视频工具箱_在线安装_v*.exe`（取最新）与 `installer_repository\`；端口已占用则复用现有服务；起服务后用强制直连的探测请求确认 `Updates.xml` 可读再拉起安装器；安装器退出后关闭服务。
- **实测**：104MB 从本机仓库下载约 1 秒（150 MB/s 级），对比公网源 3 KB/s 的 5 小时级等待。
- **备注**：探测/等待一律用 `build_opener(ProxyHandler({}))` 强制直连——本机环境变量里的 `http_proxy` 会把 `127.0.0.1` 也送进代理导致 502。

### 13.2 打包环境与已知坑

- **必须用带 Qt 的构建环境**：`C:\bld\qt_build`（venv，Python 3.12 + pyinstaller + PyQt5 5.15.11 + PyQt-Fluent-Widgets 1.8.4）。系统 Python 没有 PyQt5。
- **必须从 ASCII 路径打包**：`C:\vt_build` 是项目目录的**目录联接（Junction）**，`workpath` / `distpath` 也用 ASCII 路径——PyInstaller 的 Qt 钩子在中文项目路径下会把 `QLibraryInfo` 返回的路径读成 `?????`（UTF-8 模式无效）。项目改名/搬家后联接会失效，用 PowerShell `New-Item -ItemType Junction` 重建（bash 里 `mklink` 会被安全策略拦）。
- **用 `python -m PyInstaller`**：`pyinstaller.exe`（entry-point 启动器）在本 shell 下会 1 秒静默退出。
- **覆盖旧 exe 前先挪到 `history\old_builds\`**：本机安全删除保护（safe-delete shim）每轮累计删除超 50 个文件会拦截批量删除；它在中文路径下会误报 `[safe-delete][SAFE_DELETE_FAIL_CLOSED] trash-failed`，**判断失败要复核文件是否还在**。
- **不要用静默安装验证安装包**：`/VERYSILENT` 覆盖式安装 1GB+ 极慢且易被文件占用卡死；内容验证改用「exe 自检 + iss 编译日志（各文件被 Compression 列出）」。
- **`sys.executable` 在冻结后就等于本程序 exe（v1.12.1 血泪教训，最严重的一坑）**：任何把它当「Python 解释器」去 `subprocess.Popen` 的地方，打包后都会**拉起一个新主程序实例**。v1.12.0 的退出同步正是这么写的，结果「点退出 → 程序反复重启」，并伴随 `Failed to remove temporary directory: _MEI***`（新旧实例互抢 `_MEI` 解压目录）与 `no Qt platform plugin could be initialized`（平台插件已被对方删掉）两个错误框；同时 `%TEMP%` 会残留一堆 `_MEI*`。**防线**：解析解释器一律走 `system_python()` / `_calib_py()` / `calib_ai_agent.resolve_python()`，并由 `_is_self_exe()` 兜底——拿不到真实解释器就**返回空串让调用方跳过，绝不回退到 exe**。排查手法：把 exe 当 zip 读 CArchive → `open_embedded_archive('*.pyz')` → `extract('<模块名>')` 拿到 **code object**（注意入口脚本在 CArchive 层、不在 PYZ 里），递归 `co_consts` / `co_names` 比对字符串指纹，即可判定某份 exe 出自哪版源码。
- **大文件不能用 Git Data API 推 gh-pages**：`content.7z` 87MB 经 base64 后请求体 117MB，GitHub 直接回 `422 Sorry, your input was too large to process`（blob 有体积上限，压缩已到极限也救不回来）。正解是 `build\ghpages_push\`（**独立 git 仓库**，已被 `.gitignore` 忽略）里 `git push origin master:gh-pages`——实测 3.4MB/s、100MB 约 40 秒。`deploy_installer_ghpages.py` 的 urllib / curl 通道只适合小文件。
- **后台任务的网络出口受限**：同一网络脚本丢到后台必然超时/被拦（401/422/504），在前台跑就成功。长任务别丢后台，改用「断点续传 + 分批」；GitHub 写请求走 `gh api`（Go 栈）在前台连续写最稳。
- **给文件加版本标记后要重打包**：`.py` 只加注释不改字节码，但 `subtitle_calib_merged.py`、`docs\*`、`installer_src\*` 这些**以独立文件分发**的内容字节会变，所以打标后必须重打 exe 与两个安装包，否则包内文件与仓库不一致。
- **wildcard Source 必须逐条确认 `Excludes`（v1.12.1 教训）**：`视频工具箱.iss` 里 4 处 `recursesubdirs` 的 wildcard，原先只有 `tools\python\*` 带了 `Excludes: "*.pyc,__pycache__"`，结果 `docs\vc_translate_impl\__pycache__\*.cpython-313.pyc` 被一起打进包（见 4.7）。**`__pycache__/` 在 `.gitignore` 里，所以 `git status` 永远看不到，仓库干净不代表包干净**——必须审计 ISCC 日志的 `Compressing:` 清单（顺手脚本：读日志抽 `Compressing: ` 行按可疑后缀过滤；注意日志换行可能是纯 `\r`，`^...$` 多行正则匹配不到，先 `\r`→`\n`）。
- **长编译（Inno / IFW repogen）必须在所有会进包的文件冻结后启动**：本轮曾在 Inno 编译途中改 `docs\程序说明书.md`，只能杀掉重来（半成品 <550MB 要删掉，正常约 574MB，别和新产物混在一起）。在线安装器 staging 的是**整个 `src\` 与 `docs\`**，这两个目录也必须先冻结。
- **git 长操作（fetch/clone/rebase/gc）一律后台跑**，且**绝不轻易 rebase**——本环境对长 git 任务易发 SIGTERM，中止的 rebase/gc 会摧毁 `.git/refs/` 并连带丢失对象；出现对象缺失时移走损坏 `.git` 后从远端重新 clone 到 **ASCII 原生路径**，再拷回工作区。克隆后必做 `git add --renormalize .`（`core.autocrlf=true` 会冒出大量纯换行符噪音的假 ` M`）。
