### 2) 与官方实现的一致性（外部基准）

拿 `kaldi-native-fbank` 当基准逐元素比对（14 条真人语音）：

| 指标 | 结果 |
| --- | --- |
| 高能量帧特征 `max|Δ|` | **0.0001** |
| 最终 embedding 余弦 | **> 0.999** |
| 同人相似度 min / mean | 0.681 / 0.783（官方 0.681 / 0.784） |

素材：3 位说话人各 2 段、交替出现共 21.6 秒的 mp4 + 带 `[说话人N]` 标注的 SRT；模板取自主播第 1 段。

```

  说话人2       ##########..................  0.242     2 条  6.2s
  说话人3       #####....................... -0.001     2 条  6.2s
```

筛选产物（只留主播，序号重排、时间轴原样保留）：

## 三、使用方式

```bat
:: 1) 先下模型（一次性，约 27MB）
python tools\download_open_source_deps.py --only speaker-model

:: 2) 录入主播声纹（从视频里截一段干净人声，10~30 秒最好）
python src\speaker_voiceprint.py enroll --src 视频.mp4 --start 12 --dur 20 --name 主播

:: 3) 先量分离度，确认阈值可靠
python scripts\dev\voiceprint_probe.py --src 视频.mp4 --srt 字幕.srt --ref-start 12 --ref-dur 20

:: 4) 筛选
python src\speaker_voiceprint.py filter --src 视频.mp4 --srt 字幕.srt --name 主播 --out 主播.srt
```

## 四、必须说清的边界

1. **重叠说话**（两人同时开口）时切出的是混合信号，相似度会掉、可能**误杀主播**。彻底解决要声源分离，而 `_asr_separate_audio` 目前**仍是占位接口**——这是最大硬伤，声纹解决不了。
2. **主播唱歌**会被判为「不像说话声」而误杀；纯 BGM 段则会被正确丢弃（BGM 不属于「说话人」，靠声纹不匹配被一并滤掉，**不是被「分离」出来**）。
3. **短 cue**（< 0.8 秒）单独提向量不稳，必须走 `score_by_speaker()` 聚簇。
4. **换麦 / 混响**会拉低相似度，建议多段录入 + 阈值可调。
5. 服务端**不开 diarization** 时没有 `[说话人N]` 标注，会退化为逐条 cue 打分（准确度下降）；探针的无 SRT 滑窗模式可用于这种情况下先看分布。
