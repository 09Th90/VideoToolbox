# 下载链路对比报告：v1.18.3 → 当前工作树

> 2026-10-14 生成。问题：用户称「v1.18 能正常下载，现在不行」。本文对比两个版本的下载链路，
> 找出真实差异。对比基准：`f9536c3`（v1.18.3，2026-10-09 20:16 发布）→ 当前工作树（HEAD 2026-10-14）。

## 结论

**下载链路代码没有回退；变化来自环境（浏览器侧加密升级 + 锁库 + 游客 cookie 失效）。**

## 一、代码对比（逐函数抽实现逐字比）

| 结果 | 函数 |
|---|---|
| **逐字相同（11 个）** | `_refresh_guest_cookies`、`_guest_cookie_args`、`ytdlp_proxy_args`、`cookies_file_status`、`cookie_file`、`cookie_browser`、`ensure_builtin_proxy`、`get_proxy_yaml`、`ytdlp_error_retryable`、`hls_alt_format`、`npe_cookie_file` |
| 不同（3 个，均为本周新增/强化） | `fetch_info_json`（加取消/登记 + cookie 失败自救）、`browser_cookie_probe`（重构成 `_browser_cookie_probe_raw` + 薄包装，命令不变）、`ytdlp_cookie_args`（120s TTL + browser 档预检门控） |

cookie 级联（`auto` → 自备文件 → 浏览器登录态 → 游客 cookie）行为一致。

GUI 侧：`_download_worker` 的 `opts` 块逐字相同；`YTDLP_DL_COMMON_ARGS`、`YTDLP_CHUNK_SIZE`、
`YTDLP_CONCURRENT_FRAGMENTS`、`ytdlp_prefer_hls`、`hls_alt_format` 全部相同。

## 二、环境变化（真正的差异）

| # | 变化 | 证据 |
|---|---|---|
| 1 | **Chrome cookie 升级为 v20（App-Bound）**，yt-dlp 解不开 | Chrome `Local State` 与 `Cookies` 同刻修改于 **2026-10-11 23:32:15**（v1.18.3 发布于 10-09）；`meta.version=24`、166/166 条值前缀 `v20`；`WindowsChromeCookieDecryptor.decrypt` 只认 v10，其它一律当 DPAPI 解 → `Failed to decrypt with DPAPI`（#10927） |
| 2 | Edge 运行中 → cookie 库独占锁 | `Could not copy Chrome cookie database`（#7271）；实测 `shutil.copy` 与 `CreateFileW(FILE_SHARE_READ\|WRITE\|DELETE)` 均失败（ERROR_SHARING_VIOLATION=32） |
| 3 | 游客 cookie 已被 YouTube 拒绝 | 当前解析结果 `--cookies data/guest_cookies.txt`，`cookies_file_status → (True, False, "只有游客 cookie（多半仍会被风控拦）")` |
| 4 | `data/config.json` 的 `proxy_yaml` 指向已不存在的 `I:\...\sub24_17slsr.yaml` | 项目已迁至 D:；I: 上该项目目录仍在但无该文件。**不是**当前失败主因：`_build_runtime_config()` 会退到内置 `tools/mihomo/config.yaml` 的 27 个节点；且 mihomo 为 10-09 启动、仍在运行 |

## 三、恢复下载的路径

1. **设置页 →「下载 Cookie」→「导入浏览器登录态」**：用独立配置 + 调试端口起浏览器，
   借浏览器自己解密，经 CDP 取明文写 `data/user_cookies.txt`，自动切到 file 模式。
   绕开 v20 与锁库两个限制。
2. 或浏览器扩展（Get cookies.txt LOCALLY）导出 cookies.txt，选「使用我导出的 cookies.txt」。

## 四、建议的收尾

- 将 `proxy_yaml` 清空（改用内置节点快照），消除指向失效路径的悬空配置。
- 不要尝试自行解密 v20 或拷贝被锁的 cookie 库——两者均不可行（见上表证据）。
