## 三、阶段 2：逐行校准（1×P0 + 25×P1/P2）

### P0（数据丢失级）

`build_online_release.fetch_remote_index`：远端索引拉取失败时被按「首次发版」处理，
会**用空索引覆盖远端全版本目录**。现仅 HTTP 404 算首发；网络错 / 5xx / 坏 JSON
指数退避重试，仍失败即拒绝发布。

### 代表性 P1

| 模块 | 缺陷 | 后果 |
|---|---|---|
| `vt_version_index` | `vkey` 排序键写反（正式=0/预发布=1 又配 `reverse=True`） | 2.0.0-beta.1 排到 2.0.0 **之前**，污染 stable 通道 |
| `vt_version_index` | 版本段数按十进制计数，被 `v` 前缀污染 | `v1.20` 被误判 1 段，命中 `1.99.0` |
| `vt_version_index` | `^`/`~` 语义未对齐 npm | `^0.x` 不递进次版本 |
| `vt_update_core` | 回滚时未先删当前目标 | 跨卷拷一半时**旧版永久丢失** |
| `vt_update_core` | `apply_removals` 未校验相对路径 | `os.path.join(install_dir, "")` = **可删整个安装目录** |
| `vt_update_core` | `ver_tuple` 自实现比较 | `"1.20"` 判成更旧、预发布恒 `(0,0,0)` |
| `vt_dl` | 续传进度从 0 重算、末轮失败留 `.dlpart` | 进度条假摔；留下 `done=全部` 的假续传态 |
| `vt_online_setup` | `--silent` 下 `askokcancel` | 无人值守**永久挂起** |
